# TD-001：E0 规范 JSON

状态：已采用；macOS／Windows 原生复现通过。

## 决定

E0 元数据采用 `E0-CANONICAL-JSON-v1`：

- UTF-8 编码；
- 对象键在所有嵌套层按 UTF-8 字节词典序排列；
- 数组保持语义规定的源顺序；
- 字符串使用 JSON 标准转义；
- 负浮点零规范为 `0`，其余有限数字使用 `serde_json` 的最短往返十进制形式；
- 不输出无意义空白；
- `NaN` 和正负无穷被拒绝；
- 字符串保留输入的 Unicode 标量序列，不在容器层静默规范化；要求 NFC 等规范化的字段由对应领域契约在进入容器层前处理；
- 未知、无定义和失败必须使用显式状态字段。

该编码是本项目的版本化子集，不宣称等同 RFC 8785。未来若改用其他标准规范化格式，必须提升规范版本并保留旧资产验证能力。

## 理由

- 递归排序消除普通映射插入与遍历顺序对摘要的影响；
- 人工可读，便于 T0/E0 诊断；
- 与权威 binary64 字段块分离，不用十进制 JSON 保存大规模连续场；
- 规则足够小，可以通过独立实现复核。

## 已有证据

- 不同插入顺序的普通映射生成相同字节；
- 嵌套数组顺序保持；
- 非有限浮点被拒绝；
- 负零与正零生成相同规范字节；
- Unicode 组合形式保留原始标量序列，极大／极小指数具有固定输出；
- 元数据与 binary64 内容共同形成语义摘要；
- 无损压缩往返不改变解码后的语义摘要。

## 验证结论

- macOS 与 Windows 生成相同规范字节及 SHA-256；
- 模式迁移夹具证明新版本读取器能验证旧资产，并明确拒绝未知未来版本；
- 机器比较结果见 [双平台比较报告](platform-comparison-macos-windows.json)。
