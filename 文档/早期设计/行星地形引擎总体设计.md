## 1. 已确认的产品方向

- 独立引擎核心，配套 Windows、macOS 桌面应用。
- 默认只输入种子；高级选项允许调整生成偏好。
- 先生成构造板块与地壳，再推导地势和海陆分布。
- 生成阶段包含简化地质历史，最终输出固定、可探索的世界。
- 支持连续缩放，并为局部三维结构预留空间。
- 支持高程、构造、气候、水系等图层、地点属性及成因查询。
- 保存生成配置与世界数据；地下结构首版采用入口和连接示意。

## 2. 首版目标与边界

首版目标是生成空间连续、具有自然成因、可以检查和复现的地理世界。

模型采用分辨率有限的近似过程，不承诺科研级地球系统模拟。自然合理性通过明确约束、过程记录和跨模块检查来评估。

首版实现全球骨架与区域细化；景点级别先使用位置、属性、标签和示意几何。完整洞穴三维漫游、逐株植被、实时地质演化和动态天气不属于首版交付范围。

原始景观词汇全部进入分类字典，但不同类别可以具有不同实现状态：已模拟、近似识别、仅预留。不得将仅预留类别展示为已具备可靠生成能力，也不要求每个世界出现全部类别。

## 3. 系统边界

### 引擎核心

负责生成、区域细化、空间查询、分类和验证。不得依赖窗口、地图控件或用户界面状态。

### 工作进程

运行引擎任务，负责调度、取消、进度、检查点和失败恢复。初期限制同时运行的重型任务数量，避免全球生成与局部细化争夺内存。

### 世界数据层

管理权威数据、分块索引、对象索引、生成状态及版本。世界事实与可重建的显示缓存分开存储。

### 桌面应用

负责创建世界、地图导航、图层切换、地点查询和存档管理。界面不自行推导一套与引擎不同的地理事实。

### 命令行入口

提供无界面的生成、验证和配置导出能力，供批量试验与跨平台比较使用。

## 4. 核心数据模型

| 数据实体 | 主要内容 |
| --- | --- |
| WorldManifest | 世界 ID、种子、生效参数、引擎版本、数据格式版本、阶段状态 |
| PlanetParameters | 半径、重力及气候模型所需的行星参数；首版默认固定为类地预设 |
| SpatialCell | 稳定空间 ID、层级、父子关系、邻居、球面范围 |
| CrustField | 地壳类型、厚度、年龄、岩性及来源记录 |
| PlateModel | 板块归属、运动描述、边界区段及简化构造历史 |
| TerrainField | 基底高程、沉积层、地表高程、局部细化约束 |
| ClimateField | 温度、降水、蒸发需求及必要的季节统计 |
| HydroGraph | 河段、汇流点、湖泊、出口、内流终点和水量属性 |
| GeoFeature | 山系、山峰、瀑布、湿地等对象及其几何、归属和标签 |
| UndergroundGraph | 入口、泉口、地下通道、连接和三维范围预留 |
| ProvenanceRecord | 成因类型、输入对象、模型阶段、近似等级及证据属性 |
| ChunkRecord | 分块版本、依赖、校验信息和生成状态 |

板块归属与地壳属性分开保存；海陆属性由地势和水体分布派生。一个位置允许有多个地形、生态与景观标签。

河流等长距离对象具有全局身份，分块仅保存其局部几何或引用，不能把同一条河拆成互不相关的对象。

## 5. 空间与精度策略

全球采用球面分层空间索引。具体网格方案需通过邻接、极区表现、跨面接缝、面积计算及渲染原型比较后选择。

连续缩放是显示体验，内部使用离散细节层级。地图投影不作为权威地理坐标，避免投影变形进入物理计算。

粗尺度约束细尺度：局部细化需要保持海岸锚点、河流连接、分水岭归属和分块边界条件。细节生成不能任意改变主要水系。

局部生成需要读取邻域缓冲区，并使用确定性的边界约束；仅给各分块分配随机种子不足以保证无缝衔接。

重要地下排水连接在区域水文确定时生成。洞穴内部几何可以延迟生成，影响流域收支的连接不能等到用户进入洞穴后才决定。

## 6. 生成流水线

1. 参数解析：展开默认值，验证组合，保存完整生效参数。
2. 构造初始化：生成球面板块、连续地壳属性和运动描述。
3. 简化地质历史：通过有限阶段的构造事件积累抬升、沉降与变形记录。
4. 基础地势：结合地壳与构造影响形成山系、盆地和海盆。
5. 海水分布：根据地势、连通性及水量假设确定海洋和初始海岸。
6. 基础气候：使用纬度、海拔、海陆和简化大气输送等输入计算气候场。
7. 水文组织：识别流域、河网、湖泊与内流盆地，建立近似水量收支。
8. 地貌调整：计算有限阶段的侵蚀、搬运和沉积，按变化更新地势与水系。
9. 生态分类：根据气候、水分、基质等属性生成地表覆盖。
10. 地貌识别：识别地理对象和中文标签，关联成因记录。
11. 验证与保存：输出检查结果、全球显示数据及区域细化依赖。

第 6 至 8 阶段允许有限迭代。通过迭代上限和变化阈值控制成本；达到上限仍不满足约束时记录问题，不能把它宣称为已收敛。

首版构造历史采用规则化事件近似，暂不承诺完整板块拓扑演化。真实的裂解、合并及俯冲重建是后续独立扩展方向。

## 7. 随机性与复现

- 世界定义由种子、生效参数及引擎版本共同确定。
- 固定随机数算法与种子派生规则；不同模块和区域使用独立随机流。
- 随机流依据稳定 ID 派生，不能依赖任务完成顺序或容器遍历顺序。
- 明确排序、并行归约和数值舍入策略；不可仅依赖相同种子宣称跨平台确定性。
- 权威生成优先使用 CPU 路径，GPU 首版主要用于显示。CPU 路径仍需验证跨平台数值行为。
- 跨平台验收比较标准化权威数据，而非截图或带时间戳的存档文件整体字节。
- 原有世界打开时读取已保存事实；对旧存档生成缺失细节需要兼容的生成器版本，否则应限制细化或显式迁移，不能静默混用版本。

## 8. 配置入口

基础入口仅显示种子。高级入口建议提供海陆倾向、大陆集中程度、地形起伏、气候冷暖及季节差异。

景观偏好是软目标，不承诺指定比例或保证某种景观存在。偏好到物理参数或初始条件的映射应有记录，不能通过最终贴图掩盖模型矛盾。

生成完成后报告实际指标，区分用户偏好与生成结果。自动候选筛选如被采用，必须具有固定次数上限和可复现的选择规则。

## 9. 引擎接口草案

| 接口 | 作用 |
| --- | --- |
| validate_config | 校验配置并返回完整生效参数 |
| start_generation | 创建世界生成任务 |
| get_job_status | 查询阶段、工作量和状态 |
| cancel_job | 在安全边界取消任务 |
| resume_job | 从有效检查点恢复 |
| request_region | 请求指定范围与细节层级的数据 |
| query_location | 查询位置属性、对象、标签及成因 |
| validate_world | 输出约束检查及近似误差报告 |
| open_world / save_world | 打开和保存版本化世界数据 |

长任务返回任务 ID；进度以已完成阶段和工作单元表达，初期不承诺准确剩余时间。进程通信协议与引擎内部函数接口分别版本化。

## 10. 地形词汇覆盖

- 干旱与开阔景观：大漠、戈壁、荒丘、原野。
- 山地及相对位置：雪山、山崖、山岭、山壁、山峰、山巅、山腰、岱崮。
- 水流及河流地貌：大河、瀑布、河曲、河谷、峡谷、溪流、山涧、大江、江岸、江峡、江洲。
- 地下与出露：暗河、溶洞、天坑、石林、涌泉、山泉、山洞。
- 植被：草原、山林、树林、竹林、草丛、灌丛。
- 冰雪、湖泊和湿地：雪原、湖泊、沼泽、大泽。
- 岸线与海洋：滩涂、石滩、河滩、海滩、大海、岛屿、暗礁。
- 动态景观：烟岚、云岫。

每类另行定义必要条件、可选条件、识别尺度和实现状态。山洞不能全部归因为岩溶；暗礁等类别需要更细的海底或材质模型。烟岚、云岫首版只保留表现层扩展位。

## 11. 验收标准

- 同一配置跨平台生成的标准化权威数据一致。
- 探索顺序、任务调度顺序不影响已定义的世界结果。
- 分块边界的高程约束、河流连接和对象身份一致。
- 地表河道不存在无法解释的逆坡；水体出口与水位约束一致。
- 海洋、湖泊、内流盆地分别表达，不把所有洼地强制接入海洋。
- 水量与沉积物收支具有记录；允许误差范围在模型原型后量化。
- 地貌标签满足已定义的必要条件，成因说明可追溯到模型数据。
- 取消或异常退出后，已提交检查点可读取；未完成数据不能伪装为完成。
- 存档可在 Windows 与 macOS 间迁移；缓存缺失可重建。

验证使用有明确预期的小型地形样例、固定种子回归集及约束检查。视觉检查用于发现形态问题，不能替代数值和连通性验证。

## 12. 实施里程碑

### M0：基础可行性

实现球面分层索引、种子派生、世界清单和最小桌面地图。验证跨平台启动、缩放接缝及基础确定性；确定技术栈。

### M1：全球构造与海陆

实现地壳、简化构造历史、地势与海洋，提供构造和高程图层。退出条件是世界可保存、恢复，海陆与地质数据可查询。

### M2：气候与水文

实现基础气候、流域、河网、湖泊和内流盆地。退出条件是水系连通与水量检查达到明确阈值。

### M3：区域细化与地貌

实现受约束细化、基础侵蚀沉积、植被与首批景观分类。验证跨块连续与探索顺序无关。

### M4：产品整合

实现地点成因、图层体验、存档迁移、地下关系示意及双平台打包。公开词汇覆盖表和剩余近似限制。

## 13. 待验证的技术决策

- 核心语言、桌面框架与渲染后端。
- 球面网格方案及其与显示网格的转换方式。
- 最细分辨率、典型内存预算、生成耗时和存档体积。
- Windows 与 macOS 首版支持的系统版本和 CPU 架构。
- 地质历史模型的复杂度及气候近似范围。
- 跨平台数值确定性方案和旧版生成器兼容策略。

以上需要基于原型和实测决定，不在设计阶段虚构性能指标。
