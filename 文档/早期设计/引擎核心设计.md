# 类地行星地形引擎：核心设计

> **文档状态**
>
> - 文档类型：历史设计
> - 决策状态：已归档
> - 实现状态：不作为当前实现依据
> - 版本：0.1
> - 说明：已由重设计蓝图和当前子引擎设计取代。

关联文档：[首版设计草案](行星地形引擎总体设计.md)。

配套规范：[科学模型与验证规范](../总体架构/科学模型与验证规范.md)。其中细化了本设计的科学来源、过程假设、耦合等级、场景测试与判定规则；本设计中的简化描述不能替代该规范的适用性限制。

## 1. 职责与边界

引擎核心是把“种子与行星参数”转换成“具有自然成因的世界数据”的独立计算系统。它决定山在哪里、河流如何连接、哪里适合形成森林，以及这些结果为什么出现。

核心能力包括：生成世界、细化区域、查询解释、验证一致性。

引擎不负责窗口、按钮、地图配色和安装流程。桌面应用通过后台工作进程调用核心；同一核心也可由命令行调用。核心不依赖界面状态或用户探索顺序。

产品背景：支持 Windows 与 macOS；默认输入种子；高级选项调整偏好；先生成构造板块与地壳，再推导地势和海陆；最终生成固定世界；连续缩放并预留局部三维空间。

## 2. 输入与输出

### 输入

| 输入 | 内容 |
| --- | --- |
| 世界种子 | 各个随机过程的共同来源 |
| 行星参数 | 半径、重力、自转、轴倾角等，默认采用固定类地预设 |
| 环境参数 | 水量、气候模型所需的边界条件 |
| 高级偏好 | 海陆倾向、大陆集中程度、地形起伏等 |
| 计算配置 | 全球分辨率、区域细化上限、迭代次数与资源预算 |
| 版本信息 | 引擎版本、模型版本与数据格式版本 |

保存时必须记录展开后的完整生效配置，而非仅记录用户改动的字段。影响生成结果的计算配置也属于世界定义的一部分。

### 输出

- 球面上的连续地理属性场。
- 山系、河流、湖泊、洞穴等地理对象。
- 对象之间的连接与归属关系。
- 地形类别及其识别依据。
- 生成过程、成因和验证记录。

地图图片是世界数据的一种展示结果，不是世界的权威表示。

## 3. 空间基础模块

### 职责

为所有模块提供统一的球面位置、距离、面积、邻接关系及跨尺度对应关系。

建议采用分层球面网格，全球由粗单元组成，每个单元可以继续细分。具体网格方案尚未选择。

### 单元数据

```text
稳定标识
所属层级
父单元与子单元
相邻单元
球面范围与面积
已生成的数据及版本
```

### 跨尺度转换

地质、气候、水文不必使用相同分辨率。空间模块负责不同网格之间的数据采样与传递，但不能对所有数据统一使用普通插值：

- 高程等连续量需要保持形态和边界约束。
- 岩性等类别不能简单取平均。
- 水量等数量跨尺度传递时需要保持收支。
- 河流连接关系必须按对象关系传递。

地图投影用于展示，不作为权威地理坐标。跨尺度转换属于核心算法，需要单独验证。

## 4. 随机与确定性模块

### 职责

管理世界差异的来源，并保证生成过程可复现。

各模块不共用一个不断推进的随机序列，避免局部计算变化影响无关区域。按用途派生独立随机流：

```text
世界种子
  ├─ 构造初始化
  ├─ 地壳属性
  ├─ 地质事件
  └─ 区域细节
       ├─ 区域 A
       └─ 区域 B
```

派生依据包括模块标识、稳定区域标识、生成阶段和模型版本。

### 约束

- 探索顺序不影响区域结果。
- 多线程任务完成顺序不影响结果。
- 中断后继续生成不改变世界。
- 同一版本与配置在 Windows、macOS 上产生一致的权威数据。

除固定随机算法外，还需控制对象排序、并行归约和浮点处理。不能仅凭相同种子宣称跨平台确定性，必须比较标准化权威数据。

## 5. 地质模块

### 职责与数据

维护地壳与构造状态，生成世界的大尺度骨架。

| 数据 | 用途 |
| --- | --- |
| 板块归属与运动 | 判断边界之间的相互作用 |
| 大陆／海洋地壳属性 | 为地势和构造响应提供基础 |
| 地壳厚度与年龄 | 描述区域差异 |
| 岩性、岩层与断裂 | 影响侵蚀、渗透和地下结构 |
| 抬升与沉降记录 | 累积形成地势 |
| 地质事件历史 | 保留古老构造的影响 |

板块、地壳类型和海陆属性分别表达，板块边界不能直接当作海岸线。

### 首版模型

采用有限阶段的构造事件模型，在若干阶段中施加具有空间范围的变形、抬升和沉降，不完整求解地幔运动。

事件记录包括：

```text
事件类型
影响范围
相对发生阶段
作用强度
影响的地壳与岩层
产生的高程或结构变化
```

大陆内部的古老山系可由历史事件解释，不必全部依附于当前板块边界。

该模型生成具有构造依据的近似历史，首版不宣称具备完整板块演化能力。

## 6. 地势与海洋模块

### 地势职责

把构造影响转换为地表形状，分开维护：

- 基底地形。
- 沉积覆盖厚度。
- 最终地表高程。
- 已识别的山系、盆地和坡面结构。

分层保存用于区分侵蚀沉积物与侵蚀基岩，并支持后续地貌更新。

### 海洋职责

根据地势、水量和连通性确定海洋水位及海陆边界。封闭洼地由湖泊与内流水文处理，不能将所有低于某高程的位置直接视为海洋。

向区域细化提供稳定约束，包括主要海岸位置、岛屿身份和海盆连接关系。

## 7. 气候模块

### 职责与输出

提供水文和生态所需的长期环境统计，不要求首版模拟每日天气。

- 平均温度及季节差异。
- 降水及季节分配。
- 蒸发需求。
- 积雪形成与融化所需的统计条件。

输入包括纬度、海拔、海陆分布，以及简化大气输送模型等。

山地和海陆差异应参与计算，避免只按纬度划分气候色带。对大气与海洋输送的近似范围需要明确记录。

烟岚、云岫等具体天气景象属于未来的动态表现层，可使用本模块提供的背景条件。

## 8. 水文模块

### 职责

解释水从哪里来、经过哪里、暂存在哪里、最终去哪里，并组织地表与地下水的关系。

| 子系统 | 主要职责 |
| --- | --- |
| 水量计算 | 降水、融雪、蒸发、入渗与径流 |
| 地形排水 | 流向、汇流、分水岭与流域划分 |
| 水体网络 | 河段、湖泊、出口与内流终点的连接 |
| 地下交换 | 地表渗漏、地下通道与泉口出露 |

### 对象结构

河流采用网络表示。河段保存上游连接、下游连接、河床高程、流量估计和所属流域。

湖泊单独表达水位、容量、汇入和出口。无出口湖泊同样必须具有可解释的水量收支。

### 首版近似

采用长期或分季节的近似平衡，不要求求解完整洪水过程。必须区分未模拟的短期变化与缺乏收支依据的水量丢失。

## 9. 侵蚀与沉积模块

### 职责

将地表过程反馈到地势，处理：

- 坡面与河道侵蚀。
- 被搬运物质的去向。
- 沉积物堆积。
- 地形改变后的排水更新。

读取坡度、岩性、水量、植被覆盖等输入，输出地表高程变化和沉积物变化。

更新后重新检查受影响区域的河道和湖泊，避免河床已改变而水流仍沿旧路径运动。

首版采用有限轮次迭代并记录物质收支。迭代次数和误差阈值由实验确定；达到迭代上限不等于已经收敛。首轮缺少植被结果时使用明确记录的初始覆盖假设，后续按模型需要更新。

## 10. 地下结构模块

### 关系层

提前确定洞口、通道、泉口及其连接。影响地表排水的地下连接参与区域水文计算。

### 几何层

描述通道截面、洞室、垂直落差及内部表面，可在查看局部时按需生成。

```text
地下系统
  ├─ 节点：入口、交汇、洞室、泉口
  ├─ 通道：连接关系、高程范围、通水属性
  └─ 局部几何：按需生成的三维形状
```

地下系统受岩性、岩层及结构约束。首版先提供入口与连接示意，可实现有限岩溶场景；完整三维内部不属于首版必要交付。保留其他成因山洞的分类接口，不能将所有山洞归为岩溶。

## 11. 生态与地貌识别模块

### 生态模块

根据温度、水分、土壤、坡度等条件推导草地、树林、灌丛等覆盖。竹林等具体类型需要额外适生规则，不能只凭有水生成。

### 地貌识别模块

读取既有地理事实，识别中文地形类别。每条规则至少包括：

```text
必要条件
辅助条件
适用尺度
空间范围识别方法
置信或近似等级
与其他标签的关系
```

山巅、山腰属于相对位置，需要比较周边地形；河谷结合地形与水系识别；大泽可以覆盖多个水体和湿地区域。

同一地点可具有多个标签。分类结果不能反过来强迫物理数据凑出某种景观。完整词汇及首版覆盖原则见首版设计草案第 10 节。

## 12. 区域细化模块

### 输入

- 上一级地形。
- 邻域数据。
- 必须保留的河流、海岸与分水岭约束。
- 岩性与气候条件。
- 区域专属随机流。

### 输出与边界

输出更精细的坡面、河道、岸线及景观对象，不只是提高图像分辨率。

生成时读取范围外的邻域缓冲区，并对重要对象采用统一边界条件，避免各分块独立计算造成接缝。

细化必须明确不变量：主要河流连接和流域归属保持稳定；局部形状与位置仅在允许范围内变化。不能通过模糊显示掩盖数据断裂。

## 13. 调度与依赖

核心维护生成依赖，工作进程负责将这些阶段作为任务执行、取消与恢复。

```text
地质 → 地势 → 海陆 → 气候 → 水文
         ↑                  ↓
         └──── 侵蚀沉积 ────┘
                            ↓
                       生态与分类
```

以上为主流程示意，具体实现还需声明地下交换、植被反馈等依赖。

调度需要确定：阶段运行条件、输入数据版本、哪些结果失效、可以复用哪些结果，以及从哪个检查点恢复。

修改地图配色不触发世界重新生成；改变水量可能使海陆、气候及水系等下游数据失效。

## 14. 成因解释

记录实际使用的模型和数据。例如：

> 该区域在构造阶段获得较强抬升；随后河道侵蚀形成明显切割，因此被识别为峡谷。

每一项说明都应关联对应的事件、属性或识别记录。没有模拟的过程不能编造成已发生的事实。解释中应区分直接计算、规则推断和简化假设。

## 15. 验证模块

检查内容包括：

- 河网意外断连。
- 分块边界不一致。
- 水位与出口冲突。
- 水量与物质收支超出误差范围。
- 地形标签违反必要条件。
- 不同探索顺序、任务顺序和平台产生不同结果。

问题分级：

| 等级 | 处理原则 |
| --- | --- |
| 结构性错误 | 阻止将世界标记为有效完成，定位并修复 |
| 近似误差 | 量化、对照阈值并记录，超阈值时判定失败 |
| 视觉问题 | 保留诊断信息，独立评估显示或形态改进 |

使用有明确预期的小型样例、固定种子回归集、跨平台对比和约束检查。视觉检查不能替代数值与连通性验证。

## 16. 数据持久化与接口衔接

权威地理数据与可重建的显示缓存分开保存。每个阶段产物和分块记录生成版本、依赖版本及完成状态。

旧世界读取已保存事实；对尚未生成的区域进行细化时，需要兼容的生成器版本或显式迁移，不能静默混用规则。

对外能力沿用首版草案中的接口：配置校验、开始生成、查询任务、取消与恢复、区域请求、地点查询、世界验证，以及存档打开和保存。具体函数签名与进程通信协议待技术选型后确定。

## 17. 首版实现优先级

优先完成空间基础、确定性、地势与水文之间的闭环，再增加更丰富的地貌、生态和地下结构。

模块划分是逻辑边界，不要求每个模块采用独立服务或进程。实现时优先保证数据依赖清晰、可单独验证与可复用，避免过早分布式化。

未决事项包括：核心语言、球面网格、模型公式与参数、数值确定性策略、分辨率、性能预算、误差阈值及具体地形类别的首版支持程度。
