## 一、E1 的目标

E1 把 T0 中的等角立方球面实验提升为正式、可发布、可查询的 L1 空间能力。完成后，引擎能够稳定回答：

- 一个球面位置属于哪个权威单元；
- 单元的父级、四个子级、边、角点和邻居是谁；
- 单元的真实面积、边长、中心距离和局部切平面是什么；
- 跨立方体面时，邻接方向和切向量如何变换；
- L8 全球格与一个 L10 局部补丁如何共存；
- 补丁的核心、2:1 过渡、halo 和父级聚合关系如何查询；
- 同一空间发布如何在 Windows 与 macOS 上重建相同离散身份和规范摘要。

E1 只定义空间、几何、拓扑、细化覆盖和查询，不在单元上生成任何自然状态。

## 二、明确不进入 E1 的内容

- 板块种子、Voronoi 壳体域、欧拉运动和构造边界；
- 大陆、海洋、材料、岩性、高程和多尺度起伏；
- 气候、水文、河流、湖泊、海岸和地貌分类；
- 自然模块提出的完整细化裁决与资源竞争；
- 三维地表高程网格、纹理、相机和桌面交互；
- 全球 L10 或更高等级的自然状态计算；
- 任意数据库、网络服务或桌面框架。

显示细分和计算细化继续分离。E1 的补丁只证明空间覆盖、层级和聚合关系，不宣称补丁内已有更可信的地形。

## 三、现有实验实现的差距

当前 `sphere-core` 已验证等角映射、单位向量、父级、同层邻接、面积、大圆距离和 24 个旋转，但仍属于 TS01 实验。正式 E1 需要解决：

1. 当前 `morton_key()` 把面、层级和最长 60 位 Morton 路径塞入 `u64`，高层路径与层级位会重叠，不能成为正式身份。
2. `CellId` 直接公开 `face/level/i/j` 字段，缺少版本化文本身份和解析校验。
3. 邻接只返回对面单元，没有返回双方边编号、跨面翻转和方向变换。
4. 缺少稳定的共享边与共享顶点身份。
5. 缺少边长、边中点、局部切平面、外法向切向量和带半径的完整度量。
6. 缺少 L8/L10 补丁、2:1 平衡、核心／过渡／halo 和父级覆盖关系。
7. 缺少点、区域、补丁、尺度和固定发布查询。
8. 缺少正式空间资产、能力清单、验证报告和原子发布。

E1 会重用已经验证的数学路径，但不会直接把实验 API 原样宣布为正式契约。

## 四、E1-D01：空间规范与稳定身份

建议冻结 `cubed-sphere-equiangular-v1`，简称 `cs1`：

```text
SpatialReference
├─ frameId = cubed-sphere-equiangular-v1
├─ mapping = EQUIANGULAR
├─ radiusMetres = 6_371_000
├─ maximumIdentityLevel = 30
├─ globalPrototypeLevel = 8
└─ localPrototypeLevel = 10
```

参考半径属于空间发布规格，不写死在纯单位球数学函数中。单位球向量仍是权威方向几何，米制距离和面积由查询时绑定的半径派生。

### 4.1 面编号与边界归属

面编号保持现有实验顺序：

| 编号 | 面 |
| --- | --- |
| F0 | +X |
| F1 | −X |
| F2 | +Y |
| F3 | −Y |
| F4 | +Z |
| F5 | −Z |

向量恰好位于面缝或立方体角时，按绝对分量优先级 `X > Y > Z`，再按分量符号选择正负面。该规则只决定规范索引所有者，不产生物理接缝。

### 4.2 四叉子编号

子编号固定为：

```text
2 3    t 增大
0 1    s 增大 →
```

即 `child = di + 2*dj`。路径从根到叶记录，L0 路径为空。

### 4.3 正式 CellId

公开身份采用版本化文本：

```text
cs1/F2/L5/03122
```

规则：

- 路径长度必须等于层级；
- 路径字符只能是 `0..3`；
- 层级范围为 L0—L30；
- 文本格式负责持久化、规范 JSON 和跨语言交换；
- `i/j` 与 Morton 路径是内部可逆索引，不进入公开语义；
- 不再使用当前存在位段重叠风险的 `u64 morton_key()` 作为正式身份；
- 内部索引可使用结构化元组或 `u128`，但其位布局不属于 v1 公共契约。

共享边 `EdgeId` 由同层相邻单元的规范有序对和双方边关系派生；共享顶点 `VertexId` 由该层所有入射单元的规范有序集合派生。面缝和立方体角只能产生一个拓扑实体。

## 五、E1-D02：权威几何与度量

正式 `sphere-core` 至少提供：

```text
UnitVec3
FaceCoord
CellId / EdgeId / VertexId
CellGeometry
EdgeGeometry
TangentFrame
NeighbourRelation
```

### 5.1 数值约束

- `UnitVec3` 只能由有限、非零向量规范化构造；字段私有，禁止构造非法单位向量。
- 球面距离使用 `atan2(|a×b|, a·b)`，避免接近零和 π 时直接 `acos` 的病态。
- 角点按面内固定次序生成，再验证相对球面外法向的有向次序。
- 单元面积由有向球面多边形计算；负面积、非有限面积或超过整球面积立即失败。
- 边长、中心距离和面积分别乘半径、半径和半径平方得到量纲结果。
- 经纬度是派生显示值，不参与身份、邻接或面积计算。

### 5.2 局部切平面

每个查询位置提供右手正交标架：

```text
normal = 球面单位向量
eastLike · normal = 0
northLike · normal = 0
eastLike × northLike 与 normal 同向
```

跨面方向转换先恢复三维切向量，再投影到目标位置标架，不直接复用面的上下左右分量。

### 5.3 单元几何输出

`CellGeometry` 至少包含：

- 中心单位向量；
- 四个规范角点；
- 单位球面积与米制面积；
- 四条边的弧长；
- 中心到四邻居中心的距离；
- 中心切平面；
- 空间规范和半径引用。

几何对象按需计算或由可重建缓存提供，不要求把 L8 全部几何永久写入资产。

## 六、E1-D03：拓扑与跨面邻接

边顺序固定为 `West, East, South, North`。邻接查询返回：

```text
NeighbourRelation
├─ sourceCell / sourceEdge
├─ targetCell / targetEdge
├─ edgeOrientation = SAME | REVERSED
├─ tangentTransform
└─ sharedEdgeId
```

必须满足：

- 同层每个单元恰有四个边邻居；
- `A → B` 必有唯一 `B → A`；
- 双方引用同一 `EdgeId`；
- 双方边长在统一容差内相等；
- 面缝方向变换可逆；
- 立方体八个角处没有重复或缺失 `VertexId`；
- 上层模块不自行编写面缝判断表。

E1 只冻结同层拓扑和粗细边的分段对应关系，不实现水、热或物质通量。

## 七、E1-D04：层级、补丁与 2:1 平衡

原型空间由完整 L8 全球格和一个 L10 局部补丁组成。三种覆盖必须分开：

1. **核心**：L10 权威查询覆盖；只有核心可以在目标尺度替代父级采样。
2. **过渡叶网格**：核心外围的 L9 活动叶单元，使 L10、L9、L8 相邻叶单元最多相差一级。
3. **halo**：按目标层 L10 表达的计算支持区；它可以覆盖核心外区域，但不是权威叶网格，也不替代父级。

```text
L8 环境
  └─ L9 过渡叶环
       └─ L10 核心
L10 halo = 核心外的支持采样覆盖，独立于活动叶所有权
```

`PatchManifest` 至少包含：

```text
patchId
frameId / parentReleaseId
baseLevel / targetLevel
coreCoverage
transitionLeafCoverage
haloCoverage
supportWidth
parentChildLineage
aggregationWeights
capabilityState
```

补丁规划遵循稳定排序，输入集合顺序、线程数、缓存和查询顺序不能改变结果。E1 实现空间级 2:1 平衡和预算拒绝；完整 P0—P3 多模块协调器留到相关自然模块进入后实现。

## 八、E1-D05：查询契约

E1 查询会话固定一个不可变空间发布，不在会话中动态切换版本。最小查询包括：

- `locate(unitVector, level) -> CellId`；
- `geometry(cellId, spatialReference) -> CellGeometry`；
- `parent/children/ancestor`；
- `neighbour(cellId, edge) -> NeighbourRelation`；
- `edge/vertex` 规范身份与几何；
- `cover(sphericalCap, level) -> ordered CellId set`；
- `patchAt(unitVector or CellId) -> patch/coverage role`；
- `resolve(cellId, requestedLevel) -> active leaf or capability result`；
- `aggregation(parent, patch) -> child cells and true-area weights`。

区域覆盖查询首先支持球冠和单元集合。任意球面多边形、曲线缓冲和自然对象覆盖索引可以在需要它们的里程碑增加，但必须复用同一身份和拓扑。

查询结果必须稳定排序，并区分：可用、覆盖外、尺度不可用、未解析、依赖失败和损坏资产。能力不足时不静默降级。

## 九、E1-D06：资产、发布和 CLI

### 9.1 工程结构

确认后拟进行以下代码调整：

```text
engine/crates/sphere-core/
├─ identity.rs
├─ vector.rs
├─ mapping.rs
├─ geometry.rs
```

- `sphere-core` 保持纯计算，不依赖文件系统、CLI 或桌面库。

- `terrain-cli` 增加 `sphere build/inspect/validate/query`，不增加 `generate terrain`。

### 9.2 首个空间发布

发布只保存可重建空间事实和补丁谱系：

```text
SpatialReleaseManifest
├─ spatialReleaseId
├─ spatialReference
├─ identityFormatVersion
├─ faceAndTieBreakRules
├─ globalCoverage = L8
├─ patchManifests
├─ capabilityManifest
```

不需要写出 393,216 份重复几何记录；规则可确定重建的几何只保存规范、版本和验证摘要。查询索引属于可重建资产。

## 十、E1-D07：验收、误差和性能门槛

### 10.1 科学与结构硬门槛

| 编号 | 门槛 |
| --- | --- |
| E1-G01 | CellId 文本往返、父子关系和排序稳定，L0—L30 无身份碰撞 |
| E1-G02 | 面缝／角点唯一归属，所有同层邻接互反且共享边身份一致 |
| E1-G03 | 单位向量范数误差不超过 `5e-15` |
| E1-G04 | 非边界点面坐标往返绝对误差不超过 `2e-14` |
| E1-G05 | L8 全球面积相对闭合误差不超过 `1e-12` |
| E1-G06 | 四个子单元面积和与父面积相对误差不超过 `1e-12` |
| E1-G07 | 切平面正交、单位长度与右手性误差不超过 `2e-14` |
| E1-G08 | 24 个立方体旋转保持身份关系、邻接和面积 |
| E1-G09 | 球冠覆盖无假阴性，输出无重复且顺序稳定 |
| E1-G10 | L10 核心、L9 过渡、L8 环境满足 2:1；halo 不取得权威所有权 |
| E1-G11 | 输入顺序、1／2／4 线程、分块和缓存变化不改变离散摘要 |

| E1-G14 | 空间发布不可变、中断候选不可见、损坏资产不能打开 |

容差使用统一档案，不按平台分别放宽。若解析或高精度 Oracle 表明门槛不合理，必须修改方案和容差版本，不能只调整测试常量。

### 10.2 固定夹具

- PI01：删除、反转或重复一条跨面关系；
- E1F01：六面、十二条立方体边和八个角的规范归属；
- E1F02：L0—L30 CellId 编解码与碰撞集；
- E1F03：跨面共享边、顶点和方向翻转；
- E1F04：父子面积、边分段和聚合权重；
- E1F05：跨面球冠覆盖；
- E1F06：固定 L8→L10 补丁、L9 过渡和 L10 halo；
- E1F07：24 个旋转的变形关系；
- E1F08：非法向量、非法层级、预算不足和损坏清单。

Python Oracle 只实现独立解析／高精度检查，不导入 Rust 代码。

### 10.3 原型性能门槛

在登记的参考桌面 CPU 上，发布模式暂定：

- 流式枚举 L8 全部 393,216 个单元并计算基础几何：不超过 10 秒；
- 100,000 次固定点定位查询：不超过 3 秒；
- 固定 E1F06 补丁规划与验证：不超过 2 秒；
- E1 验证峰值内存：不超过 1 GiB；
- 只含空间规范、补丁和证据的发布包：不超过 100 MiB。

性能不能通过降低 binary64 精度、跳过接缝验证或删除证据达成。首轮运行先登记机器档案；若门槛受机器差异影响，应形成版本化性能档案，不改变科学门槛。

## 十一、实施顺序

确认方案后按以下顺序修改代码，每一步都保持 workspace 可测试：

1. **E1-01 身份与规范**：实现 `SpatialReference`、正式 CellId 文本、父子和内部索引；废止实验 `u64 morton_key` 的正式用途。
2. **E1-02 几何**：封装合法单位向量、等角映射、角点、面积、距离和切平面。
3. **E1-03 拓扑**：实现规范边／顶点身份、邻接关系、边对应和方向变换。
4. **E1-04 补丁**：实现 L8/L10 覆盖、L9 过渡、L10 halo、2:1 验证和聚合权重。
5. **E1-05 查询**：实现固定发布会话、点／球冠／邻接／尺度／补丁查询与能力状态。
6. **E1-06 发布**：新增 `sphere-release`，生成首个只含空间能力的不可变发布。
7. **E1-07 CLI 与证据**：增加无界面命令、固定夹具、Oracle、性能和双平台报告。
8. **E1-08 冻结门**：汇总验收，形成 E1 报告；全部硬门槛通过后才允许 E2 依赖该发布。

## 十三、停止条件

出现以下任一情况，停止代码扩展并回到方案讨论：

- 正式身份无法在 L0—L30 保持无碰撞、可解析和稳定排序；
- 面缝邻接或角点无法形成唯一拓扑实体；
- Windows/macOS 出现离散身份或规范摘要差异；
- 2:1 平衡必须依赖查询顺序或临时遍历顺序；
- 球冠覆盖只能通过漏单元换取性能；
- 需要修改 E0 冻结语义才能继续；
- 实现开始承载板块、高程、海陆或其他自然状态。

## 十四、已确认结论

E1-D01 至 E1-D07 已一次性确认：

1. `cs1`、面编号、面缝归属、子编号和文本 CellId；
2. 单位向量、真实球面度量和局部切平面；
3. 共享边／顶点身份与可逆跨面邻接；
4. L8 全球格、L10 核心、L9 过渡和独立 L10 halo；
5. 点、球冠、邻接、尺度、补丁和聚合查询；
6. `sphere-core + sphere-release + terrain-cli` 的工程边界；
7. E1-G01—G14、固定夹具、性能门槛和双平台退出条件。

确认只授权上述 E1 范围。任何构造、材料或地形生成仍需后续里程碑的单独实施方案与确认。
