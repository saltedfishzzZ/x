## 一、修正目标与范围

E2-v1 已证明现有最小构造原型能够在 macOS 与 Windows 上稳定重现既有离散结果，但阶段审计确认三项会直接污染 E3 输入语义的问题：

1. 固定测试构造与普通随机构造可能共享同一个 `GenerationIdentity`；
2. 活动偏好通过 `WorldId` 和 `PlateId` 改变欧拉轴，违反“只改变幅度”的既定规则；
3. M1 发布物的准入结论、能力和依赖闭包没有从真实输入重算，修改派生结论并重算文件摘要后仍可能通过验证。

E2.1 的目标是修正身份、随机变量隔离、输入验证、E1 空间契约、确定性证据和发布存储，不新增材料、高程、海陆、气候、水文或地貌生成能力。E3 只有在 E2.1 完成实现、双平台验收并正式冻结后才能恢复。

E2.1 不覆盖 E2-v1 的冻结字节，不把新语义静默写回旧模式，也不把旧报告解释为新规则已经通过。

## 二、总体状态模型

阶段状态统一为：

```text
E2-v1   = FROZEN_LEGACY_PROTOTYPE
E2.1-v2 = DESIGN_CONFIRMED / IMPLEMENTATION_PENDING
E3      = PAUSED_BY_E2_1
```

E2-v1 可以读取、检查和作为回归对照，但不能进入 E3 正式生成路径。E2.1-v2 完成前，任何普通世界仍不得宣称已经具备正式地形材料准入能力。

## 三、E2.1-D01：生成身份与稳定板块骨架

> **状态：已确认。** 将用户世界意图、具体生成过程、层发布、输入束和运行计划分开；固定测试覆盖进入世界与生成身份；板块的稳定自然角色不再由完整 `WorldId` 驱动。

### 3.1 身份分层

```text
SeedKey
  = normalizedSeed + seedProtocolVersion

WorldId
  = Hash(WorldIntentSpec)

GenerationIdentity
  = Hash(WorldId + GenerationSpec)

LayerReleaseId
  = Hash(GenerationIdentity
       + upstreamDependencies
       + layerSchemaVersion
       + authoritativePayloadHashes)

InputBundleId
  = Hash(exactUpstreamReleases
       + exactInputParameters
       + datum
       + requiredCapabilities)

RunPlanId
  = Hash(InputBundleId
       + executionScope
       + resolutionRange
       + budgetClass
       + outputNamespace
       + executionPolicyVersion)
```

`WorldId` 表示用户要求的世界；`GenerationIdentity` 表示这一世界由哪一组精确模型生成；`LayerReleaseId` 表示某一层的不可变发布；`InputBundleId` 表示下游实际消费的科学输入；`RunPlanId` 只表示执行范围和计划。

线程数、操作系统、临时目录、缓存位置、当前时间和显示状态不进入科学身份。

### 3.2 世界类型

`WorldIntentSpec` 必须显式包含：

```text
worldKind = NATURAL | FIXED_TEST
fixedTestFixtureId（FIXED_TEST 时必需）
fixedTestFixtureHash（FIXED_TEST 时必需）
```

固定测试世界和同种子的普通世界不能共享 `WorldId` 或 `GenerationIdentity`。

### 3.3 稳定板块角色

```text
TectonicSkeletonId
  = Hash(SeedKey
       + plateCountPreference
       + plateSiteModelVersion
       + fixedTestOverride)

PlateRoleId
  = Hash(TectonicSkeletonId
       + generationRank
       + siteCellId)

PlateId
  = Hash(GenerationIdentity + PlateRoleId)
```

板块站点、所有者平局裁决、欧拉轴和速度分位数使用 `PlateRoleId`。`PlateId` 用于当前生成发布内的实体引用，不作为稳定物理随机变量的抽样键。

### 3.4 偏好变化矩阵

仅改变活动偏好时：

| 对象或属性 | 是否变化 |
| --- | --- |
| `WorldId`、`GenerationIdentity`、`PlateId` | 变化 |
| `TectonicSkeletonId`、`PlateRoleId` | 不变 |
| 板块站点、分区、邻接和边界位置 | 不变 |
| 欧拉轴、基础速度分位数 | 不变 |
| 实际角速度、相对速度和活动强度 | 变化 |
| 基础边界运动类型 | 不变 |

改变板块数量偏好会改变板块骨架；改变活动偏好不能改变板块骨架。

## 四、E2.1-D02：版本、兼容性与迁移

> **状态：已确认。** E2-v1 保持只读历史原型；E2.1 使用 v2 身份和发布契约；语义改变不做原地迁移。

### 4.1 v2 契约

新增或升级：

```text
world-intent-spec-v2
generation-spec-v2
generation-identity-v2
tectonic-skeleton-v2
tectonics-release-v2
terrain-input-v2
m1-input-release-v2
```

底层随机帧协议若字节语义不变，可以保留原版本；所有板块自然角色相关的随机命名空间必须升级，避免新旧语义误用同一随机变量。

### 4.2 五类兼容性

每次变更分别声明：

1. 文件读取兼容；
2. 模式结构兼容；
3. 字段语义兼容；
4. 确定性结果兼容；
5. 科学证据兼容。

能够读取旧文件不代表新引擎认可其语义。E2-v1 的既有报告只能证明 v1 原型在原检查范围内的确定性和跨平台一致性。

### 4.3 重新生成与谱系

E2-v1 不能被改写为同身份的 v2。迁移采用重新生成，并记录：

```text
predecessorReleaseId
predecessorReleaseHash
migrationReason = E2_1_IDENTITY_CORRECTION
```

`PV01-v1` 保留；E2.1 建立独立的 `PV01-v2`，重新登记它的站点、板块关系、运动关系和验收断言。

### 4.4 E3 入口

E3 正式路径只接受 v2 的生成身份、构造发布和 M1 输入发布。v1 输入返回：

```text
REJECTED_LEGACY_SEMANTICS
```

## 五、E2.1-D03：M1 语义自洽与完整性验证

> **状态：已确认。** 发布物携带声明，验证器产生结论；M1 的准入、能力、依赖闭包和各类ID必须从真实上游重新计算。

### 5.1 字段权威性

- **权威输入**：精确上游发布ID和哈希、生成身份、请求模式、模型版本、基准、固定测试配置及真实依赖。
- **派生字段**：`InputBundleId`、`RunPlanId`、依赖闭包、准入结论、原因、能力、覆盖、知识状态和发布ID。
- **展示字段**：名称、说明、创建时间和工具信息，不参与科学判断。

派生字段可以保存用于检查，但验证器必须重算并逐项比较。

### 5.2 完整验证流程

```text
解析结构
  → 验证自身摘要
  → 打开真实上游发布物
  → 重建依赖闭包
  → 复算生成身份与 InputBundleId
  → 推导基准、能力和覆盖
  → 重算准入结论与原因
  → 复算 RunPlanId 与 M1 发布ID
  → 对比保存声明
```

修改 `DIAGNOSTIC_ONLY` 为 `ADMITTED` 并重算文件摘要，必须得到 `INVALID_DERIVED_CLAIM`。

### 5.3 验证等级

| 等级 | 范围 |
| --- | --- |
| `STRUCTURAL` | 解析、字段、类型、枚举和规范编码 |
| `SELF_CONSISTENCY` | 自身摘要、ID和派生字段复算 |
| `FULL_ADMISSION` | 打开全部上游，重建依赖、能力和正式准入 |

E3 只接受通过 `FULL_ADMISSION` 的 M1-v2。

### 5.4 准入状态

```text
ADMITTED
DIAGNOSTIC_ONLY
REJECTED
INVALID
```

原因使用稳定机器码，包括但不限于：

```text
LEGACY_SEMANTICS
MISSING_CAPABILITY
DEPENDENCY_HASH_MISMATCH
GENERATION_IDENTITY_MISMATCH
INVALID_DERIVED_CLAIM
UNSUPPORTED_VERSION_COMBINATION
INCOMPLETE_DEPENDENCY_CLOSURE
```

验证器输出独立 `M1ValidationReport`，不自动修复原发布物。

## 六、E2.1-D04：活动偏好与板块运动

> **状态：已确认。** 球面板块使用欧拉旋转模型；欧拉轴和基础速度分位由稳定板块角色决定；活动偏好只施加正数全局倍率。

### 6.1 欧拉运动

板块 `i` 在球面位置 `r` 的速度为：

```text
vᵢ(r) = Ωᵢ × r
```

其中 `Ωᵢ` 为欧拉角速度向量。欧拉轴和基础速度分位通过 `PlateRoleId` 与版本化命名空间抽取。

### 6.2 活动倍率

```text
ωbaseᵢ = BaseSpeedDistribution(SpeedQuantileᵢ)
Ωfinalᵢ = ActivityScale × Ωbaseᵢ
ActivityScale > 0
```

活动偏好不能进入欧拉轴、速度分位或板块所有者平局裁决。高级活动参数设置有效范围，不对单个板块静默截断。

### 6.3 参考系

先从原始板块角速度中减去面积加权平均旋转，再统一应用活动倍率：

```text
Ωmean  = Σ(PlateAreaᵢ × Ωrawᵢ) / Σ(PlateAreaᵢ)
Ωbaseᵢ = Ωrawᵢ - Ωmean
Ωfinalᵢ = ActivityScale × Ωbaseᵢ
```

这样移除无地质意义的整体刚体旋转，同时保持活动档位间的严格比例。

### 6.4 边界类型与强度

边界基础类型按相对速度的法向和切向比例判断，不使用会随活动倍率跨越的固定现实速度门槛。发布时分别保存：

- 与倍率无关的运动类型、方向比例和分类置信；
- 随倍率变化的相对速度、汇聚率、张裂率、剪切率和活动强度。

数值退化的近静止边界使用 `KINEMATICALLY_INDETERMINATE`；地质上的低活动状态单独表达，二者不能混用。

## 七、E2.1-D05：E1 空间契约补全

> **状态：已确认。** 保留等角立方球面和 `cs1` 路线，补充统一解析、规范边几何、能力查询及可重建的局部细化验证。

### 7.1 权威空间表达

- 单位球三维向量是跨模块权威物理几何；
- `(face,u,v)` 是立方球面寻址坐标；
- `(face,level,i,j)` 是规范离散 `CellId`；
- 经纬度和地图投影只用于显示与交换。

### 7.2 统一解析

```text
resolve(position, requestedLevel, spatialRelease)
  -> CellResolution
```

结果明确返回请求层级、实际叶单元、实际层级、覆盖来源以及 `EXACT`、`COARSER_AVAILABLE`、`FINER_AVAILABLE`、`OUTSIDE_PATCH`、`UNAVAILABLE` 或 `INVALID_POSITION` 状态。

### 7.3 规范边几何

`EdgeGeometry` 至少表达端点球面向量、弧长、规范方向、左右单元、切向、A指向B的球面内法向、跨面状态和粗细谱系。

同一共享边必须满足：

```text
edge(A, B).id == edge(B, A).id
edge(A → B).normal == -edge(B → A).normal
```

边ID由规范单元身份构造，不通过浮点端点近似合并。

### 7.4 局部细化

局部补丁分为核心区、过渡区和晕区。相邻活动叶单元满足：

```text
|levelA - levelB| <= 1
```

验证器必须从叶单元重建父子谱系、同面和跨面邻接、核心覆盖、过渡集合、晕区和2:1平衡。发布物保存的 `balanced=true` 或区域计数只是派生声明。

### 7.5 查询与能力

空间查询必须区分可用、发布外、未加载、不支持、非法输入和发布损坏，不能以空值混淆。空间能力由实际数据和验证结果推导，不由任意布尔字段声明。

## 八、E2.1-D06：确定性、线程与跨平台证据

> **状态：已确认。** 将确定性分级；离散拓扑完全一致，权威连续量规范化后逐字节一致，诊断量才允许预注册容差。

### 8.1 确定性等级

| 等级 | 要求 |
| --- | --- |
| D0 | 身份、拓扑、分类、状态和原因码完全一致 |
| D1 | 权威数值量化和规范编码后逐字节一致 |
| D2 | 非权威诊断量在预注册误差内一致 |

### 8.2 数值协议

权威物理量使用“整数值＋明确单位＋明确尺度”。协议明确舍入顺序、半数处理、负零、非有限数和溢出；建议使用 `round-half-to-even`，并拒绝 `NaN`、无穷和范围溢出。

所有影响身份和拓扑的连续判断先转换为规范定点整数，再与整数门槛比较。确定性路径采用固定算法、固定系数和固定求值顺序的数学内核。

### 8.3 线程确定性

随机取样按 `SeedKey + domainTag + stableEntityId + sampleIndex` 无状态寻址。并行工作按稳定分片计算，按分片ID和实体ID固定合并。

线程报告必须记录请求线程数、实际参与线程数、并行任务数和参与证据。若实现仍为串行，只能标记 `SERIAL_ONLY`；仅设置环境变量不能证明多线程确定性。

### 8.4 同源跨平台证明

每个平台报告必须绑定：

```text
sourceTreeHash
cargoLockHash
rustCompilerVersion
targetTriple
buildProfile
enabledFeatures
deterministicMathVersion
schemaManifestHash
fixtureManifestHash
validatorVersion
executedCheckSetHash
```

两个平台检查集合不同必须返回 `CHECK_SET_MISMATCH`。每个门禁独立关联执行检查、证据文件、观察值和预期关系；缺少证据时为 `NOT_EVALUATED`，不能统一填充 `PASS`。

### 8.5 校准与验证隔离

PCAL 和 PVAL 必须真实执行、样本不重叠并分别报告。固定件必须由测试直接加载；未被测试引用的固定件报告为 `UNREFERENCED_FIXTURE`。

## 九、E2.1-D07：发布存储、提交与冻结

> **状态：已确认。** 发布存储采用不可变对象、内容寻址和精确引用；原子可见性与崩溃耐久性分别证明。

### 9.1 发布身份与路径

每个发布物同时验证逻辑 `ReleaseId` 和规范字节 `ContentHash`。进入路径的标识符使用 Windows 与 macOS 的共同安全子集，禁止分隔符、绝对路径、点路径、控制字符、Unicode混淆和Windows保留设备名。内部对象目录优先使用十六进制摘要。

### 9.2 资产头

`AssetHeader` 至少包含模式版本、资产类型、资产ID、内容哈希、载荷长度、规范编码、生成身份、生产模型版本和精确依赖。验证器重算身份、摘要、长度、依赖与版本兼容性。

### 9.3 三阶段提交

```text
PREPARE
  → 在 staging 写入候选对象、清单和事务记录

VALIDATE
  → 执行结构、摘要、身份、依赖、语义和能力验证

COMMIT
  → 安装不可变对象，完成文件与目录同步，原子切换正式引用
```

`ATOMICALLY_VISIBLE` 与 `DURABLY_COMMITTED` 是不同状态。只完成重命名不能宣称已经证明断电耐久。

### 9.4 冲突、幂等与恢复

- 相同ID、相同内容：`ALREADY_COMMITTED`；
- 相同ID、不同内容：`IDENTITY_CONTENT_CONFLICT` 并隔离；
- 崩溃恢复依据事务记录和哈希，不依据修改时间猜测；
- 隔离内容不能被正式依赖解析器读取；
- 人类可读别名可以移动，正式依赖只能保存精确ID与哈希。

### 9.5 冻结

E2.1 冻结记录必须绑定源码树、锁文件、模式、固定件、两个平台报告、跨平台比较报告、正式发布物和最终证据包。冻结后不修改原记录；后续语义修复建立新冻结版本。

## 十、统一验收矩阵

### 10.1 身份与偏好隔离

1. 固定测试世界与同种子普通世界拥有不同 `WorldId` 和 `GenerationIdentity`。
2. 活动档位变化时板块站点、`PlateRoleId`、分区、欧拉轴和基础速度分位保持一致。
3. 实际角速度和边界运动分量按活动倍率缩放。
4. 板块数量偏好变化时 `TectonicSkeletonId` 发生变化。
5. v1 输入不能进入 E3 正式路径。

### 10.2 M1 与依赖验证

1. 正常 M1-v2 通过 `FULL_ADMISSION`。
2. 修改准入结论、能力、依赖闭包、`InputBundleId` 或 `RunPlanId` 并重算文件摘要后仍被拒绝。
3. 替换上游内容但保留原ID时失败。
4. 混合不同世界的E1和E2发布物时失败。
5. 诊断输入只能得到 `DIAGNOSTIC_ONLY`。

### 10.3 空间与细化

1. 面内部、面缝和立方体角点均产生唯一规范解析。
2. 跨面邻接双向一致，边ID一致且方向相反。
3. 删除过渡单元、制造叶重叠或伪造平衡声明均被拒绝。
4. 晕区不足返回明确错误。
5. 单元遍历顺序不改变空间发布ID。

### 10.4 数值、线程和平台

1. D0结果在Windows与macOS完全一致。
2. D1载荷规范化后逐字节一致。
3. 容器、任务和分片执行顺序变化不改变结果。
4. 1、2、4线程测试证明真实线程参与并产生同一权威结果；没有并行实现时诚实报告 `SERIAL_ONLY`。
5. 两个平台使用同一源码、固定件和检查集合。
6. PCAL与PVAL真实执行且样本隔离。

### 10.5 存储与冻结

1. 非法路径和Windows保留名称被拒绝。
2. 同ID同内容幂等，同ID不同内容隔离。
3. 候选发布在提交前不可见，提交后完整可见。
4. 模拟中断后能够恢复或明确隔离。
5. 缺少任一冻结证据时不能进入 `FROZEN`。

## 十一、实施阶段建议

在用户确认具体代码修改方案后，建议按以下顺序实施：

| 阶段 | 内容 | 退出条件 |
| --- | --- | --- |
| E2.1-01 | 固定 v1 基线与新增 v2 模式骨架 | v1资产不变，v2模式可独立解析 |
| E2.1-02 | 身份分层和稳定板块角色 | 身份碰撞与活动隔离测试通过 |
| E2.1-03 | 欧拉运动和边界类型／强度分离 | 活动变形关系测试通过 |
| E2.1-04 | M1完整语义重建 | 篡改重签名故障夹具全部拒绝 |
| E2.1-05 | E1查询、边几何和补丁重建 | 跨面与2:1验证通过 |
| E2.1-06 | 数值规范与真实执行器证明 | D0/D1及线程证据通过 |
| E2.1-07 | 存储提交、恢复和路径安全 | 双平台故障注入通过 |
| E2.1-08 | 固定件、门禁和PCAL/PVAL修正 | 每项门禁具有独立证据 |
| E2.1-09 | macOS与Windows原生验证 | 两端同源、同检查集合通过 |
| E2.1-10 | 审计、冻结与E3入口复核 | E2.1-v2正式冻结 |

相互依赖的修改保持顺序实施；每一阶段先形成具体代码方案和受影响文件清单，得到用户确认后再修改代码。

## 十二、仍需在实施方案中量化的事项

以下内容不阻碍本设计确认，但必须在代码实施前给出精确规格：

1. 活动档位的具体倍率和高级参数有效范围；
2. 基础板块速度分布及其现实资料来源；
3. 权威物理量的整数单位、量化尺度和溢出界限；
4. 确定性超越函数内核的具体实现与误差上界；
5. E1局部补丁的最小晕区策略；
6. macOS与Windows耐久提交所使用的具体系统语义；
7. E2.1门禁编号、固定件编号和平台报告模式；
8. 是否在E2.1即引入真实并行；若暂不引入，线程门禁必须保持 `SERIAL_ONLY`。

这些事项只能选择满足本规范的实现方式，不能重新放宽已经确认的身份、隔离、验证和证据边界。
