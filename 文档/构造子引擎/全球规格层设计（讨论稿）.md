# 全球规格层设计

> **文档状态**
>
> - 文档类型：分层设计
> - 决策状态：已确认
> - 实现状态：未实现；定量参数待校准
> - 版本：0.2
> - 说明：L2 架构决定已确认。

本文讨论整体行星引擎的 L2“全球规格层”。L2 不生成板块、地形、气候或水文；它把用户输入、固定类地背景、模型版本和生成规则固化为完整世界规格，使所有下游模块对“正在生成哪一颗世界”拥有同一答案。

关联：[球面空间底座设计](球面空间底座设计（讨论稿）.md) · [构造引擎前置条件清单](构造引擎前置条件清单（讨论稿）.md) · [引擎重设计蓝图](../总体架构/引擎重设计蓝图（讨论稿）.md)。

## 一、L2 解决什么问题

用户默认只输入种子，但引擎实际运行还需要知道：

- 使用哪个类地背景预设；
- 行星半径、重力、自转、公转、倾角和大气／海洋背景是什么；
- 允许哪些高级偏好以及偏好影响哪些概率和参数；
- 采用哪些构造、气候、水文和地貌模型版本；
- 生成哪些代表季节和空间层级；
- 是否正在运行固定测试世界；
- 哪些设置会改变世界，哪些只影响计算速度或显示方式。

L2 的输出不是一组松散设置，而是一份不可变、可序列化、可比较的 `世界规格`。

```text
用户输入
  ├─ 种子（默认唯一必填）
  └─ 高级偏好（可选）
         ↓
固定类地预设 + 模型清单 + 规格校验
         ↓
不可变世界规格
         ↓
L1 空间、L3 构造及所有后续自然模块
```

## 二、L2 的职责边界

### L2 负责

- 规范化种子并派生世界随机根。
- 选择并版本化固定类地背景预设。
- 保存会改变自然世界的高级偏好。
- 固化代表季节、启用模块和模型版本。
- 验证参数组合是否合法、是否超出模型适用范围。
- 生成世界规格摘要和世界身份。
- 为固定测试世界提供受控覆盖机制。
- 区分世界内容、计算计划和显示状态。

### L2 不负责

- 根据参数真正生成板块、高程、降水、河流或景观。
- 将用户偏好直接解释为“必须出现某个对象”。
- 保存相机、配色、标签密度和当前选中对象。
- 根据机器性能偷偷改变世界内容或科学模型。
- 将未受支持的参数组合包装成看似成功的世界。

## 三、L2 的建议分层

```text
L2.1 输入规范化
     ↓
L2.2 类地预设解析
     ↓
L2.3 高级偏好解析与约束
     ↓
L2.4 模型清单与季节集合
     ↓
L2.5 世界规格校验
     ↓
L2.6 身份、摘要与随机命名空间
     ↓
不可变 WorldSpec
```

| 子层 | 主要职责 | 输出 |
| --- | --- | --- |
| L2.1 输入规范化 | 处理种子字符串、默认值、单位和枚举 | 规范化用户输入 |
| L2.2 类地预设解析 | 将预设名称展开为完整行星背景 | 已版本化背景参数 |
| L2.3 偏好解析 | 将“海洋较多”等偏好转换为受限参数分布 | 内容偏好与影响范围 |
| L2.4 模型清单 | 固定各模块版本、代表季节和功能开关 | 模型清单与季节集 |
| L2.5 规格校验 | 检查冲突、模型适用范围和测试覆盖 | 有效规格或明确拒绝原因 |
| L2.6 身份生成 | 规范序列化、摘要、随机根和差异比较 | 世界标识与不可变规格 |

## 四、L2 的拟议决定

| 编号 | 需要确定的问题 | 当前建议 |
| --- | --- | --- |
| L2-D01 | 哪些设置构成世界身份 | 将世界规格、运行计划、显示状态严格分开；只有改变自然内容的字段进入世界身份 |
| L2-D02 | 固定类地预设包含哪些参数 | 固定首版的行星几何、重力、自转、公转、倾角、大气与海洋背景，并对预设本身版本化 |
| L2-D03 | 时间和代表季节怎样写入规格 | 固定地理骨架加同一世界的代表季节集，季节定义进入世界规格 |
| L2-D04 | 高级偏好怎样影响生成 | 偏好调整概率分布和约束范围，不直接保证景观结果，不允许突破硬约束 |
| L2-D05 | 随机流怎样从种子派生 | 使用规范化种子和命名空间派生独立随机流，模块增加或执行顺序不改变其他结果 |
| L2-D06 | 模型版本怎样管理 | 每个模块独立版本化，世界规格保存完整模型清单和兼容规则 |
| L2-D07 | 测试世界怎样覆盖默认规格 | 测试世界使用显式覆盖层，只改声明字段并保存覆盖原因 |
| L2-D08 | 生成质量和资源预算属于哪里 | 运行计划独立于世界规格；若降级改变自然结果，则产生不同计算状态或新快照并明确记录 |

## 五、L2-D01：世界规格、运行计划和显示状态

最容易造成不可重现问题的是把所有设置放进同一个配置对象。例如相机位置不应该改变大陆，而选择不同水文模型则必须改变世界身份。

因此建议分为三类。

### 5.1 世界规格 WorldSpec

世界规格回答：**这是一颗什么世界？**

建议包含：

```text
规范化种子
类地预设标识与版本
影响自然内容的高级偏好
代表季节集合与定义版本
启用的自然模块
各模块模型标识与版本
空间规范版本
测试世界覆盖（若有）
规格格式版本
```

这些字段任意一个发生有效变化，都应得到不同的世界身份或世界修订版本。

### 5.2 运行计划 GenerationPlan

运行计划回答：**这次准备怎样计算它？**

建议包含：

```text
当前目标空间层级
活动区域与细化请求
线程／任务并行度
内存与缓存预算
允许等待时间
优先运行哪些模块或测试
中间结果保存策略
```

单纯改变线程数、缓存大小或任务顺序，不应改变最终世界。如果预算不足导致某模块降级或未完成，结果必须标记为条件通过／未验证，不能假装与完整结果相同。

若所谓“质量档位”实际更换了模型、分辨率或近似公式并改变自然结果，它就不能只放在运行计划中；对应的模型版本、目标层级或近似状态必须进入世界快照及其身份记录。

### 5.3 显示状态 ViewState

显示状态回答：**用户现在怎样看它？**

建议包含：

```text
相机位置与缩放
球体／等经纬图／局部三维视图
图层开关和配色
标签密度
高程夸张倍率
当前选中对象
界面布局
```

显示状态不进入世界身份。改变颜色、高程夸张或相机位置后，世界快照摘要必须保持不变。

### 5.4 三者之间的关系

```text
WorldSpec ──生成──→ 世界快照
                       ↑
GenerationPlan ──安排计算与细化
                       ↓
ViewState ───────只读取并显示
```

运行计划不能修改 WorldSpec，显示状态不能修改世界快照。用户调整高级偏好时，不是在当前 ViewState 中改色，而是创建新的 WorldSpec，并生成可比较的新世界或世界分支。

### 5.5 世界身份

建议用世界规格的规范化序列化结果生成身份摘要：

```text
WorldId = Hash(CanonicalSerialize(WorldSpec))
```

规范化序列化至少需要保证：

- 字段顺序固定；
- 单位统一；
- 默认值显式展开；
- 浮点参数使用规定精度和表示；
- 无关空白、界面语言和对象显示顺序不影响摘要；
- 不包含相机、缓存目录、线程数等运行／显示字段。

用户可见名称可以是友好的短名称，但不能代替完整身份摘要。

### 5.6 世界修订与派生快照

同一个 WorldSpec 可以拥有多个计算阶段：

```text
WorldSpec W
├─ Snapshot S0：只有全球空间与规格
├─ Snapshot S1：构造骨架完成
├─ Snapshot S2：地形与材料完成
├─ Snapshot S3：气候和水文完成
└─ Snapshot S3 + R1：附加某区域细化补丁
```

这些快照属于同一个世界规格，但模型完成度和证据不同。若更换模型版本、类地预设或内容偏好，则产生新的 WorldSpec；若只增加已声明模型的计算完成度，则产生同一世界下的新快照。

### 5.7 D01 建议规则

```text
世界规格决定世界内容和身份
运行计划决定何时、在哪里、用多少资源计算
显示状态决定怎样观察结果
三者使用不同数据结构和保存位置
同一世界可以有多个计算完成度不同的快照
改变自然模型或内容偏好会产生新的世界规格
```

## 六、L2-D02：固定类地背景预设

首版只支持一个版本化的类地背景 `earthlike-v1`。用户默认不需要理解或输入行星物理参数；L2 将预设展开为完整字段，再交给构造、气候和水文模块。

类地预设不是“复制现实地球地图”，而是固定行星尺度和环境量级，使世界差异主要来自板块、海陆、地形、材料和自然过程的空间组合。

### 6.1 三类参数

| 类别 | 含义 | 是否进入 WorldSpec | 示例 |
| --- | --- | --- | --- |
| 世界背景参数 | 描述这颗行星本身，会改变自然结果 | 是，通过预设版本显式展开 | 半径、重力、自转、轴倾角、水量背景 |
| 模型物理常量 | 属于模型实现或单位体系，不用于区分不同世界 | 通过模型版本固定，不作为用户偏好 | 水密度、热容、潜热、数学常量 |
| 暂不模拟参数 | 现实中存在，但首版没有相应过程 | 记录为未建模，不伪造影响 | 磁场变化、真实月球潮汐、地幔化学演化 |

只有被实际模型读取的世界背景参数才应影响世界内容。预设可以保留尚未启用的字段，但必须标记“声明但未参与计算”，避免用户误以为它已经产生物理作用。

### 6.2 行星几何与重力

| 字段 | `earthlike-v1` 初始建议 | 首版用途 |
| --- | --- | --- |
| 参考形状 | 球体 | 与 L1 等角立方球面一致；首版不处理椭球扁率 |
| 平均半径 | 约 6371 km | 距离、面积、局部曲率、三维位置和尺度换算 |
| 表面重力 | 约 9.81 m/s²，首版视为全球常量 | 水位势能、简化大气和地貌尺度的背景参数 |
| 高程基准 | 独立于最终海平面的行星参考面 | 使地形高程和海平面求解可以分开版本化 |

行星半径和重力在首版冻结，不作为高级偏好。若未来开放小型类地行星或高重力世界，需要重新验证大气、侵蚀、水文与地貌模型，不能只缩放球体显示。

### 6.3 自转、轨道与恒星辐射

| 字段 | `earthlike-v1` 初始建议 | 首版用途 |
| --- | --- | --- |
| 平均太阳日 | 24 小时 | 日平均气候背景和时间单位 |
| 自转方向 | 与现实地球一致 | 全球风向和旋转效应的方向约定 |
| 轨道周期 | 约 365.24 日 | 代表季节的时间基准 |
| 轴倾角 | 约 23.44° | 纬度季节差异、日照季节变化 |
| 轨道偏心率 | 约 0.0167 | 季节辐射背景；简化模型可只使用其低阶影响 |
| 平均恒星辐照 | 约 1361 W/m² | 气候能量输入的量级 |

首版固定恒星为太阳型背景，不开放恒星类型、轨道距离、轴倾角和自转周期。气候模型若没有使用其中某个字段，必须在模型清单中标明，而不能因为规格中存在就宣称已经模拟。

### 6.4 大气背景

首版采用接近现实地球的背景大气，但不要求完整大气环流或大气化学。预设至少应声明：

| 字段组 | 建议内容 | 主要消费者 |
| --- | --- | --- |
| 表面压力背景 | 约一个标准大气压 | 温度、湿度容量、蒸发和降水近似 |
| 平均分子量／主要组成 | 氮氧型类地大气的固定背景 | 气候模型适用范围和热力参数选择 |
| 热容量背景 | 与类地大气相符的固定量级 | 季节温度响应与热量输送 |
| 温室背景 | 固定的首版基线参数化 | 全球平均温度基线；不模拟碳循环 |
| 水汽可用性 | 由温度、海洋、输送与地形共同计算 | 降水、雨影、积雪与水文输入 |

降水不属于预设参数。预设只给出大气背景；具体降水必须由水汽来源、温度、输送、地形抬升和季节共同决定。

### 6.5 水量背景与海平面

首版不把“海洋覆盖 70%”直接作为结果切割线。这样做会强迫任意地形都达到指定面积比例，也会把低于海平面的封闭盆地误判为海洋。

建议 WorldSpec 保存：

```text
全球水量背景／海洋水量目标
初始储库分配规则版本
海洋连通判定版本
海平面闭合求解版本
```

生成顺序为：

```text
构造与地形产生盆地和高程
        ↓
按照水量背景求解海洋水面
        ↓
从主要海洋种子执行连通域判定
        ↓
得到全球海洋、海岸和封闭低地
        ↓
气候与水文再决定内陆湖、积雪、土壤水和地下储量
```

因此：

- 海洋面积是地形、连通关系和水量共同产生的结果。
- 低于海平面的封闭盆地不自动获得海水。
- 内陆盆地是否积水由降水、来流、蒸发、入渗、地下交换和溢流决定。
- 高级偏好中的“海洋较多／较少”应调整水量背景和可能的地壳高程先验范围，而不是按目标百分位强制切海岸。

首版水量背景建议接近现实地球量级，可用“折算到全球面积的等效水层厚度”表达；具体数值需要结合首个地形原型校准，不在概念阶段冻结。

### 6.6 构造与内部活动背景

构造引擎还需要一个固定的类地活动背景，但它不等同于真实地幔模拟。预设可以包含：

- 板块数量的合理先验范围；
- 大陆壳、洋壳和过渡壳的背景比例范围；
- 构造活动强度的标准档；
- 汇聚、离散和走滑边界的允许集合；
- 构造影响尺度与高程响应的模型版本。

这些字段只为 L3 提供可复现的初始分布和约束范围。最终板块数量、位置和边界仍由种子决定。首版可以允许高级偏好调整“板块较少／标准／较多”或“构造较平缓／标准／活跃”，但不能直接指定“必须在某处生成山脉”。

### 6.7 首版明确后置的背景过程

以下参数或过程暂不进入首版有效计算：

- 椭球形状、纬度重力差和真实大地水准面。
- 月球轨道、精确潮汐势和潮汐长期演化。
- 磁场、太阳风和高层大气逃逸。
- 大气化学、碳循环和长期温室反馈。
- 地幔热对流、放射性热演化和真实板块速度历史。
- 长期海平面变化、冰盖等静力回弹和构造均衡完整模型。

后置不表示这些过程不存在，而表示首版不会用它们解释具体景观。若局部模型需要简化潮汐或温室背景，应使用明确的边界参数化，并标为受约束近似。

### 6.8 预设版本与显式展开

保存世界时不能只保存：

```text
preset = earthlike-v1
```

还应保存该版本实际展开的参数和用途状态：

```text
presetId: earthlike
presetVersion: 1
resolvedParameters: ...
activeParameters: ...
declaredButUnused: ...
```

这样未来发布 `earthlike-v2` 时，旧世界仍可重现，不会因为软件默认值变化而悄悄改变半径、气候或水量背景。

### 6.9 D02 建议规则

```text
首版使用单一、版本化的固定类地预设
半径、重力、自转、轨道、轴倾角和大气背景默认冻结
海洋由水量、地形和连通性共同求解，不按面积百分位强制切割
降水、湖泊和积雪不是预设结果，而由后续自然模块计算
构造预设只规定先验范围和活动背景，不指定具体山脉
预设字段标明是否真正参与计算
保存世界时显式保存已展开参数
```

## 七、L2-D03：代表季节与内部时间语义

已确认的产品方向是“固定地理骨架＋可切换的代表季节状态”。D03 需要进一步区分用户看到的季节画面和引擎内部用于维持水量连续性的时间计算。

### 7.1 为什么不能独立生成四张季节地图

如果春、夏、秋、冬各自重新随机生成，容易出现：

- 冬季积雪消失后没有进入春季融雪径流；
- 夏季湖泊水位与春季来水没有关系；
- 河流、湿地和湖盆在切换季节时改变身份；
- 一份水同时留在积雪中，又被计算进河流和湖泊；
- 南北半球使用同一个“夏季”温度与辐射状态。

因此代表季节必须来自同一条周期状态链，而不是四个独立世界。

### 7.2 两层时间表达

建议首版采用：

```text
内部：12 个气候月／轨道时间箱，循环计算全年状态
外部：4 个代表轨道相位，供用户切换观察
```

内部 12 个时间箱用于：

- 太阳辐射和温度的年内变化；
- 降水雨雪分配；
- 积雪累积、融化与再冻结的简化过程；
- 土壤水、地下储量、河流流量、湖泊水位和湿地范围的连续转移；
- 检查年末与下一年年初的水量闭合。

“气候月”是一个周期计算时间箱，不要求对应具体历史年份或现实天气。后续模型可以增加时间步，但不能改变首版代表季节的身份含义而不升级版本。

### 7.3 四个代表轨道相位

首版对外提供四个稳定状态标识：

| 状态 | 轨道含义 | 北半球解释 | 南半球解释 |
| --- | --- | --- | --- |
| Q0 | 第一分点附近 | 春季代表态 | 秋季代表态 |
| Q1 | 北向至点附近 | 夏季代表态 | 冬季代表态 |
| Q2 | 第二分点附近 | 秋季代表态 | 春季代表态 |
| Q3 | 南向至点附近 | 冬季代表态 | 夏季代表态 |

状态身份使用 Q0–Q3 或等价的轨道相位标识，不直接把整颗行星命名为“春、夏、秋、冬”。界面可以根据对象所在半球显示本地季节名称。

赤道和热带地区不应被强制解释为温带四季。它们仍使用同一轨道相位，但查询解释应根据当地降水、温度和水文状态显示“湿润期、干燥期、过渡期”或其他实际条件。

### 7.4 代表态不是极端天气

每个代表状态表达该轨道相位附近的气候学典型状态，不是某一天的天气，也不包含随机风暴、寒潮、持续干旱或异常年份。

代表态可保存：

- 典型温度和降水条件；
- 雨雪比例、积雪水当量与融雪状态；
- 土壤水、地下储量和蒸发需求；
- 河流流量等级、湖泊水位、湿地淹水范围；
- 地表覆盖和植被季节状态；
- 本相位使用的输入、时间窗口和模型状态。

极端事件、逐日天气和年际波动后置，不用代表季节伪装。

### 7.5 固定骨架与季节可变状态

| 固定或缓慢骨架 | 可随代表季节变化 |
| --- | --- |
| 板块、构造边界、基岩和主要材料区 | 温度、降水与蒸发需求 |
| 基础高程、主山脉、盆地和主海岸 | 积雪、融雪、土壤水和地下储量 |
| 主流域、湖盆、主要河网和对象标识 | 河段流量、季节断流和分流活跃度 |
| 洞穴／地下连接候选、主河谷和峡谷 | 湖面、河滩、湿地和漫流范围 |
| 全球海平面和海洋连通域（首版） | 地表覆盖和植被季节表现 |

季节状态可以让某条支流断流、湖面缩小或河滩显露，但不能重新随机生成流域、改变主河身份或移动构造山脉。

### 7.6 状态量与通量的时间语义

不同数据不能都用一个“季节值”表示：

| 数据类型 | 代表态含义 | 示例 |
| --- | --- | --- |
| 状态量 | 代表相位时的典型存量或平均状态 | 积雪水当量、湖泊储量、土壤水、地下水位 |
| 通量 | 相位窗口内的平均速率或累计量，并明确单位 | 降水、融雪、河流流量、蒸发、入渗 |
| 稳定对象 | 同一对象在该相位的活动状态 | 河流 R17 的常流／季节流状态 |
| 范围几何 | 由该相位状态派生的版本化边界 | 湖岸、湿地淹水区、雪原范围 |

每个字段必须声明自己是时点状态、时间平均还是期间累计，避免把“一个月总降水”与“平均降水速率”直接相加。

### 7.7 周期连续与收敛

内部状态按全年顺序推进：

```text
月 1 → 月 2 → … → 月 12 → 下一周期月 1
```

积雪、土壤水、地下水和湖泊储量从前一时间箱传入下一时间箱。初始状态可以来自预设，但正式代表季节应在运行若干周期后达到稳定的周期状态，或明确标记没有收敛。

建议检查：

```text
周期末储量 - 周期初储量
= 全年输入 - 全年输出 - 全年损失
```

若在规定迭代次数与容差内不能形成稳定周期，应输出“未收敛”或“条件通过”，不能任意截取一年的结果作为稳定季节。

### 7.8 季节状态与世界身份

进入 WorldSpec 的是：

- 季节集合定义版本；
- 内部时间箱方案与版本；
- 代表相位定义；
- 所用气候和水文模型版本。

用户当前选择查看 Q0、Q1、Q2 或 Q3 属于 ViewState，不改变 WorldId。若把内部 12 个时间箱改为另一种时间积分方案，或者改变代表相位定义，则会影响自然结果，必须产生新的规格或模型版本。

### 7.9 D03 建议规则

```text
同一固定地理骨架派生所有季节状态
内部使用 12 个气候时间箱维持全年连续账本
外部提供 Q0–Q3 四个代表轨道相位
南北半球使用相反的本地季节解释
热带按实际干湿和水文条件解释，不强制套用温带四季
状态量、平均通量和累计通量明确区分
积雪、湖泊和地下储量跨时间箱连续传递
代表态不模拟逐日天气、极端事件和年际变化
切换查看季节不改变世界身份
```

## 八、L2-D04：高级偏好与自然约束

默认生成仍然只要求一个种子。高级偏好用于改变世界生成的倾向，而不是绕过自然模型直接指定结果。

```text
用户偏好
   ↓ 转换为有边界的上游先验
构造、材料、水量等自然模块
   ↓
在硬约束内生成世界
   ↓
偏好满足报告
```

### 8.1 偏好、参数和结果的区别

| 类型 | 示例 | 是否允许用户直接控制 |
| --- | --- | --- |
| 固定类地参数 | 半径、重力、轴倾角、大气压力 | 首版不开放 |
| 因果偏好 | 板块较多、水量较高、材料更多样 | 允许，以受限档位调整先验 |
| 景观倾向 | 偏向群岛、内陆干旱、岩溶高地 | 可作为因果偏好组合，但不保证结果 |
| 结果配额 | 必须有 20 条大河、30% 沙漠、至少 5 个三角洲 | 不作为首版生成输入 |
| 显示偏好 | 河流颜色、标签数量、高程夸张 | 属于 ViewState，不进入世界规格 |

“更多山脉”不能直接在地图上增加山峰，而应调整构造活动、汇聚边界响应和地形起伏的允许范围；最终是否形成大型山系仍由板块布局、材料和后续地貌过程决定。

### 8.2 首版建议开放的因果偏好

首版偏好使用少量有序档位，例如“低／标准／高”或“较少／标准／较多”。界面档位由版本化规则映射到内部参数范围，用户不需要直接填写未经验证的物理数值。

| 偏好 | 主要影响的上游条件 | 不直接保证的结果 |
| --- | --- | --- |
| 板块数量 | L3 板块数量先验与典型尺度 | 不保证大陆数量或山脉数量 |
| 大陆破碎度 | 陆壳区域生长、连接与碎片化先验 | 不保证岛屿总数或固定海岸长度 |
| 构造活动度 | 边界活动强度和构造地形响应范围 | 不保证最高峰高度或到处有火山 |
| 地形起伏倾向 | 构造约束转为区域高差的允许范围 | 不保证某个位置出现峡谷或瀑布 |
| 全球水量背景 | 海洋水量、海平面闭合和后续水文可用水背景 | 不保证海洋面积百分比、河流数或湖泊数 |
| 材料多样度 | 岩性／表层材料种类与空间异质性先验 | 不保证特殊地貌一定形成 |
| 可溶岩倾向 | 可溶材料区域出现的概率和尺度先验 | 不保证溶洞、天坑或暗河成立 |

偏好之间尽量保持单一职责。例如“全球水量背景”主要改变可用水量，不同时偷偷改变板块数量和材料分布，这样结果才可解释和测试。

### 8.3 景观倾向作为因果组合

为了让不了解模型的用户表达需求，可以提供少量“世界性格”或景观倾向。它们不是新的物理参数，而是对多个因果偏好的透明组合。

| 景观倾向 | 可以提高的前置条件 | 仍然必须满足 |
| --- | --- | --- |
| 群岛世界倾向 | 较高大陆破碎度、更多海洋边缘与适当水量 | 构造布局、海洋连通和岛屿高程 |
| 高山流域倾向 | 较强构造活动和地形起伏 | 汇聚边界、材料、高程与气候水源 |
| 干旱内陆倾向 | 较大大陆内部尺度、较低水量或更强雨影机会 | 水汽路径、蒸发需求与地形屏障 |
| 岩溶高地倾向 | 提高可溶岩区域机会与裂隙背景 | 补给、入渗、地下连通和出露条件 |
| 湖沼平原倾向 | 增加低坡盆地和适合滞水材料的机会 | 实际来水、蒸发、出口和水量收支 |

界面应能展开显示这些组合实际改变了哪些因果偏好。用户关闭组合后，原有单项偏好应恢复，而不是残留隐藏参数。

### 8.4 偏好不是保证

偏好属于软约束，其优先级低于：

```text
自然硬约束
> 模型适用范围
> 世界规格合法性
> 用户因果偏好
> 视觉丰富度
```

例如用户选择“可溶岩较多”，但某个具体区域没有足够补给和地下连通条件，那么该区域仍不能正式生成暗河或天坑。偏好只能提高形成前提的机会，不能替代证据。

首版不承诺单个种子的结果随每档偏好都严格单调变化。自然系统具有空间组合和阈值效应；方向性主要通过固定种子组的统计验证，同时对能直接控制的上游参数保持单调映射。

### 8.5 冲突与不可满足偏好

偏好解析器按以下过程工作：

1. 将界面档位转换为版本化的内部参数范围。
2. 检查是否超出 `earthlike-v1` 和各模型的适用范围。
3. 检查多个偏好是否竞争同一参数或产生明显矛盾。
4. 生成解析后的 WorldSpec 和偏好影响清单。
5. 世界生成后比较实际统计与偏好方向，形成满足报告。

不能静默把冲突偏好改回默认值。系统可以：

- 接受软偏好，但说明它们互相制约，最终不保证全部明显体现；
- 将部分偏好限制在合法边界，并明确显示解析值；
- 对超出模型范围或破坏硬约束的组合拒绝生成。

测试世界的硬覆盖不属于用户偏好。T01–T06 和 K01–K04 可以为了验证过程显式固定边界条件，但输出必须标记为测试世界，不能伪装成随机世界。

### 8.6 偏好满足报告

每颗世界应保存一份偏好报告：

```text
请求偏好
解析后的因果参数范围
实际采用值／随机抽样值
受影响模块和随机流
生成后的相关统计
满足、部分满足、未明显体现或被拒绝
原因与自然约束
```

例如：

```text
请求：岩溶高地倾向 = 高
解析：可溶岩区域先验提高，裂隙背景采用高档合法范围
结果：可溶岩面积增加，但湿润补给区较少
结论：部分满足；形成岩溶候选区，正式暗河对象较少
```

报告用于解释偏好如何影响世界，不用于在生成后篡改结果使其看起来满足要求。

### 8.7 偏好与世界身份

所有影响自然内容的解析偏好进入 WorldSpec。因此：

- 同一种子、同一偏好得到同一个世界身份和结果。
- 同一种子修改偏好后产生新的世界规格或比较分支。
- 只修改偏好界面但解析值未变化，不产生新身份。
- 配色、图层开关和高程夸张不属于内容偏好，不改变 WorldId。

若生成过程使用有界重试或候选选择来满足偏好，重试次数、候选排序和选择规则必须确定性且版本化，不能在后台不断更换隐藏种子。

### 8.8 D04 建议规则

```text
默认只输入种子，高级偏好全部可选
偏好调整上游因果先验，不直接规定景观配额
首版只开放少量有边界、可解释的档位
景观倾向是透明的因果偏好组合
自然硬约束和模型适用范围高于用户偏好
世界生成后输出偏好满足报告
内容偏好进入 WorldSpec，显示偏好进入 ViewState
同一种子与偏好始终可重现，不隐藏更换种子
```

## 九、L2-D05：种子规范化与命名随机流

种子是默认唯一必填输入，但它不能直接交给语言运行时自带的随机函数。D05 将种子定义为一套跨平台、与执行顺序无关的随机协议。

```text
用户种子文本
    ↓ 规范化
规范种子字符串
    ↓ 固定哈希协议
根随机密钥
    ↓ 命名空间 + 稳定对象／单元标识
可随机访问的确定性样本
```

### 9.1 种子文本规范化

建议采用以下首版规则：

| 项目 | 规则 | 原因 |
| --- | --- | --- |
| 输入类型 | 一律作为 Unicode 文本处理，包括纯数字 | 避免数字精度、正负号和 JSON 类型差异 |
| Unicode | 转换为 NFC 规范形式 | 视觉相同的组合字符得到相同种子 |
| 首尾空白 | 删除 | 避免复制粘贴产生不可见差异 |
| 内部空白 | 连续 Unicode 空白折叠为一个普通空格 | 提高人工输入与跨平台一致性 |
| 大小写 | 区分 | 保留用户明确输入，`Aurora` 与 `aurora` 是不同种子 |
| 控制字符 | 拒绝 | 防止不可见控制符造成难以解释的差异 |
| 长度 | 建议限制为 1–128 个 Unicode 标量值 | 便于界面、保存、比较和测试 |
| 空输入 | 自动生成可见种子并写回输入框和 WorldSpec | 世界不能依赖未保存的隐藏随机值 |

WorldSpec 保存规范化字符串；界面可以另存原始显示文本，但原始文本不参与身份和随机派生。规范化规则本身属于 `seed-format-v1`，未来改变规则必须升级版本。

### 9.2 世界身份与随机根分开

世界身份仍由完整 WorldSpec 计算：

```text
WorldId = Hash(CanonicalSerialize(WorldSpec))
```

随机根则从规范种子派生：

```text
SeedKey = Hash("planet-engine/seed/v1" + normalizedSeed)
```

两者分开的好处是：同一种子调整偏好时，可以继续使用相同的底层随机分位，使两个世界便于比较；偏好、预设和模型版本仍通过 WorldId 明确区分结果和缓存。

具体哈希算法必须固定并版本化。首版建议采用跨平台实现成熟的 256 位加密哈希作为派生基础；它在这里用于稳定性和命名空间隔离，不用于安全认证。

### 9.3 不使用全局可变随机数序列

传统做法是：

```text
rng = Random(seed)
a = rng.next()
b = rng.next()
c = rng.next()
```

如果后来在 `a` 与 `b` 之间增加一次取样，后面的所有结果都会变化。并行运行、模块顺序和区域访问顺序也可能改变取样次数。

正式引擎应使用按名称和稳定标识随机访问的样本：

```text
Random(namespace, entityId, property, sampleIndex)
```

例如：

```text
Random("tectonics/plates", "planet", "plate-count", 0)
Random("tectonics/plate", plateId, "motion-direction", 0)
Random("materials/region", regionId, "lithology", 0)
Random("terrain/cell", cellId, "detail-residual", 3)
```

新增河流配色或新的材料属性不会移动板块随机序列，因为它们属于不同命名空间和属性键。

### 9.4 分层命名空间

建议命名空间与自然模块及稳定对象一致：

```text
world/tectonics/plates
world/tectonics/boundaries
world/terrain/base
world/materials/lithology
season/Q1/climate
season/Q1/hydrology
region/{cellId}/terrain-detail
object/{objectId}/geomorphology
test/{testWorldId}/{variantId}
```

每个模块只能使用自己声明的命名空间。命名空间、样本属性和索引的语义属于模型采样契约；若改变其含义或取样分布，需要升级相应模型或随机协议版本。

### 9.5 四叉细化与随机性

局部细化使用稳定单元标识派生随机值：

```text
region/{face}/{level}/{quadtreePath}/...
```

因此：

- 先细化区域 A 再细化 B，与相反顺序得到相同结果。
- 卸载后重新生成同一单元，得到相同细节。
- 相邻区域的生成不因线程调度顺序变化。
- 子级随机细节必须受父级聚合约束，不能改变父级总量或稳定骨架。

连续噪声场也不能以“访问一个单元就取一次随机数”实现。应根据稳定格点／球面基函数标识生成系数，使相邻区块在边界上采样同一底层场。

### 9.6 分布取样与跨平台一致性

哈希位串只是原始随机材料，还要转换为整数、均匀小数、方向或其他分布。转换规则必须版本化：

- 无符号整数的字节序固定。
- 均匀浮点使用固定数量的有效随机位和明确区间，例如 `[0,1)`。
- 整数范围取样避免简单取模造成的偏差。
- 球面方向取样采用固定公式，避免经纬度均匀导致极区聚集。
- 正态分布等复杂取样使用确定性算法或版本化近似，不依赖不同运行时的默认实现。
- 对会触发分类门槛的结果设置明确量化／容差，避免不同平台微小浮点差异改变对象身份。

权威哈希和整数派生应达到逐位一致；连续物理计算则按各模型声明的数值容差验证。不能笼统承诺所有浮点中间值在所有硬件上逐位相同。

### 9.7 有界重试与候选选择

某些生成步骤可能需要在约束内选择候选，例如避免过小板块或寻找合法湖盆出口。允许确定性的有界重试：

```text
Random(namespace, entityId, property, attemptIndex)
```

必须满足：

- 最大尝试次数固定并版本化；
- 候选排序和接受条件固定；
- 实际选择的尝试编号进入证据；
- 全部失败时明确拒绝、降级或上报，不在后台更换世界种子；
- 增加无关候选不会改变已有候选的随机值。

### 9.8 种子不是世界的全部身份

以下两份世界即使种子相同，也不是同一 WorldSpec：

```text
seed = aurora-01, earthlike-v1, tectonics-v1
seed = aurora-01, earthlike-v1, tectonics-v2
```

种子用于提供可重复随机材料；预设、偏好、模型版本、空间规范和季节方案共同定义世界。界面应允许复制完整世界规格，而不能只复制种子后声称一定得到完全相同结果。

### 9.9 D05 建议规则

```text
种子统一规范为版本化 Unicode 文本
大小写区分，空白和控制字符按明确规则处理
WorldId 来自完整 WorldSpec，SeedKey 来自规范种子
使用命名空间与稳定标识随机访问样本
不使用跨模块共享的可变全局随机序列
局部细化和并行顺序不影响随机结果
分布转换、重试和候选选择全部版本化
失败时不隐藏更换种子
```

## 十、L2-D06：模型版本、兼容与世界迁移

自然引擎会持续改进。构造边界算法、气候输送、水文收支或地貌分类只要发生变化，同一种子就可能产生不同结果。D06 的目标是让旧世界可重现、新模型可采用，并且升级过程不覆盖用户已有世界。

### 10.1 世界规格必须锁定模型清单

WorldSpec 不只保存一个“引擎版本”，而要保存所有会影响自然结果的模型清单：

```text
specSchemaVersion
spatialModelVersion
seedProtocolVersion
planetPresetVersion
tectonicsModelVersion
terrainModelVersion
materialsModelVersion
climateModelVersion
hydrologyModelVersion
geomorphologyModelVersion
classificationModelVersion
seasonDefinitionVersion
```

每个模型版本必须是不可变发布：同一个版本号一旦用于保存世界，就不能在后续软件更新中改变行为。修正会影响结果的错误，也必须发布新行为版本。

### 10.2 模型清单 Manifest

每个模块提供机器可读清单：

```text
模型标识与行为版本
输入／输出数据结构版本
参数结构与默认预设版本
依赖模块及允许版本范围
声明使用的随机命名空间
数值确定性与容差说明
可读取的旧结构版本
可用的迁移器与限制
参考测试向量／基准摘要
```

人类可读的语义版本号用于沟通，但可重现性不能只依赖“1.2.3”文字。正式清单还应包含规范内容摘要或构建身份，以确认实际载入的是同一份模型契约。

### 10.3 三种兼容性必须分开

| 兼容类型 | 含义 | 示例 |
| --- | --- | --- |
| 存储兼容 | 新软件能读取旧快照文件 | 字段重命名但可无损转换 |
| 数据契约兼容 | 新模块能正确理解旧模块输出 | 新水文模型仍能读取旧地形高程和流域结构 |
| 行为／结果兼容 | 相同输入产生相同自然结果 | 修复仅涉及日志文字，不改变任何模型状态 |

“文件能打开”不代表“可以继续用新模型增量计算”。如果旧气候输出缺少新水文模型必需的湿度字段，那么存储上可读，数据契约上仍不兼容。

### 10.4 哪些变化会创建新世界规格

| 变化 | 是否改变 WorldId | 处理方式 |
| --- | --- | --- |
| 相机、配色、标签或高程夸张 | 否 | 只修改 ViewState |
| 线程数、缓存目录和任务顺序 | 否 | 只修改 GenerationPlan |
| 无损文件编码／压缩变化 | 否 | 迁移存储容器，保留原始摘要和迁移记录 |
| 添加不参与结果的诊断字段 | 通常否 | 新快照结构版本，行为版本不变 |
| 修复改变板块、温度、河流或分类结果的错误 | 是 | 发布新模型行为版本，创建升级分支 |
| 改变随机命名空间、取样分布或重试顺序 | 是 | 升级随机／模型版本，不能冒充旧结果 |
| 改变时间步、近似公式或分类阈值 | 是 | 新模型版本和新 WorldSpec |

判断标准不是改动大小，而是它是否可能改变权威自然状态、对象身份、证据或验收结论。

### 10.5 依赖失效图

升级一个模块时，只复用明确兼容的上游快照，并使所有受影响的下游结果失效：

```text
空间／规格
    ↓
构造 → 地形与材料 → 气候 → 水文 → 地貌与覆盖
              ↘───────────────↑
```

| 改变的模块 | 通常需要重算 |
| --- | --- |
| 空间规范 | 构造及全部下游模块 |
| 构造 | 地形、材料、气候、水文、地貌和覆盖 |
| 地形／材料 | 气候、水文、地貌和覆盖 |
| 气候 | 水文、季节覆盖及依赖气候的地貌分类 |
| 水文 | 河湖湿地状态、沉积近似、地貌和覆盖 |
| 地貌分类 | 对象分类、证据与显示索引；不反向修改上游自然状态 |
| 显示适配器 | 只重建显示缓存 |

实际复用范围由模型清单中的输入契约决定，不能只根据模块名称猜测。

### 10.6 打开旧世界的三种模式

建议桌面应用提供：

1. **原版本模式**：旧模型仍可用时，按原 WorldSpec 打开、查询和继续细化，维持原 WorldId。
2. **冻结查看模式**：旧模型不可用但快照完整时，只读查看已有状态和证据；不能用新模型悄悄补算缺失区域。
3. **升级分支模式**：复制原 WorldSpec，替换选定模型版本，创建新的 WorldId，并按依赖图重算；原世界保持不变。

升级不应原地覆盖。用户可以同时比较旧世界和升级分支，查看板块、河网、对象分类和验收结论发生了哪些变化。

### 10.7 纯存储迁移

如果变化只涉及文件结构、压缩或字段编码，且解码后的权威状态逐项相同，可以保持 WorldId：

```text
旧容器格式
   ↓ 无损迁移
新容器格式
```

迁移必须保存：

- 原文件或原快照摘要；
- 迁移器标识和版本；
- 迁移时间与目标结构版本；
- 迁移前后权威数据比较结果；
- 是否存在无法迁移的非权威缓存。

若无法证明无损，就不能归类为纯存储迁移。

### 10.8 对象身份与版本谱系

模型升级后，对象标识不一定可以机械沿用。例如新水文模型可能把一条河拆成两条分流，或把两个湖盆合并。

升级分支应保存对象谱系：

```text
旧对象 R17
├─ 新对象 R17a（主流）
└─ 新对象 R17b（分流）
```

谱系关系可以是：

- 保持；
- 修改；
- 拆分；
- 合并；
- 删除／不再成立；
- 新增。

只有身份、拓扑和生成依据都保持兼容时，才能沿用稳定对象标识。空间位置相近或名称相同不足以证明是同一对象。

### 10.9 升级报告

每次升级分支应生成：

```text
源 WorldId 与目标 WorldId
替换的模型及版本
复用、迁移和重算的快照范围
失效的缓存和证据
对象谱系变化
固定测试世界的前后结论
无法迁移或尚未验证的内容
```

如果新版本没有通过适用的 K01–K04、T01–T06 或全局规格测试，不应将升级结果标记为正式通过。

### 10.10 版本号与行为摘要

建议同时使用：

- 人类可读版本号：帮助理解兼容级别和发布历史；
- 行为版本：任何结果变化都必须更新；
- 清单摘要：确认实际参数、依赖和采样契约；
- 数据结构版本：决定快照和对象记录怎样读取；
- 引擎构建身份：用于诊断，不单独决定 WorldId。

不能仅凭“补丁版本”推定结果一定兼容。科学模型中的一个小阈值修正也可能改变流域出口或对象身份。

### 10.11 D06 建议规则

```text
WorldSpec 锁定所有结果相关模型版本
已发布模型版本的行为不可修改
存储兼容、数据契约兼容和结果兼容分开判断
结果相关变化产生新模型版本和新 WorldId
旧世界优先按原版本重现，无法运行时冻结只读
升级采用新分支，不原地覆盖旧世界
只复用清单明确兼容的上游快照
对象变化保存保持、拆分、合并等谱系关系
每次升级输出完整影响与验收报告
```

## 十一、L2-D07：固定测试世界覆盖机制

固定测试世界不是一个“碰巧生成了目标景观的随机种子”，而是一份版本化的受控输入规格。它在 `earthlike-v1` 和锁定模型清单之上，只覆盖为验证某条过程链所必需的字段。

```text
基础 WorldSpec／earthlike-v1
             ↓
固定测试世界输入覆盖层
             ↓
单因素变体覆盖层（可选）
             ↓
解析并冻结 TestWorldSpec
             ↓
自然引擎生成结果
             ↓
独立验收规则读取结果并判定
```

### 11.1 测试输入与验收预期必须分离

每个测试包分成两部分：

| 部分 | 内容 | 谁可以读取 |
| --- | --- | --- |
| `TestInput` | 固定地形、材料、水汽、来水、海平面和边界条件等输入 | 世界规格解析器和自然模块 |
| `TestOracle` | 预期方向、硬约束、失败条件、证据要求和容差 | 验收模块；自然生成模块不可读取 |

例如 T04 可以输入“大河来水、来沙、低坡河口和海洋边界”，但不能把“生成一个三角洲”作为输入字段。是否形成三角洲必须由引擎结果满足水量、沉积物和海岸保留条件后，由 `TestOracle` 判定。

这种隔离防止模型读取答案后直接制造目标景观。

### 11.2 测试世界覆盖层

覆盖层至少保存：

```text
testWorldId 与输入版本
基础预设和允许的模型版本
固定测试种子／随机协议版本
声明覆盖的字段路径
覆盖操作及其值、单位和原因
锁定字段
空间范围和边界条件
禁止使用的用户偏好
输入指纹与解析后的完整规格
```

覆盖操作只允许有限形式：

- 将某字段设为固定值；
- 将某参数范围替换为受控范围；
- 提供固定空间场、对象骨架或边界通量；
- 锁定某字段，阻止偏好或运行计划修改；
- 为测试目的启用／关闭一个明确声明的过程模块；
- 继承基础规格中未覆盖的所有字段。

不允许任意脚本在解析后修改 WorldSpec，也不允许覆盖生成结果、对象状态或验收结论。

### 11.3 覆盖白名单与作用域

每个固定测试世界都有自己的覆盖白名单。例如：

| 测试世界 | 允许覆盖 | 通常不允许覆盖 |
| --- | --- | --- |
| K02 汇聚边界 | 板块位置、相对运动代理、边界附近地形初值 | 气候、水文结果和最终山脉分类 |
| T01 湿润山地流域 | 山地、海洋水汽边界、温度／降水边界、雪水初态 | 直接写入河流流量或湖泊通过结论 |
| T03 冲积平原 | 上游来水来沙、低坡谷地、材料、出口 | 直接写入江洲、河曲或湿地对象 |
| T05 岩溶高地 | 可溶岩、裂隙、补给和出露边界 | 直接写入暗河、泉水或天坑分类 |

如果测试需要修改白名单之外的字段，必须升级测试输入版本并说明原因。解析器应输出基础规格与测试规格的完整差异，不能让未声明变化混入测试。

### 11.4 测试优先级与用户偏好

测试模式下的优先级为：

```text
自然硬约束与模型适用范围
> 固定测试输入与锁定字段
> 专门测试的变体覆盖
> 测试允许的用户输入
> 普通高级偏好
```

默认禁用普通用户偏好，避免“更多水量”之类的设置污染受控条件。只有测试目标本身就是验证偏好时，测试定义才显式允许相应字段。

测试覆盖不能突破模型适用范围。若某场景故意使用边界极值，应标记为边界／压力测试，不能把其结论当作普通类地世界有效性。

### 11.5 固定种子与随机控制

每个测试输入版本使用固定且可见的测试种子，例如：

```text
test/T01/input-v1
```

测试种子不能被用户种子替换。测试内部仍使用 D05 的命名随机流，因此：

- 重复运行得到相同背景细节；
- 增加无关取样不改变目标过程；
- 基础场景和单因素变体共享相同非目标随机样本；
- 失败可定位到具体输入、模型和随机样本。

固定测试世界不必完全消除随机性，但所有随机性必须可重复且与测试目标隔离。

### 11.6 单因素变体

T01–T06 中的 V01、V02 等变体应在基础测试规格上追加最小覆盖：

```text
BaseInput
└─ Variant V01
   ├─ 只改变一个声明字段或一个紧密耦合参数组
   ├─ 继承相同测试种子
   └─ 保存预期变化方向
```

运行前自动生成差异报告：

```text
允许变化：terrain.ridgeHeight
实际变化：terrain.ridgeHeight
未声明变化：无
```

如果发现其他 WorldSpec 字段变化，变体在生成前即判为配置失败。运行后再由 `TestOracle` 判断结果变化方向是否符合预期。

### 11.7 测试世界身份和版本

建议分开版本化：

```text
inputVersion：改变测试输入、覆盖字段或边界条件
oracleVersion：改变验收规则、容差或证据要求
```

改变 `inputVersion` 会改变 TestWorldSpec 和 WorldId。只改变 `oracleVersion` 不改变已经生成的世界状态，但会产生新的验收报告身份和结论版本。

每份报告至少绑定：

- TestWorldSpec／WorldId；
- 输入版本和验收版本；
- 完整模型清单；
- 基础场景或变体标识；
- 输出快照和证据摘要。

### 11.8 区域测试与全球上下文

固定测试世界可以是完整小型行星配置，也可以是嵌入球面空间的受控区域。区域测试必须显式声明边界：

- 上游来水、水汽、热量和沉积物输入；
- 下游出口、海洋、开边界或封闭边界；
- 周围地形与材料缓冲区；
- 哪些量由外部固定，哪些由区域内部计算；
- 边界影响区是否排除在核心验收范围之外。

区域测试不能假装边界不存在。没有全球气候上下文时，水汽或温度必须作为受控边界输入，并在结论中说明该限制。

### 11.9 禁止的测试捷径

固定测试世界不得：

- 直接写入“通过”“生成三角洲”或“这里是天坑”等输出答案；
- 为基础场景和变体使用不同隐藏种子；
- 在生成完成后修改结果以满足预期；
- 只保存截图而不保存状态、账本和证据；
- 用测试专用分支绕过正式守恒、拓扑或分类代码；
- 将区域边界输入描述成完整全球自然过程结果。

测试可以使用受控输入，但必须调用与随机世界相同的正式模型和数据契约。

### 11.10 D07 建议规则

```text
固定测试世界是版本化输入覆盖层，不是特殊结果脚本
TestInput 与 TestOracle 严格分离
每个测试只覆盖白名单字段，其他字段继承版本化预设
测试种子固定可见，命名随机流与目标过程隔离
单因素变体只允许声明字段发生变化
输入版本和验收版本独立管理
区域测试显式声明所有边界通量和适用范围
测试调用与随机世界相同的正式模型
```

## 十二、L2-D08：运行预算、完成状态与保存策略

WorldSpec 决定要生成哪一颗世界，GenerationPlan 决定本次计算投入多少时间、内存和存储。资源预算不能静默改变种子、模型、自然参数或硬约束，只能改变任务安排、当前完成范围以及是否使用明确标记的近似快照。

### 12.1 不使用含义模糊的“低／中／高质量”

一个“低质量”按钮可能同时意味着低分辨率、少算季节、不算地下水、缩短收敛次数或换用另一套公式，用户无法判断结果还能否比较。

建议首版使用三个明确运行目标：

| 运行目标 | 目的 | 最低输出 | 结论边界 |
| --- | --- | --- | --- |
| 快速预览 | 尽快看到世界骨架 | 全球空间、构造、海陆与粗地形；其他模块可缺失或使用明确近似 | 只能用于浏览方向，不能声称气候水文已完成 |
| 标准生成 | 得到首版可探索世界 | 基线层级的构造、地形材料、12 时间箱气候水文、Q0–Q3 代表态和对象查询 | 通过适用的内部硬检查；局部高阶对象仍可为候选或未细化 |
| 验证运行 | 审查模型和证据 | 标准生成结果、额外收敛／守恒诊断、方向性变体或指定固定测试 | 可形成正式验收报告；不等于现实数据验证 |

三个目标不改变 WorldSpec。它们产生同一世界下不同 `ComputationManifest` 和完成状态的快照。

### 12.2 快照身份与计算清单

同一 WorldSpec 可以同时拥有：

```text
WorldId W
├─ PreviewSnapshot P1
├─ StandardSnapshot S1
└─ ValidationSnapshot V1
```

每个快照保存计算清单：

```text
父快照与 WorldId
运行目标
已执行模块及版本
空间层级和活动区域
采用的近似与容差
完成／缺失／失败的任务
未满足的细化请求
证据和检查结果
内容摘要与 SnapshotId
```

预览和标准快照即使来自同一 WorldSpec，也不能共用同一个 SnapshotId。后续完整计算不会原地伪装成旧预览，而是创建新快照并把它标记为更完整的当前结果。

### 12.3 模块与区域完成状态

完成状态应同时记录到模块、季节、区域和对象证据中：

| 状态 | 含义 |
| --- | --- |
| 未计划 | 本次运行目标不包含该任务 |
| 等待／运行中 | 任务已进入计划或正在计算 |
| 已计算 | 模型已完成，但尚未执行全部适用验证 |
| 已验证 | 适用的硬检查、容差和证据要求已通过 |
| 近似 | 使用了明确声明的简化或低层级结果 |
| 条件通过 | 关键约束通过，但存在声明的缺失过程或精度限制 |
| 未验证 | 有可显示结果，但缺少必要证据或测试 |
| 失败 | 计算、守恒、收敛、兼容或资源要求失败 |
| 过期 | 上游快照或模型版本变化，结果不可继续作为当前结论 |

地图可以显示近似或未验证图层，但必须让用户看到状态。对象级“已计算、受约束生成、候选、泛化表达、不生成”继续用于自然对象；两套状态分别回答“任务完成到哪里”和“对象结论是什么”。

### 12.4 预算字段

GenerationPlan 可以包含：

- 允许的内存和磁盘缓存上限；
- CPU 线程和可用计算设备；
- 前台交互延迟目标与后台等待时间；
- 同时活动的区域和最大细化请求数量；
- 自动保存频率；
- 是否允许运行明确声明的近似任务；
- 本次优先的模块、季节、区域或测试世界。

线程数、缓存目录和任务顺序不影响 WorldId。预算导致的实际完成范围、近似和失败进入快照计算清单。

### 12.5 资源不足时的降级顺序

建议按以下顺序处理：

1. 取消 P3 预取与视觉美化任务。
2. 延后未选区域的 P2 观察细化，继续显示父级结果。
3. 限制同时活动区块并把已完成区块写入缓存。
4. 延后不影响当前目标的可选诊断和高阶分类。
5. 使用已声明的近似快照，并标记近似范围、模型和误差边界。
6. 若 P0 正确性或当前运行目标的最低条件仍无法满足，停止相关任务并报告资源不足。

任何降级都不能：

- 破坏水量、热量和沉积物守恒后继续标记完成；
- 删除河网、海岸、板块等关键拓扑来节省资源；
- 降低迭代次数却把未收敛状态标为稳定；
- 换用未记录的算法、隐藏种子或不同模型版本；
- 把只完成显示细分的区域标为自然模型已细化。

### 12.6 预览如何升级为标准结果

快速预览提供构造和粗地形后，标准生成应复用明确兼容的上游快照：

```text
预览：空间 → 构造 → 粗地形
                       ↓ 作为兼容上游输入
标准：              地形材料细化 → 气候 → 水文 → 地貌
```

若标准模型要求不同的空间层级或发现预览骨架不满足契约，应创建新的上游快照并使相关预览结果过期，不能为保持画面一致而保留错误骨架。

### 12.7 保存内容分级

| 类型 | 内容 | 是否必须保存 |
| --- | --- | --- |
| 权威规格 | WorldSpec、模型锁定清单、偏好解析、测试覆盖 | 必须 |
| 权威快照 | 已验证自然状态、对象注册表、账本、依赖和摘要 | 用户保存或正式验收时必须 |
| 检查点 | 任务图、迭代状态、随机协议位置、未完成请求 | 长任务恢复所需，完成后可按策略清理 |
| 可重建缓存 | 空间索引、显示网格、投影纹理、派生统计加速数据 | 可以删除 |
| 界面状态 | 相机、图层、选中对象和布局 | 可选，独立于世界身份 |

删除可重建缓存后，使用相同 WorldSpec、快照和模型版本应能恢复相同权威结果。若某项数据删除后无法可靠重建，它就不是普通缓存。

### 12.8 原子保存与恢复

保存应以完整检查点或已验证快照为单位：

1. 先写入新临时容器和校验摘要。
2. 确认所有必需数据、依赖和清单完整。
3. 原子地登记为新的有效快照。
4. 保留上一份有效快照，直到新快照验证完成。

程序中断、磁盘不足或任务失败时，应用打开最后一份有效快照，并显示哪些任务尚未完成。不能把半写入快照当成正式世界。

恢复计算还需要确认锁定模型是否可用。若模型缺失，按 D06 进入冻结查看或升级分支，不能用当前模型继续旧检查点。

### 12.9 自动保存与保留策略

建议：

- WorldSpec 创建后立即保存。
- 每个主要模块完成并通过最低检查后保存新快照。
- 长时间季节迭代和区域细化按时间／任务数量创建检查点。
- 用户显式保存、导出或运行验收时固定当前快照，避免被缓存清理。
- 自动检查点可按数量和空间预算清理，但至少保留最后有效快照和最近可恢复检查点。
- 删除正式快照、世界分支或验收证据属于显式管理动作，不由普通缓存淘汰执行。

### 12.10 D08 建议规则

```text
运行预算属于 GenerationPlan，不改变 WorldId
快速预览、标准生成和验证运行产生不同快照完成度
所有近似、缺失、失败和过期状态都显式记录
资源不足先取消预取和延后局部细化，不牺牲 P0 正确性
预览可复用兼容上游结果，但不能冒充完整世界
权威规格、快照和证据与可重建缓存分开保存
保存使用原子快照和可恢复检查点
模型缺失时冻结查看或建立升级分支，不混算
```
