# 构造验收与解释层设计

> **文档状态**
>
> - 文档类型：分层设计
> - 决策状态：已确认
> - 实现状态：未实现
> - 版本：0.2
> - 说明：L7-D01 至 L7-D07 架构决定已全部确认。

本文讨论构造子引擎的 L7“验收与解释层”。L7 不再生成板块、边界或构造地形约束；它从 L1—L6 的不可变快照、契约、证据和固定测试输入中，独立判断构造骨架是否满足已声明的规则，并把结论、失败位置、影响范围和解释链交给发布与调试流程。

关联文档：[构造引擎前置条件清单](构造引擎前置条件清单（讨论稿）.md) · [构造输出契约层设计](构造输出契约层设计（讨论稿）.md) · [第一版验收标准](../验收体系/第一版验收标准（讨论稿）.md) · [测试世界矩阵与验收顺序](../验收体系/测试世界矩阵与验收顺序（讨论稿）.md)。

## 一、L7 的职责与边界

### L7 负责

- 把 L1—L6 分散的硬约束、关系断言、固定世界、确定性和兼容性检查组成可版本化的验收计划。
- 区分执行状态、适用性、断言严重级和验收结论。
- 执行 K01–K04 构造固定世界、固定种子组、变形测试和消费者契约检查。
- 保证 `TestOracle` 与正式生成路径隔离。
- 从失败断言追溯到快照、字段、对象、空间区域、来源规则和最小复现输入。
- 输出可机器读取的验收报告，并向人类提供与之一致的解释。

### L7 不负责

- 不为了让测试通过而修改 L1—L6 的自然状态。
- 不把地图“看起来像地球”当成科学验收。
- 不用单一通过率掩盖未运行、不适用、未实现或缺少证据的项目。
- 不越权验收地形、气候、水文或地貌的最终结果。L7 只能判断构造输出是否具备成为它们上游输入的资格。
- 不用验收预期作为生成器的隐藏提示。

## 二、L7 的输入与输出

### 输入

- L1—L6 已冻结的快照及其规范摘要。
- 字段、对象、依赖图、证据图、缺失状态和兼容性报告。
- 版本化的 `ValidationPlan`、测试适用域、容差和发布配置。
- K01–K04 的 `TestInput` 与封闭的 `TestOracle`。
- 固定种子组、变形关系、跨平台规范摘要和历史基线。

### 输出

- `ValidationRun`：一次验收执行的不可变记录。
- `AssertionResult`：单项断言的适用性、执行状态、结论、数值、容差和证据。
- `ValidationReport`：按快照、层、测试世界、区域、对象和失败码组织的总报告。
- `FailureBundle`：最小复现输入、失败位置、直接证据、依赖切片和环境清单。
- `ExplanationView`：从验收结论追溯至 L6 证据图的只读解释视图。
- 面向 L6 发布流程的门槛结论，不含对自然状态的写入权。

## 三、L7 拟议决定

| 编号 | 问题 | 建议方向 |
| --- | --- | --- |
| L7-D01 | 验收状态与结论如何定义 | 执行、适用性、严重级和结论分轴；总结论不用平均分掩盖阻断失败 |
| L7-D02 | 测试目录如何组织 | 建立 L1—L6 要求追踪矩阵，分开单快照不变量、关系、统计、契约和迁移测试 |
| L7-D03 | K01–K04 如何成为正式测试资产 | 输入、Oracle、方向变体、容差和证据完全版本化，每层只验收自己有权回答的现象 |
| L7-D04 | 无现实唯一答案时怎样验证 | 使用变形关系、属性测试、固定种子统计和跨尺度／跨平台一致性 |
| L7-D05 | 验收结论如何解释 | 结论必须引用断言、输入、观测值、阈值、对象与 L6 证据链，文字只是派生表达 |
| L7-D06 | 失败如何定位和最小化 | 保存稳定失败码、空间切片、依赖切片、最小复现和影响范围，不把一个根因复制成大量无关错误 |
| L7-D07 | 报告与发布门槛如何统一 | 定义构造验收包、差异报告、调试发布和正式发布规则，并为后续子引擎复用 |

## 四、L7-D01：验收状态、适用性、严重级与结论

### 4.1 四个问题不得混成一个枚举

一条测试记录至少要分别回答：

1. **执行到哪里**：没有运行、正在运行、已完成，还是验收器自身出错？
2. **是否适用**：这条断言是否应用于当前模型、测试世界、对象或空间区域？
3. **它的严重程度**：违反后是否必须阻断，还是只能引起降级或提示？
4. **证据支持什么结论**：通过、条件通过、不通过，还是未验证？

如果把它们放进同一个 `status`，“未运行”、“不适用”和“没有发现错误”就容易被统计成通过。L7 将四个问题建模为独立维度。

### 4.2 执行状态

`executionState` 只表示验收器的运行过程：

| 状态 | 含义 | 能否产生科学结论 |
| --- | --- | --- |
| `NOT_RUN` | 未开始，或前置条件未满足 | 否 |
| `RUNNING` | 正在收集或计算证据 | 否 |
| `COMPLETE` | 按计划执行完成 | 是，但仍取决于证据完整性 |
| `ERROR` | 验收器、读取器或运行环境本身出错 | 否，不得记为被测模型失败 |
| `CANCELLED` | 本次执行被明确中止 | 否 |

`ERROR` 和自然模型的 `FAIL` 必须分开。例如报告文件无法写入，说明验收流程失败，不说明板块几何错误。

### 4.3 适用性

`applicability` 回答一条断言是否有权评价当前对象：

| 状态 | 含义 | 处理 |
| --- | --- | --- |
| `APPLICABLE` | 当前输入、模型能力和对象类型满足断言适用域 | 进入判定 |
| `NOT_APPLICABLE` | 规则明确不适用 | 单独记录，不进入通过率或总结论分母 |
| `UNDETERMINED` | 缺少判断适用性所需的元数据或能力声明 | 转为未验证，不得猜测为不适用 |

例如“洋壳扩张源两侧的更新接近度应递减”不适用于 K01 纯大陆背景；它应记为 `NOT_APPLICABLE`，不能算一个“自动通过”。

### 4.4 断言严重级

`severity` 由验收计划预先声明，不允许在看到结果后临时降级：

| 级别 | 典型含义 | 违反后果 |
| --- | --- | --- |
| `BLOCKING` | 空间覆盖、对象拓扑、非法数值、预期泄漏、快照篡改等基础安全性 | 整个发布单元不通过 |
| `REQUIRED` | 当前模型声明必须满足的物理、几何、关系或契约规则 | 对应范围不通过，并可阻断依赖它的下游发布 |
| `ADVISORY` | 已声明的质量、精度、性能或可选能力要求 | 可导致条件通过、能力降级或警告 |
| `INFORMATIONAL` | 仅用于对比、趋势或调试 | 不直接改变验收结论 |

“某种子世界山脉偏少”不应临时被定为阻断错误。只有当版本化规范事先声明了相应统计范围、样本和门槛，它才能作为正式断言。

### 4.5 四种对外验收结论

`verdict` 沿用已有共识：

| 结论 | 严格含义 |
| --- | --- |
| `PASS` | 所有适用的阻断与必需断言完成且通过；未出现需要降级的已声明限制 |
| `CONDITIONAL_PASS` | 阻断与必需断言通过，但存在已允许的可选过程缺失、精度限制或能力降级；降级范围必须可定位 |
| `FAIL` | 有充分证据证明至少一条适用的阻断或必需断言被违反 |
| `NOT_VERIFIED` | 不具备作出通过或失败结论的完整证据，包括未运行、执行错误、适用性未定或必需证据缺失 |

证据不足通常得到 `NOT_VERIFIED`，而不是 `FAIL`。但如果契约本身要求“必须提供来源证据”，而快照明确缺少该必需字段，那么“必需证据契约”本身可以判为 `FAIL`。

### 4.6 单项断言记录

每个 `AssertionResult` 至少包含：

```text
assertionId
requirementIds[]
planVersion
subjectSnapshotId
subjectScope
executionState
applicability
severity
verdict
observedValues[]
expectedRelation
toleranceProfile
evidenceRefs[]
failureCode?
limitationCodes[]
startedAt / finishedAt
validatorVersion
```

`subjectScope` 必须能表示整个快照、一层、一个字段、一个对象、一条边界段、一个球面区域或一个消费者视图。否则“失败”只能指向整个世界，无法安全重算局部。

### 4.7 聚合不使用平均分

同一范围的对外总结论按以下规则聚合：

1. 任一适用的 `BLOCKING` 或 `REQUIRED` 断言为 `FAIL` → 范围结论为 `FAIL`。
2. 无硬失败，但任一适用的必需断言为 `NOT_VERIFIED` → 范围结论为 `NOT_VERIFIED`。
3. 阻断与必需断言均通过，但存在允许的降级或适用的建议断言未达标 → `CONDITIONAL_PASS`。
4. 其余情况 → `PASS`。

某世界即使 999 项通过，只要有 1 项“球面覆盖存在空洞”的阻断断言失败，就不能用 99.9% 通过率发布。报告可以给出计数和比例，但它们只是描述量，不替代门槛逻辑。

### 4.8 前置失败与阻断传播

前置阻断失败后，L7 可继续执行不依赖它的只读诊断，但必须区分：

- `ROOT_FAILURE`：直接证明规则违反的根失败。
- `BLOCKED_BY_DEPENDENCY`：因上游失败而无法安全判定的后续项。
- `SECONDARY_FAILURE`：即使考虑上游问题，仍有独立证据的其他失败。

被阻断的项目是 `NOT_VERIFIED`，不是新的根失败。这样可以避免一个边界拓扑错误在报告中被复制成几万个伪“地形约束失败”。

### 4.9 Oracle 隔离

`TestInput` 可被正式模型读取，因为它就是受控世界输入。`TestOracle` 只能被 L7 读取，其中的预期方向、门槛、容差、必需对象和禁止结果不得进入 L1—L6。

每次固定世界验收应保存：

1. 生成前的 `TestInput` 规范摘要。
2. 不含 Oracle 的运行清单。
3. 在打开 Oracle 之前已冻结的生成快照摘要。
4. Oracle 版本及其独立评价结果。

移除验收器、更改报告语言或更换 Oracle 存储位置，不得改变生成快照的规范摘要。

### 4.10 校准数据与验收数据分离

将来用原型或现实参照调整阈值时，用于调参的世界或数据集属于 `CALIBRATION`；用于最终判断的属于 `ACCEPTANCE`。同一个样本可以在不同版本中变更用途，但不得在同一模型版本内同时用它选择门槛和声称独立通过。

K01–K04 主要验证关系和方向，不要求现实世界的精确数值复刻。如果以后声称某个绝对高度、速度或宽度在现实上有效，必须另行建立现实参照数据、指标和外部验证记录。

### 4.11 视觉检查的位置

地图和球体截图适合发现：

- 接缝、尖刺、条带、周期重复和过度平滑。
- 明显不连续的边界影响或与方向矛盾的约束图。
- 不合理的显示泛化、标签重叠或高程夸张。

但视觉检查的默认严重级为 `ADVISORY` 或 `INFORMATIONAL`。只有当问题能转化为可重复的几何、连续性或契约断言后，才能作为正式阻断条件。

### 4.12 D01 建议规则

1. 执行状态、适用性、严重级和验收结论必须分开。
2. 对外结论固定为通过、条件通过、不通过和未验证；不适用是适用性，不是通过。
3. 阻断和必需断言不得被平均分、总通过数或图像印象抵消。
4. 证据不足不得判为通过；验收器出错不得伪装成自然模型失败。
5. 严重级、适用域和容差在观察结果前由版本化计划固定。
6. `TestOracle` 不得进入 L1—L6，生成快照必须在 Oracle 评价前冻结。
7. 根失败、依赖阻断和独立次生失败分开记录。
8. 校准用样本与独立验收样本分开管理。

### 4.13 与早期扁平状态的兼容映射

[科学模型与验证规范](../总体架构/科学模型与验证规范.md) 早期将 `PASS / FAIL / BLOCKED / NOT_RUN / NOT_IMPLEMENTED / NOT_APPLICABLE` 放在同一状态列表中。L7-D01 不否定这些历史报告，而是将它们无歧义地拆回多个维度：

| 早期状态 | L7 映射 | 说明 |
| --- | --- | --- |
| `PASS` | `COMPLETE + APPLICABLE + PASS` | 必须同时具有完整证据 |
| `FAIL` | `COMPLETE + APPLICABLE + FAIL` | 必须引用被违反的断言 |
| `BLOCKED` | `NOT_RUN` 或 `COMPLETE` + `APPLICABLE` + `NOT_VERIFIED` + `BLOCKED_BY_DEPENDENCY` | 根据是否已执行到发现阻断来区分 |
| `NOT_RUN` | `NOT_RUN` + 无可发布结论 | 对外聚合时视为 `NOT_VERIFIED` |
| `NOT_IMPLEMENTED` | 能力限制码 + `NOT_VERIFIED` 或 `NOT_APPLICABLE` | 如果发布配置要求该能力，则未验证；如果明确不在当前配置适用域，则不适用 |
| `NOT_APPLICABLE` | `applicability = NOT_APPLICABLE` | 不产生通过结论，不进入分母 |

新报告以多维字段为权威表达；导出旧格式时可生成扁平兼容值，但必须保留信息损失警告。尤其是 `CONDITIONAL_PASS` 在早期列表中没有等价值，不得静默压成 `PASS`。

## 五、L7-D02：要求追踪矩阵与测试目录

### 5.1 验收从要求开始

L7 不能先积累一批测试，再猜它们覆盖了哪些自然规则。每项正式验收必须从一条版本化要求出发，并且可以反向从测试结果找回被验证的要求。

一条 `RequirementRecord` 至少包含：

```text
requirementId
sourceLayer
sourceDecision
statement
normativeLevel
subjectKinds[]
applicabilityRule
requiredEvidence[]
allowedVerificationMethods[]
failureImpact
introducedInVersion
supersedes[]
status
```

`statement` 必须可判定，例如“板块覆盖不重叠且无空洞”。“地图应该自然”只能成为设计目标，不能直接成为正式要求。

### 5.2 规范级别

`normativeLevel` 区分：

| 级别 | 意义 |
| --- | --- |
| `MUST` | 声明能力在适用域内必须满足，违反时不得正式发布 |
| `SHOULD` | 默认应满足；偏离时必须有明确理由、范围和降级表达 |
| `MAY` | 可选能力；未实现不能被表述为失败，但也不能声称已验证 |
| `INFORMATIVE` | 解释、示例或研究方向，不直接产生发布门槛 |

规范级别与 D01 的断言严重级相关，但不等同。一条 `MUST` 可能由多个 `REQUIRED` 断言和一个 `BLOCKING` 先决检查共同验证。

### 5.3 双向追踪

追踪图必须同时支持：

- `Requirement → TestCase → Assertion → Result → Evidence`：查某项决定如何被证明。
- `Result → Assertion → Requirement → Decision`：查某项失败为什么会阻断发布。
- `SnapshotField/Object → Evidence → Result`：查某个自然值参与了哪些验收。
- `ModelVersion → RequirementSet → ValidationPlan`：确定某版本应运行的完整测试面。

任何正式阻断断言如果没有 `requirementId`，只能进入诊断实验，不得临时改变发布结论。

### 5.4 测试类型目录

L7 使用明确的 `testMethod` 分类：

| 类型 | 回答的问题 | 例子 |
| --- | --- | --- |
| 单快照不变量 | 当前状态是否自洽 | 板块覆盖无空洞、对象引用有效 |
| 关系断言 | 多个量或对象的关系是否正确 | 汇聚增强时抬升资格不应系统减弱 |
| 固定世界 | 受控因果链是否符合预期 | K01–K04 |
| 变形测试 | 无唯一数值答案时，变换前后关系是否保持 | 整体球面旋转后拓扑和标量不变 |
| 统计集成 | 多个种子上是否出现系统性偏差 | 碎片板块数量、边界长度分布 |
| 契约测试 | 下游能否按声明读取 | `TerrainInputView` 字段和状态 |
| 序列化／迁移 | 保存、加载和允许的升级是否保真 | 规范摘要和对象身份不变 |
| 负向与故障注入 | 错误输入是否被拒绝且不损坏状态 | 缺块、坏哈希、非法拓扑 |
| 视觉诊断 | 是否存在尚未公式化的形态问题 | 条带、接缝或伪周期 |

一项要求可以由多种方法共同验证。例如跨面接缝正确性同时需要网格不变量、球面旋转变形测试和可视诊断图。

### 5.5 覆盖状态

每项 `MUST` 和 `SHOULD` 要求都有独立覆盖结论：

| 状态 | 含义 |
| --- | --- |
| `COVERED` | 所需的正常、边界、失败和证据路径均有适用测试 |
| `PARTIAL` | 只覆盖了部分适用域、分支或证据要求 |
| `GAP` | 当前没有能够支持结论的测试 |
| `CONFLICT` | 不同要求或断言对同一输入规定了不可同时满足的结果 |
| `OBSOLETE` | 要求已被新版本取代，仅供历史快照重放 |

`GAP` 和 `CONFLICT` 不是模型测试失败，而是验收规范本身不完整；它们会阻止相关能力被声称为“已验证”。

### 5.6 分层权限

每条要求和断言声明 `sourceLayer` 与 `subjectLayer`。

- L3 可以验收板块覆盖和运动代理，不能提前验收山脉。
- L4 可以验收边界分类和相对运动关系，不能声称最终海沟存在。
- L5 可以验收构造约束响应，不能验收最终高程或河流。
- L6 验收封装和契约保真，不重新决定 L3—L5 的科学结论。
- L7 聚合与解释结论，不发明新的自然值。

越层断言必须在计划解析时被拒绝，不等到生成完成后才发现。

### 5.7 需求变更

要求版本变化分为：

- 编辑性变化：不改变可判定语义。
- 适用域变化：新增或移除了受管范围。
- 门槛／容差变化：可能改变结论。
- 规范级别变化：会改变发布影响。
- 语义替换：必须新建 `requirementId` 并保留 `supersedes` 关系。

历史报告继续按它们当时的要求版本解释，不用新门槛静默重写旧结论。

### 5.8 D02 建议规则

1. 所有正式断言必须追溯到版本化要求和已确认决定。
2. 要求、测试、断言、结果与证据必须双向可查。
3. 覆盖缺口和规范冲突单独报告，不伪装成模型失败。
4. 测试分类保留其证明能力边界，视觉诊断不替代数值或关系断言。
5. 分层权限阻止提前验收下游现象。
6. 历史报告绑定原要求版本，要求语义变化不得原地覆盖。

## 六、L7-D03：K01–K04 固定世界资产与分层 Oracle

### 6.1 固定世界是版本化资产

K01–K04 不是临时配置文件，而是构造引擎的正式测试资产。每个 `TectonicTestWorldSpec` 包含：

```text
testWorldId / version
purpose
applicableLayers[]
testInputRef
sealedOracleRefsByLayer
variants[]
controlledFactors[]
fixedFactors[]
toleranceProfile
requiredEvidence[]
forbiddenGeneratorReads[]
expectedCapabilityLimits[]
```

测试资产的变化与模型变化分开版本。否则在修改模型的同时偷偷放宽 Oracle，会使回归结论失去意义。

### 6.2 TestInput 与 TestOracle 的物理隔离

`TestInput` 只描述受控的世界条件：板块几何、壳体倾向、欧拉运动代理、指定的模型版本和必需背景。`TestOracle` 描述预期关系、禁止结果、容差和必需证据。

例如 K02 可以输入“两板块沿法向相向运动”，但不得输入“此处必须是汇聚边界”或“请在这条线上生成造山约束”。这些只能由 Oracle 在快照冻结后判定。

### 6.3 分层 Oracle

同一固定世界在不同层有不同的有权问题：

| 层 | K02 汇聚世界可判定 | 不得判定 |
| --- | --- | --- |
| L3 | 覆盖、相邻、运动代理有限且参考系等价 | 汇聚类型、山脉 |
| L4 | 法向相向资格、边界分段、子类型和置信 | 最终高程、海沟或火山 |
| L5 | 抬升／缩短约束、宽度响应、衰减与来源账本 | 最终山峰、气候雨影 |
| L6 | 相同值、状态、证据在契约封装后保真 | 重新裁决 L3—L5 科学结论 |

一个下游现象不得被前置层“顺便验收”。这使失败能被准确定位到最早出现问题的层。

### 6.4 K01–K04 的统一职责

| 世界 | 核心因果 | 必须包含的变体类别 |
| --- | --- | --- |
| K01 壳体与基底 | 壳体连续属性与板块身份解耦，大陆／过渡／洋壳基底连续 | 淹没大陆条件、稳定核心、洋壳更新、跨板块同壳体 |
| K02 汇聚 | 相向运动、汇聚子类型、极性或碰撞资格、连续响应 | 对称／非对称洋—洋、洋—陆、陆—陆、斜向汇聚、边界端部 |
| K03 离散 | 分离运动、张裂／扩张资格、有源更新与衰减 | 大陆张裂、过渡张裂、洋壳扩张、无源洋壳域、斜向扩张 |
| K04 走滑与三重点 | 切向主导、转换连接、压扭／张扭、三分支拓扑闭合 | 一般走滑、转换边界、压扭、张扭、三重点闭合、退化端部 |

### 6.5 单因素变体

每个变体必须声明：

- 唯一主动改变的 `controlledFactor`。
- 必须保持不变的 `fixedFactors`。
- 预期改变方向、预期不变项和允许的次生响应。
- 不允许出现的语义升级。

若一个变体同时改动壳体倾向、运动速度和网格尺度，它可以用于组合回归，但不能证明单一因果关系。

### 6.6 方向关系优先于过早数值冻结

在参数尚未通过原型标定时，Oracle 优先声明：

- 符号或排序关系。
- 空间连续、衰减或局部性。
- 拓扑闭合和对象连接。
- 允许的 UNKNOWN 与置信下降。
- 不得出现的伪结论。

绝对米值、宽度、速度、比例和样本门槛只有在参数已标定、适用域已声明后才成为硬 Oracle。

### 6.7 数值黄金快照的位置

黄金快照可用于发现未预期变化，但不能成为唯一 Oracle。正式报告必须区分：

- 规范关系仍正确，但数值实现发生了允许变化。
- 结果变化超出已声明容差。
- 对象身份或拓扑发生了语义变化。
- 测试资产版本不同，结果不可直接比较。

### 6.8 资产变更审查

以下变更必须生成测试资产差异报告：

- 增删变体或受控因素。
- 修改 Oracle 方向、禁止结果、容差或严重级。
- 改变固定网格、尺度、板块几何或运动代理。
- 改变某层的验收权限。

资产变更后，旧报告保留，新旧结果仅在兼容性报告允许时才直接对比。

### 6.9 D03 建议规则

1. K01–K04 的输入、Oracle、变体、容差和证据都是版本化资产。
2. `TestInput` 与 `TestOracle` 物理隔离，快照先冻结、Oracle 后评价。
3. 同一测试世界按 L3—L6 分层评价，每层只回答自己有权判定的问题。
4. 单因素变体与多因素组合回归分开标记。
5. 未标定阶段优先验证方向、连续、拓扑和禁止结果，不过早冻结伪精确数值。
6. 黄金数值快照只是回归证据之一，不替代语义断言。

## 七、L7-D04：属性、变形、统计、跨尺度与跨平台验证

### 7.1 构造世界没有唯一正确图像

一个种子对应的板块布局不存在现实世界中可逐像素对照的唯一答案。因此 L7 不把“与一张标准地图相同”当作主要验收方式，而是组合五类证据：

1. 单世界必须满足的不变量。
2. 控制变量前后必须成立的变形关系。
3. 多种子集成上的统计边界。
4. 网格层级与局部细化之间的语义一致。
5. Windows 与 macOS 等支持平台之间的规范一致。

### 7.2 不变量与容差关系

断言按数学性质区分：

| 类型 | 示例 | 比较方式 |
| --- | --- | --- |
| 精确不变量 | 对象标识、拓扑连接、枚举状态、源账本引用 | 精确相等 |
| 守恒／闭合关系 | 板块覆盖总面积、三重点闭合残差 | 根据面积、尺度和浮点误差的明示容差 |
| 顺序关系 | 增强汇聚输入后局部抬升资格不应系统降低 | 单调或排序断言 |
| 形态关系 | 边界响应连续并随距离衰减 | 连通、梯度、零交叉或尺度摘要 |
| 统计关系 | 大样本中不应经常出现极小碎片板块 | 预声明指标、样本和置信区间 |

每个近似断言必须引用 `toleranceProfileId`。“基本一样”、“差不多”和代码内未记录的隐藏 epsilon 不能成为正式判据。

### 7.3 变形测试目录

L7 首版至少保留以下变形家族：

| 变换 | 必须保持 | 允许改变 |
| --- | --- | --- |
| 相同请求重复运行 | 快照规范摘要、对象身份、值、状态和证据结论 | 日志时间、内存地址和非规范调试顺序 |
| 任务顺序／线程数变化 | 自然状态与规范摘要 | 执行时间和缓存命中 |
| 整体球面旋转 | 标量、拓扑、类型和相对几何；向量随旋转等变 | 经纬度数值与面索引表达 |
| 立方球面面重映射 | 物理邻接、距离、面积和对象连接 | 存储布局 |
| 增加局部细化 | 未受影响的全球骨架、稳定对象身份和父级守界摘要 | 受授权区域的局部细节和误差范围 |
| 序列化、压缩、缓存清除 | 公共查询、规范摘要和解释结论 | 字节布局、块顺序和运行性能 |
| 投影、配色、语言、高程夸张变化 | 全部自然状态和验收结论 | 显示结果 |
| 局部输入扰动 | 明确失效范围之外的状态 | 依赖图覆盖范围内的派生值 |

“增大构造活动度就必须让每个位置都更高”不是合法变形关系。参数的因果作用需要按它真正控制的字段、空间范围和统计指标声明。

### 7.4 固定种子统计集

统计验收使用版本化的固定种子集，而不是每次随机抽取直到结果好看。每项统计断言预先声明：

- 种子集标识和选择规则。
- 样本数及中止条件。
- 指标的单位、聚合方式和空间加权。
- 参考范围、置信区间、多重比较或假阳性控制。
- 该指标是阻断、建议还是仅用于趋势观测。

统计集用于发现系统性偏差，不要求每个种子都具有相同的板块数、边界类型比例或地形约束分布。

### 7.5 防止对固定集过拟合

如果模型调整直接参考了某些固定种子的失败，这些样本自动进入校准集。正式验收还需要：

- 未用于调参的保留种子集。
- 属性与变形测试，避免只记住具体地图。
- 必要时的扩展随机探索，但其发现在固定为新测试前只作诊断证据。

### 7.6 跨尺度一致性

粗细层级不必逐单元相同，但必须满足字段描述器声明的聚合语义：

- 平均型标量按真实面积加权。
- 极值、范围和存在性摘要不能只由平均值代替。
- 方向字段在球面切平面中正确聚合，不直接平均经纬分量。
- 线性对象和拓扑关系通过对象泛化表达，不从单元投票重建身份。
- UNKNOWN、低置信和强冲突不得在上采样中被平均掉。

### 7.7 跨平台确定性等级

Windows 和 macOS 的一致性分为：

| 等级 | 要求 |
| --- | --- |
| A 规范精确 | 世界、快照、对象身份，拓扑，枚举状态，原因码，规范摘要一致 |
| B 容差等价 | 明确许可浮点差异的连续字段在预声明容差内，且不导致分类、拓扑或发布结论分叉 |
| C 展示独立 | 像素、字体、抗锯齿和 GPU 细节可不同，不参与自然快照摘要 |

如果 B 级浮点差异跨过某个分类门槛，导致一个平台为汇聚、另一个为 UNKNOWN，则不是“可接受的浮点差异”，必须阻断。

### 7.8 非确定性排查

对间歇失败的测试，L7 应在不改变输入的前提下收集：

- 不同任务顺序与线程数。
- 冷缓存与热缓存。
- 不同分块加载顺序。
- 不同序列化往返次数。
- 重复运行的规范摘要集合。

只要相同输入可以产生多个权威摘要，该模型版本就不得正式发布。

### 7.9 D04 建议规则

1. 不依赖唯一参考地图，组合不变量、变形关系、统计、跨尺度和跨平台证据。
2. 精确等价和容差等价分开；所有容差版本化。
3. 统计种子集、指标、样本数和判定方法在看到结果前固定。
4. 校准种子与保留验收种子分开，未固定的随机发现先作诊断。
5. 粗细尺度按字段语义比较，不要求逐单元相同。
6. 跨平台差异不得改变对象身份、拓扑、分类、状态或发布结论。

## 八、L7-D05：验收证据与人类可读解释

### 8.1 验收证据图

L6 证据图解释“自然值为什么出现”；L7 在其上建立 `ValidationEvidenceGraph`，解释“为什么这份快照获得某个验收结论”。

证据图的主要节点包括：

- 要求和已确认决定。
- 测试计划、用例、断言和 Oracle 版本。
- 快照、字段、对象、空间范围和依赖版本。
- 观测值、预期关系、容差和适用性判定。
- 根失败、阻断关系、能力限制和最终结论。
- 对应的 L6 自然证据节点。

L7 不复制 L6 的整个来源账本，而是使用稳定引用把验收断言连到必需的自然证据。

### 8.2 每个结论的最小证据

一个可发布的 `AssertionResult` 至少回答：

1. 验收的是哪条要求。
2. 为什么该要求对当前对象适用或不适用。
3. 读取了哪个快照、字段、对象和区域。
4. 观测值、预期关系和容差是什么。
5. 使用哪个验收器、要求版本和 Oracle 版本。
6. 结论如何从证据得出，又如何影响上层聚合。

仅有“预期 0.8，实际 0.7”不足以解释失败；还必须知道数值的单位、聚合方式、容差、空间范围以及 0.8 是方向门槛、校准范围还是仅为回归基线。

### 8.3 解释查询

L7 支持以下结构化查询：

| 查询 | 回答 |
| --- | --- |
| `WHY_VERDICT` | 为什么得到 PASS、CONDITIONAL_PASS、FAIL 或 NOT_VERIFIED |
| `WHY_NOT_PASS` | 哪些根失败、必需未验证或已允许降级阻止了完全通过 |
| `WHAT_WAS_TESTED` | 当前范围运行了什么，哪些不适用或被阻断 |
| `WHAT_REMAINS_UNVERIFIED` | 覆盖缺口、未实现能力、缺失证据和适用性未定项 |
| `WHY_CHANGED` | 两次验收之间由模型、输入、要求、Oracle、容差或平台中哪一项导致结论变化 |
| `WHAT_IS_AFFECTED` | 失败或限制影响哪些区域、对象、字段、能力和下游消费者 |
| `SHOW_MINIMAL_EVIDENCE` | 在不丢失结论依据的前提下返回最小证据子图 |

### 8.4 人类文本不是权威证据

中文或其他语言的报告由结构化证据渲染。更换文字模板、翻译或排版时：

- `reasonCode`、`failureCode`、数值、单位、容差和引用不变。
- 结论不变。
- 不允许文字模板将 UNKNOWN 或 NOT_VERIFIED 润色成确定事实。
- 不允许省略导致条件通过的能力限制。

### 8.5 解释详细度

| 级别 | 用途 | 必须保留 |
| --- | --- | --- |
| 摘要 | 世界列表、发布状态、普通查询 | 结论、根原因、影响范围、限制数量和计划版本 |
| 标准 | 开发调试和设计审查 | 断言、观测值、预期、容差、主要依赖和局部证据 |
| 完整 | 复现、科学审计和模型迁移 | 完整追踪图、输入清单、所有中间观测、版本、环境和规范摘要 |

详细度只改变输出体积，不改变断言结论或不确定性。

### 8.6 比较解释

两份报告比较前，必须先判定：

- 世界规格和测试输入是否可比。
- 模型、契约、要求、Oracle 和容差版本是否相容。
- 对象能否通过稳定身份或谱系关系对齐。
- 空间范围和网格层级是否允许相同聚合。

结论变化至少分为：`REGRESSION`、`IMPROVEMENT`、`EXPECTED_CHANGE`、`NEWLY_VERIFIED`、`NO_LONGER_VERIFIED` 和 `NOT_COMPARABLE`。不可比结果不得标记为回归。

### 8.7 证据体积与保留

证据可以按断言、区域、对象和失败簇分块。可重建的调试时序、中间可视化和性能采样可按策略裁剪，但以下内容必须保留：

- 结论所依赖的最小证据子图。
- 所有根失败和能力限制。
- 要求、计划、Oracle、容差和验收器版本。
- 被验收快照的规范摘要和输入清单。
- 发布门槛的聚合路径。

### 8.8 D05 建议规则

1. L7 证据解释验收结论，通过引用连接 L6 自然证据，不复制整个账本。
2. 每个结论必须包含要求、范围、观测、预期、容差、版本和聚合路径。
3. 人类文本从结构化证据生成，翻译和模板不改变结论。
4. 摘要、标准和完整解释的结论一致。
5. 快照比较先判定可比性，再标记回归或改进。
6. 最小发布证据、根失败、能力限制和发布聚合路径不得被裁剪。

## 九、L7-D06：失败归因、最小复现与影响范围

### 9.1 失败事件与失败原因分开

一个根因可能导致许多断言报错。例如跨面邻接断裂可以同时触发板块覆盖、边界连续、对象查询和构造场连续失败。L7 将其分为：

- `FailureOccurrence`：某条断言在某范围上的一次失败观测。
- `FailureCluster`：根据断言、空间、对象谱系和依赖图聚合的相关失败簇。
- `RootCauseCandidate`：由证据支持的根因候选，允许多个和 UNKNOWN。
- `DependencyBlock`：由根失败导致的后续未验证。

聚类不能仅依靠错误文本相同；它必须参考稳定失败码、依赖关系、空间重叠和观测证据。

### 9.2 稳定失败身份

每个失败事件保存：

```text
failureCode
assertionId
requirementId
subjectScope
snapshotId
occurrenceFingerprint
clusterId?
rootCauseRelation
firstObservedVersion
evidenceRefs[]
```

`occurrenceFingerprint` 从断言、规范化范围、关键对象身份和失败类型派生，不包含时间戳、本机路径或任务顺序。快照改变后可以通过对象谱系尝试对齐，但语义不兼容时必须建立新失败身份。

### 9.3 因果归因的证据等级

L7 不应因为两个失败出现在相近区域就断言因果。根因关系分为：

| 等级 | 含义 |
| --- | --- |
| `PROVEN` | 依赖图、受控复现或故障注入证明移除该原因后失败消失 |
| `SUPPORTED` | 时间、空间、依赖和变形证据一致，但尚未完成最小对照 |
| `POSSIBLE` | 与证据兼容，但仍有多个同样合理的候选 |
| `UNKNOWN` | 当前证据无法区分原因 |

报告不得将 `POSSIBLE` 渲染成已确定的根因。

### 9.4 最小复现包

`FailureBundle` 至少包含：

- 原始世界规格或固定测试输入的内容引用。
- 模型、存储、契约、要求、计划、Oracle、容差和验收器版本。
- 失败所需的最小权威快照块，以及它们的哈希和依赖切片。
- 触发失败的查询、断言和观测数据。
- 球面范围、对象身份、拓扑邻域和必要的上下文缓冲区。
- 支持平台、数值模式、并发计划和运行环境摘要。
- 预期结论及原失败指纹。

复现包必须可以在不读取原工作目录、缓存或界面状态的情况下重放。

### 9.5 语义保持的最小化

自动最小化可尝试：

- 删除与失败无依赖关系的快照块。
- 缩小球面区域，但保留足够的拓扑缓冲区。
- 裁剪无关字段和诊断证据。
- 在固定世界中删除非必需变体。
- 缩短边界段或对象集，同时重新验证核心失败指纹。

最小化不得：

- 直接编辑生成结果以保留失败。
- 破坏板块覆盖、球面邻接或对象拓扑的必需前提。
- 将原失败替换成另一种更简单的失败。
- 读取 Oracle 来修改自然输入。

每次最小化后都必须重新运行原断言，并确认失败码、关键观测和根因关系仍等价。

### 9.6 空间影响范围与因果范围

L7 分开两种范围：

- `causalScope`：已知或候选根因所在的最小区域、对象或字段集。
- `impactScope`：由依赖图计算出的可能受影响下游范围。

影响范围可以比因果范围大得多。一个局部边界拓扑错误可能使整条边界对象和其约束场都不可信，但不能因此声称整条边界都是根因。

### 9.7 复测分类

修复或环境变化后的复测结果分为：

| 结果 | 意义 |
| --- | --- |
| `FIXED` | 原失败不再出现，原断言通过，且未引入新阻断失败 |
| `PERSISTS` | 同一失败指纹或谱系对齐后的同一语义失败仍存在 |
| `CHANGED_FAILURE` | 原失败消失，但该范围出现了另一种失败 |
| `FLAKY` | 同一规范输入在重复运行中产生分叉结论 |
| `NOT_COMPARABLE` | 要求、Oracle、容差、输入或语义版本不允许直接对比 |

`FLAKY` 在自然权威输出上是确定性阻断，不能用“重试到通过”隐藏。

### 9.8 D06 建议规则

1. 失败事件、失败簇、根因候选和依赖阻断分开建模。
2. 失败身份不依赖时间戳、机器路径或任务顺序。
3. 根因结论保留证据等级和 UNKNOWN，不把空间相邻当成因果。
4. 最小复现包独立于原工作目录、缓存和界面状态。
5. 最小化保留物理、几何和拓扑前提，不直接编辑输出。
6. 因果范围和影响范围分开。
7. 复测区分已修复、仍存在、失败改变、间歇失败和不可比。

## 十、L7-D07：验收包、差异报告与发布门槛

### 10.1 统一验收包

L7 最终输出不是一个布尔值，而是不可变 `TectonicValidationPackage`：

```text
packageHeader
subjectSnapshotRef
validationPlanRef
requirementSetRef
testAssetManifest
runManifest
assertionResults
coverageReport
verdictTree
evidenceManifest
failureBundles
comparisonReport?
capabilityStatement
releaseGateDecision
canonicalDigest
```

验收包与被验收 `TectonicSnapshot` 双向引用，但不改变原快照内容。相同快照可以在新的要求集上产生新验收包，旧包继续保留。

### 10.2 结论树

结论按以下层级聚合：

```text
Assertion
  → TestCase / Variant
    → Requirement
      → Layer
        → Capability
          → ConsumerProfile
            → Snapshot release gate
```

每个上层结论都保存参与聚合的子项、被排除的不适用项、聚合规则和根失败。用户可以从“不可发布”一直展开到具体观测值和球面位置。

### 10.3 能力声明

`capabilityStatement` 对每项能力记录：

- 能力标识与版本。
- 适用的行星预设、网格层级、模型和消费者。
- PASS、CONDITIONAL_PASS、FAIL 或 NOT_VERIFIED。
- 已验证的范围和未覆盖边界。
- 允许近似、已知限制和禁止声明。
- 相关固定世界、统计种子集和现实参照状态。

“构造引擎已验证”不能作为无范围的统称。可以精确声称“在 `earthlike-v1` 和已列网格层级上，板块覆盖、边界关系、构造约束和下游契约已按某计划版本验证”。

### 10.4 诊断与正式发布

L7 对 L6 发布状态给出门槛建议：

| L7 情况 | 允许的 L6 用途 |
| --- | --- |
| 存在阻断／必需 `FAIL` | 仅 `DRAFT` 或 `DIAGNOSTIC_ONLY`，不向正式下游消费者发现 |
| 存在必需 `NOT_VERIFIED` | 仅 `DRAFT` 或 `DIAGNOSTIC_ONLY` |
| `CONDITIONAL_PASS` | 默认 `DIAGNOSTIC_ONLY`；只能向明确接受对应限制的具名实验性消费者提供，不进入标准地形生成路径 |
| 标准发布配置 `PASS` | 才可将快照原子设为 `RELEASED` 并向标准下游发现 |

这一规则保守处理首版：条件通过世界可以被查看、调试和对比，但不伪装成无限制的正式上游。未来若需要“受限正式发布”，应新增具名消费者配置和明确能力边界，不放宽现有 `RELEASED` 语义。

### 10.5 发布前置顺序

标准构造发布至少依次检查：

1. 验收计划、要求集、测试资产和容差内部一致。
2. L1—L6 必需快照、清单、块哈希和规范摘要完整。
3. 所有阻断与必需单快照断言通过。
4. K01–K04 的适用分层 Oracle 通过。
5. 变形、固定种子统计、跨尺度和跨平台必需项通过。
6. L6 消费者契约、序列化、缓存重建和原子发布检查通过。
7. 覆盖报告不存在相关 `MUST` 缺口或规范冲突。
8. 验收包及其最小证据、失败包和能力声明完整。
9. 快照与验收包组成单一原子发布事务。

前序失败后可以继续诊断，但后序通过不能抵消发布阻断。

### 10.6 原子性与绑定

正式发布记录必须同时绑定：

- `snapshotId` 与快照规范摘要。
- `validationPackageId` 与验收包规范摘要。
- 发布配置、能力声明和消费者契约版本。
- 发布状态与事务记录。

任一块缺失、哈希不匹配或验收包指向另一快照时，整个发布不可用。不允许“快照已发布，报告稍后补齐”。

### 10.7 差异报告

新版本与基线比较时，报告分开：

- 输入与世界规格变化。
- 模型与契约变化。
- 要求、Oracle、容差与测试资产变化。
- 自然快照的字段、对象、拓扑和状态变化。
- 验收结论的回归、改进、新验证、失去验证和不可比。
- 能力声明和下游可用性变化。

数值差异未超容差不自动等于“无变化”；如果对象身份、拓扑、分类或证据来源发生变化，仍必须显式报告。

### 10.8 历史保留与取代

新发布不删除旧快照或验收包。旧版可转为 `SUPERSEDED`，并保留：

- 当时的输入、模型、要求和验收结论。
- 取代它的快照和原因。
- 是否为错误修复、模型升级、要求变更或单纯新世界。
- 旧消费者的可重放性与兼容性。

### 10.9 L7 的自验收

L7 本身也必须被验证：

- 用人工构造的 PASS、CONDITIONAL_PASS、FAIL 和 NOT_VERIFIED 结果树验证聚合。
- 注入缺失证据、坏哈希、错误 Oracle 版本和依赖环验证拒绝。
- 验证报告语言、排版和详细度不改变结论。
- 验证快照与验收包交叉绑定和原子发布。
- 验证旧状态映射、历史报告重放和不可比检测。

L7 失败时不得为自己生成通过证明。验收器的测试与被验收模型的测试使用独立资产和失败空间。

### 10.10 D07 建议规则

1. L7 输出不可变验收包，不以单一布尔值取代明细。
2. 结论从断言、用例、要求、层、能力、消费者到发布门槛逐级聚合。
3. 所有“已验证”声明都必须附带行星预设、模型、尺度、消费者和已知限制。
4. 首版标准 `RELEASED` 只接受标准发布配置 `PASS`；条件通过默认仅诊断或具名实验用途。
5. 快照、验收包、能力声明和发布状态原子绑定。
6. 差异报告分开输入、模型、验收资产、自然状态和结论变化。
7. 旧发布以 `SUPERSEDED` 保留历史和重放能力，不原地改写。
8. L7 有独立自验收集，不能为自身故障生成通过结论。
