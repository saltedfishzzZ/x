本文说明构造引擎开始设计和实现前必须具备哪些前置条件。这里的“构造引擎”指首版用于生成板块、洋陆倾向、边界类型候选与大尺度高程约束的模块；它不是完整的地幔对流和板块运动历史模拟器。

## 零、构造子引擎与整体自然状态引擎

地形、气候、水文、材料和地貌分类都属于**整体行星引擎**。它们不应被塞进“构造子引擎”的内部，因为每个系统都有独立的输入、状态、约束和验收规则；但它们必须在同一套自然状态引擎中协同工作。

```text
类地行星引擎
│
├─ 世界规格与空间底座
│   ├─ 种子、预设、模型版本、稳定随机流
│   └─ 球面网格、跨尺度映射、世界快照
│
├─ 构造子引擎                  ← 本文重点
│   └─ 板块、边界、构造地形约束
│
├─ 地形与材料子引擎
│   └─ 高程、海陆、坡度、盆地、分水岭、岩性与表层
│
├─ 气候子引擎
│   └─ 温度、水汽、降水、蒸发需求、雨雪与融雪条件
│
├─ 水文子引擎
│   └─ 径流、积雪、地下储量、河湖、湿地、分流与入海收支
│
├─ 地貌与覆盖子引擎
│   └─ 河谷、峡谷、瀑布、三角洲、岩溶、植被／覆盖与分类状态
│
└─ 验收、解释与展示适配层
    └─ 测试世界、对象证据、地图、局部三维与桌面应用
```

这些子引擎的关系如下：

```text
空间与世界规格
        ↓
构造 → 地形与材料 → 气候 → 水文 → 地貌与覆盖
                     ↘───────↑
                地形与材料对水文提供容器与入渗条件
```

箭头表示首版的主要计算方向，不表示绝对隔离。例如气候读取地形高程和海陆；水文同时读取气候、地形和材料；地貌读取全部上游状态。首版不让“地貌名称”反向修改构造或基础高程。需要反馈时，应以受控迭代和新的派生快照表达，而不是跨模块直接写入数据。

因此，构造子引擎的 L6“输出契约层”不是把下游模块排除在外，而是为它们提供可信的共同上游输入：板块、边界、构造约束和稳定空间标识。下游模块位于整体引擎中，并通过这些契约组合出完整世界。

## 一、先确定构造引擎的职责边界

构造引擎需要明确交付以下结果：

```text
稳定球面空间单元
→ 板块区域及稳定标识
→ 洋壳／陆壳初始倾向
→ 板块边界及其类型候选
→ 造山、裂谷、洋盆等大尺度地形约束
→ 供地形、材料、气候与水文模块使用的证据
```

首版不交付以下结果：

- 板块从某个远古初态连续运动到当前的真实历史。
- 地幔对流、地壳热演化、地震、火山喷发、断层破裂或精确地层年代。
- 现实地球某座山脉、海沟或大陆的精确复刻。

这个边界是第一项前置条件。若不先限定输出，构造模块会在“随机大陆轮廓”和“完整地球物理模拟”之间失去可实现、可验证的范围。

## 二、启动所必需的前置条件

以下条件缺失时，不能开始正式的构造骨架实现。

| 编号 | 前置条件 | 必须确定的内容 | 原因 |
| --- | --- | --- | --- |
| P01 | 世界规格 | 种子、固定类地背景版本、模型版本、允许的高级偏好 | 确保同一请求可重现，并区分不同世界或不同模型 |
| P02 | 球面空间体系 | 全球单元、邻接关系、面积／距离计算、跨经线和极区规则、稳定单元标识 | 板块边界、距离、面积和局部细化都依赖它 |
| P03 | 板块数据模型 | 板块标识、覆盖范围、壳体倾向、运动／应力代理量、年龄或成熟度的状态边界 | 让“板块”成为可查询对象而非颜色区域 |
| P04 | 板块初始分布规则 | 板块数量范围、中心或生长规则、最小面积、避免碎片化的规则 | 控制大陆与构造区的全球可读性和稳定性 |
| P05 | 相对运动代理 | 如何以简化方式表达两板块相向、相离或走滑的趋势 | 决定边界类型候选，不能仅靠两种颜色相邻 |
| P06 | 边界分类门槛 | 汇聚、离散、转换／走滑、模糊或未分类边界的判定条件与置信状态 | 造山带、裂谷和海盆必须有不同的生成前提 |
| P07 | 构造到地形的契约 | 构造输出怎样约束高程、洋盆、山脉、裂谷、岛弧候选；哪些只提供倾向 | 防止地形模块忽略构造或反向篡改板块结果 |
| P08 | 可重现随机流 | 构造随机流的名称、作用域和与其他模块的隔离规则 | 使显示、局部细化或新增模块不会改变板块骨架 |
| P09 | 证据与验收格式 | 板块、边界和构造地形候选须保存的输入、判据、版本和降级原因 | 支持固定测试与“为什么这里有山脉”的查询 |

## 三、用于讨论的引擎结构与分层

构造引擎不应被理解为一个“生成板块的函数”。它应是自然状态引擎中最上游的一组分层能力：底层保证球面空间和可重现性，中间层构成板块及边界，顶层把构造结果翻译为地形和材料能够读取的约束。

```text
┌──────────────────────────────────────────────┐
│ L7  验收与解释层：构造测试、证据、查询、失败定位 │
├──────────────────────────────────────────────┤
│ L6  输出契约层：构造约束场、对象与下游接口       │
├──────────────────────────────────────────────┤
│ L5  构造地形约束层：抬升、裂谷、洋盆、结构控制   │
├──────────────────────────────────────────────┤
│ L4  边界动力学代理层：汇聚、离散、走滑、不确定   │
├──────────────────────────────────────────────┤
│ L3  板块状态层：板块覆盖、壳体倾向、运动代理     │
├──────────────────────────────────────────────┤
│ L2  全球规格层：类地预设、种子、模型版本、偏好   │
├──────────────────────────────────────────────┤
│ L1  球面空间与可重现性底座：网格、邻接、随机流   │
└──────────────────────────────────────────────┘
```

层间只允许自下而上的数据依赖。高层可以读取低层结果，但不能为了让画面“更好看”而修改下层的板块覆盖、边界类型或随机流。

### L1：球面空间与可重现性底座

**回答的问题**：世界在哪里？相邻关系如何定义？同一请求能否重现？

**拥有的数据**：

- 球面单元及稳定标识。
- 单元面积、中心坐标、邻接、球面距离与方向。
- 全球、区域和局部层之间的映射。
- 按名称隔离的构造随机流和快照身份。

**向上输出**：可信的空间查询、邻接图、面积与距离计算，以及由世界规格派生的随机流。

**不负责**：板块、海陆、高程、边界类型或任何景观名称。

**已确认方案**：L1-D01 至 L1-D06 已全部确定。采用等角分层立方球面、四叉细化、中心／边／顶点混合布局、统一细化协调器、不可变父快照与版本化细化补丁、独立对象拓扑，并以球体、等经纬图和局部切平面／三维作为首版视图。具体分辨率、缓存和误差容差由空间原型验证。详见：[球面空间底座设计](球面空间底座设计（讨论稿）.md)。

### L2：全球规格层

**回答的问题**：这颗行星按什么背景条件生成？哪些输入属于同一个可复现世界？

**拥有的数据**：

- 世界种子与世界快照标识。
- 固定类地背景版本：半径、重力等级、海平面参考、板块数量范围等。
- 用户允许调整的高级偏好，以及它们对哪个模块生效。
- 启用模块、模型版本、测试世界配置和运行状态。

**向上输出**：不可变的世界规格。L3 及以上层只能读取它，不能将一次生成结果写回为新的输入。

**不负责**：随机抽样后的板块边界、地形高程或现实参数标定。

**已确认状态**：L2-D01 至 L2-D08 的架构决定已完成。首版采用版本化固定类地预设，默认只输入种子，高级偏好调整因果先验；世界规格、运行计划和显示状态分离，模型、测试覆盖、随机协议、运行完成度和保存策略均有独立版本与证据。定量值与具体算法留待对应原型和模型校准。

### L3：板块状态层

**回答的问题**：球面由哪些板块覆盖？它们的基本壳体倾向和运动代理是什么？

**拥有的数据**：

- 板块标识、覆盖范围、中心／骨架与最小面积约束。
- 陆壳、洋壳、过渡壳等初始倾向。
- 每板块的相对运动代理或应力代理。
- 板块成熟度、稳定度或活动度等可选状态。

**向上输出**：完整、无重叠、无空洞的板块覆盖，以及在任意位置查询所属板块和壳体倾向的接口。

**不负责**：边界究竟是汇聚还是离散；最终海陆、高程、河网和气候。

**关键约束**：壳体倾向不等于海陆标签。大陆可局部低平或被海水淹没，洋壳也可能形成海岛或高地候选。

### L4：边界动力学代理层

**回答的问题**：相邻板块之间的相对关系是什么？它为哪类构造现象提供资格？

**拥有的数据**：

- 相邻板块对、边界单元或连续边界线。
- 相对运动在边界法向和切向上的代理量。
- 汇聚、离散、走滑、不确定等分类及其强度、置信度。
- 三重点、复杂边界和低置信区域的显式状态。

**向上输出**：具有方向和影响强度的边界约束，而不是已经画好的山脉或裂谷。

**不负责**：真实应力求解、地震模拟、火山喷发、精确断层几何，或用边界类型直接指定高程。

**关键约束**：允许“不确定”。不完整的运动代理必须降低分类状态，而不是为了地图完整性强制归类。

### L5：构造地形约束层

**回答的问题**：板块和边界趋势如何改变“哪些地方更有资格成为高地、裂谷、洋盆或线性结构带”？

**拥有的数据**：

- 大陆基底与洋盆基底的相对高程倾向。
- 汇聚边界的抬升／造山约束场。
- 离散边界的裂谷、低地、洋中脊或张裂约束场。
- 走滑边界的线性结构控制候选。
- 距边界的衰减范围、组合规则与来源证据。

**向上输出**：连续的构造约束场、候选区和成因证据，供地形和材料模块组合使用。

**不负责**：具体山峰、峡谷、河谷、海岸线、岩性或植被。后续地形模块有权加入多尺度起伏和侵蚀结果，但不能无理由消除构造约束的来源记录。

**关键约束**：边界附近不应出现一条同宽、同高的人工山脉。约束必须能与板块、材料、地形扰动和后续侵蚀共同作用。

### L6：输出契约层

**回答的问题**：构造引擎以何种稳定、可验证的形式交给其他自然模块？

**拥有的数据**：

- 构造快照与版本摘要。
- 供地形模块读取的基底和约束场。
- 供材料模块读取的壳体倾向、构造区和结构控制候选。
- 供查询模块读取的板块、边界、候选区和证据索引。
- 依赖图与失效范围。

**向上输出**：只读构造快照。任何下游模块的结果都以新的派生快照存在，不回写构造快照。

**不负责**：直接调用渲染、处理鼠标交互或保存桌面应用的界面状态。

**关键约束**：输出中必须明确每个字段的单位／归一化方式、空间分辨率、模型状态和适用范围，避免下游误用“候选”值为“已计算事实”。

### L7：验收与解释层

**回答的问题**：构造骨架是否满足自身契约？一片高地或边界为什么会出现？失败时回查哪里？

**拥有的数据**：

- K01–K04 构造固定测试世界及其变体。
- 覆盖、邻接、边界分类、方向性与可重现性检查结果。
- 对象查询的证据链：世界规格 → 板块 → 边界 → 约束场。
- 通过、条件通过、不通过、未验证等结论。

**向上输出**：验收报告、失败位置、失效范围和查询解释。

**当前状态**：L7-D01 至 L7-D07 已全部确认，构造子引擎 L1—L7 架构讨论完成。详见：[构造验收与解释层设计](构造验收与解释层设计（讨论稿）.md)。

**不负责**：为了通过测试而修改任何自然状态；验收层只能报告和定位问题。

## 四、两条横切能力

下面两项不是单独的自然层，但必须贯穿 L1–L7：

### 4.1 版本与可重现性

每层产物都要记录输入快照、模型版本、随机流名称与摘要哈希。这样才能区分“同一种子、不同预设”与“同一预设、不同模型版本”造成的差异。

### 4.2 证据与模型状态

每一层都要保存其结果是已计算、受约束生成、候选、泛化表达还是不生成。越靠上层的对象不能掩盖下层的不确定性，例如 L5 的低置信构造约束不能在地图中显示为“已证实山脉”。

## 五、层间数据流与禁止的反向写入

```text
L1 空间／随机流
        ↓
L2 世界规格
        ↓
L3 板块覆盖与壳体倾向
        ↓
L4 边界运动代理与类型
        ↓
L5 构造地形约束场
        ↓
L6 只读构造快照 ───→ 地形、材料、气候、水文模块
        ↓
L7 验收与解释
```

禁止的反向写入包括：

- 为了让大陆轮廓更美观，显示层直接移动板块边界。
- 因为后续河流不好看，水文模块回写抬升带或改变板块类型。
- 因为某处缺少山峰，地貌分类模块直接提高 L5 的构造高程约束。
- 因为局部三维细节更丰富，按访问顺序改变 L1 的随机流或单元边界。

允许的后续改动只能通过新的世界规格或派生快照完成，并由依赖图声明重算范围。

## 六、建议的讨论顺序

为避免一次讨论全部算法，建议按以下顺序确认：

1. **先确认 L1**：球面空间体系应优先保证什么——等面积、局部细化、实现简洁，还是渲染方便？
2. **再确认 L2**：固定类地预设中哪些参数必须冻结，哪些可以作为高级偏好。
3. **再确认 L3**：板块是以“有限刚性区域”表示，还是采用更抽象的构造分区；是否需要过渡壳。
4. **再确认 L4**：相对运动代理要达到什么可信度，是否必须支持走滑和三重点。
5. **再确认 L5**：构造约束对高程的影响应只是候选引导，还是需要成为强制的地形骨架。
6. **最后确认 L6、L7**：快照、对象查询、K01–K04 与未来 T01–T06 如何进入工程工作流。

现阶段最值得先讨论的是 L1：球面空间体系。它决定板块覆盖、边界连续性、局部细化和后续所有自然模块的公共坐标基础。

## 七、固定类地背景中应先给定的参数

用户已确认首版采用固定类地背景。因此以下参数不必一开始开放为高级选项，但必须在一个版本化预设中有明确取值或范围。

| 参数组 | 首版应给出的内容 | 对构造结果的影响 |
| --- | --- | --- |
| 行星几何 | 半径、球形近似、重力等级或等价地形尺度 | 单元距离、面积、相对高差与流域尺度 |
| 壳体类别 | 至少区分陆壳倾向、洋壳倾向和可选过渡壳 | 海陆基底、高原、洋盆与岛屿候选 |
| 板块数量范围 | 合理的最小值、目标范围、最大值 | 板块尺度、边界密度和大陆破碎度 |
| 相对运动尺度 | 只需定义归一化的运动／应力强度与分布 | 汇聚、离散、走滑边界的相对显著性 |
| 海平面参考 | 作为后续海陆阈值与洋盆解释的稳定基准 | 大陆面积、海岸和盆地出口 |
| 高程响应范围 | 造山、裂谷、洋中脊、洋盆的相对高程影响上限 | 避免构造约束生成不合尺度的尖峰或深坑 |
| 构造稳定性假设 | 首版是“代表性构造状态”，非连续运动史 | 防止季节切换或局部浏览改变板块边界 |

这里的数值应被视为项目预设，而不是一开始就宣称为现实地球的唯一正确参数。只有当后续开放其他行星类型时，才需要将它们变为可调输入并重新验证适用范围。

## 八、构造数据模型的最低内容

### 4.1 板块记录

每个板块至少需要：

```text
板块标识
球面覆盖范围与边界
主壳体倾向（陆壳／洋壳／过渡）
相对运动代理向量或应力代理场
构造成熟度／稳定度（可选）
生成来源、随机流与模型版本
```

“主壳体倾向”不是最终海陆标签。海陆还会受高程、海平面和后续地形处理影响；这样可以表达低平大陆、淹没陆架或抬升洋壳候选，而不把板块颜色直接等同为陆地。

### 4.2 边界记录

每段边界至少需要：

```text
边界标识 · 相邻板块 A/B
空间折线或边界单元集合
相对运动分类：汇聚／离散／走滑／不确定
强度与置信状态
地形约束：造山、裂谷、洋中脊、海沟或一般边界候选
证据与依赖版本
```

边界允许处于“不确定”状态。首版不应为了视觉完整把全部接缝强行归类为某种现实构造类型。

### 4.3 构造地形约束记录

构造模块输出的是约束场和候选区，而不是已完成山峰网格：

- 大陆基底／洋盆基底倾向。
- 汇聚边界附近的抬升与高地候选。
- 离散边界附近的裂谷、低地或洋中脊候选。
- 走滑边界附近的线性结构控制候选。
- 距边界衰减的影响范围、强度和方向。

地形模块在这些约束内加入侵蚀、材料、盆地和多尺度细节，且必须保留构造来源。

## 九、首版可采用的构造近似

在不求解完整动力学的前提下，首版可以采用以下方法：

1. 在球面空间上确定有限数量的板块种子，并通过受控生长或球面最近域形成覆盖。
2. 给每块板块分配独立且可重现的壳体倾向与相对运动代理。
3. 根据相邻板块的相对运动在局部法向上的分量，判定汇聚、离散或走滑趋势；分类保留置信度。
4. 从边界类型生成连续的构造约束场，而非沿边界直接绘制锯齿状山脉或裂缝。
5. 将构造约束与多尺度地形扰动、材料和海平面共同输入地形模块，形成可被后续水文使用的稳定高程容器。

这套近似必须满足的物理方向性是：汇聚趋势通常提高高地／造山资格，离散趋势通常提高裂谷或洋盆资格，走滑趋势主要提供线性结构控制而不自动制造最高山脉。它不声称给出真实板块速度、应力值或地质历史。

## 十、构造引擎与后续模块的接口

| 下游模块 | 从构造引擎读取 | 不应从构造引擎读取 |
| --- | --- | --- |
| 地形 | 基底倾向、边界类型、影响强度、稳定空间标识 | 已完成河谷、瀑布、湖泊或植被标签 |
| 材料 | 壳体倾向、构造区、结构控制候选 | 精确岩性、土壤厚度或洞穴网络 |
| 气候 | 高程的上游来源、海陆初始关系 | 直接指定降水、风向或气候分类 |
| 水文 | 高程容器、分水岭和海陆出口 | 任意河网或水量 |
| 地貌分类 | 构造高地、裂谷、结构线等成因证据 | 绕过材料与水文的最终对象名称 |
| 显示与查询 | 板块、边界、证据和模型状态 | 可修改的内部状态 |

## 十一、构造层的验收条件

构造引擎至少应通过以下不依赖气候与水文的检查：

| 编号 | 条件 | 验证方式 |
| --- | --- | --- |
| C01 | 同一世界规格生成相同的板块、边界与约束场 | 重复生成并比较稳定标识与结果摘要 |
| C02 | 板块完整覆盖球面，无重叠、空洞或极区断裂 | 球面单元覆盖与邻接检查 |
| C03 | 板块数量、面积与边界长度处于预设容许范围 | 全局统计与最小面积检查 |
| C04 | 边界类型来自相对运动代理，且保留不确定状态 | 构造边界审计表 |
| C05 | 汇聚、离散、走滑控制改变时，相应地形约束按方向变化 | 单因素变体比较 |
| C06 | 显示层、局部放大或新增无关模块不会改变构造快照 | 随机流与快照哈希比较 |
| C07 | 构造高地或裂谷候选可追溯到边界、壳体和参数依据 | 对象查询与证据包检查 |

## 十二、建议的最小构造测试世界

T01–T06 主要验证构造之后的自然系统。构造模块自身还应有四个更小的受控测试世界：

| 编号 | 固定设定 | 应验证的结论 |
| --- | --- | --- |
| K01 单一大陆板块与洋壳背景 | 一个大陆倾向区被洋壳倾向区包围 | 海陆基底倾向连续、板块覆盖完整、无边界碎片 |
| K02 汇聚边界 | 两板块相向的相对运动代理 | 汇聚线附近产生连续高地／造山约束，远离边界逐步衰减 |
| K03 离散边界 | 两板块相离的相对运动代理 | 形成裂谷／低地或洋中脊约束，不误判为汇聚山脉 |
| K04 走滑与三重点 | 走滑边界及三板块交汇 | 线性结构控制与边界拓扑保持稳定，不产生无解释的尖峰 |

K01–K04 通过后，构造输出才作为 T01–T06 的可信上游输入。它们不替代自然系统测试，而是降低后续失败定位的难度。

## 十三、尚待决定的内容

- 具体采用哪一种球面网格及其局部细化算法。
- 板块覆盖采用最近域、生长前沿、图分割还是其他受控方案。
- 运动代理是每板块刚体向量、边界应力场还是更抽象的构造类型生成器。
- 海陆阈值与壳体倾向如何共同作用，以及是否允许独立大陆碎片和岛弧候选。
- 造山、裂谷和洋盆约束的具体形状函数、影响范围、数值尺度与与材料模块的耦合深度。
- K01–K04 是否与 T01–T06 一起进入首版验收标准。

本文列出构造引擎开始实现前的决策与数据条件，不等于已经选定任何具体算法或参数。
