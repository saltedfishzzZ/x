# 构造输出契约层设计

> **文档状态**
>
> - 文档类型：分层设计
> - 决策状态：已确认
> - 实现状态：未实现；工程选型待定
> - 版本：0.2

本文讨论构造子引擎的 L6“输出契约层”。L6 不再生成板块、边界或构造场，而是把 L1–L5 已确认的权威状态组织成统一、只读、版本化和可验证的构造快照，供地形、材料、查询及后续自然模块通过稳定接口读取。

关联：[构造引擎前置条件清单](构造引擎前置条件清单（讨论稿）.md) · [全球规格层设计](全球规格层设计（讨论稿）.md) · [板块状态层设计](板块状态层设计（讨论稿）.md) · [边界动力学代理层设计](边界动力学代理层设计（讨论稿）.md) · [构造地形约束层设计](构造地形约束层设计（讨论稿）.md)。

## 一、L6 的职责与边界

### L6 负责

- 绑定 L1–L5 的不可变上游快照及完整模型清单。
- 定义公共对象、字段、单位、空间层级、状态和查询语义。
- 为不同下游模块提供受限、稳定的只读视图。
- 保存构造对象与字段的依赖关系和失效范围。
- 区分正式公共契约、诊断证据和可重建缓存。
- 提供对象、位置、区域、多尺度和证据查询入口。
- 管理契约版本、兼容性、序列化和升级分支。
- 原子发布统一构造快照，并阻止不合格输入进入下游。

### L6 不负责

- 重新计算或修改 L1–L5 的自然状态。
- 根据下游需要改变板块、边界、壳体或构造资格。
- 生成最终地形、材料、气候、水文或景观分类。
- 调用渲染、处理鼠标交互或保存桌面界面状态。
- 把内部调试缓存、数组布局或算法步骤承诺为永久公共接口。
- 隐藏上游的不确定、条件、失败或候选状态。

## 二、L6 的输入与输出

### 输入

```text
L1 COMPLETE + PASSED 空间快照
L2 WorldSpec 与模型版本锁
L3 COMPLETE + PASSED PlateStateSnapshot
L4 COMPLETE + PASSED BoundaryDynamicsSnapshot
L5 COMPLETE + PASSED TectonicTerrainConstraintSnapshot
公共契约版本和下游能力声明
```

### 输出

```text
TectonicSnapshot
├─ 世界、空间、模型与契约头
├─ 公共对象目录
├─ 公共字段目录
├─ 地形／材料／查询等只读视图
├─ 空间查询与多尺度语义
├─ 依赖图、失效范围和对象谱系
├─ 证据索引与状态说明
├─ 兼容性和序列化信息
└─ 可重建缓存清单
```

## 四、L6-D01：公共契约、诊断证据与缓存分层

### 4.1 L6 是统一外观，不复制整个世界

L6 的 `TectonicSnapshot` 是面向下游的统一外观。它绑定并引用 L1–L5 权威快照，按公共契约暴露必要对象和字段，不把所有内部数组复制成一份新的可变数据集。

这样可以：

- 保持对象身份和来源引用唯一；
- 避免多份字段失去同步；
- 允许内部缓存独立重建和淘汰；
- 让公共契约版本与内部存储实现分开；
- 明确下游究竟依赖哪个上游快照。

### 4.2 三层数据结构

建议分为：

| 层级 | 内容 | 下游能否作为计算依赖 |
| --- | --- | --- |
| A 公共权威契约 | 稳定对象、字段值、单位、状态、空间语义、版本和依赖 | 可以，按消费者视图限制 |
| B 诊断与证据 | 生成来源、候选拒绝、修复、限幅、测试、失败和解释链 | 只用于查询、审计和调试，不作为隐式自然输入 |
| C 可重建缓存 | 网格覆盖索引、空间加速结构、显示几何、量化预览 | 不可以，可删除重建 |

B 层中的某项证据若未来需要参与自然计算，必须经过正式数据契约升级进入 A 层，不能让下游偷偷读取日志字段。

### 4.3 公共快照头

`TectonicSnapshotHeader` 至少包含：

```text
tectonicSnapshotId
WorldId / WorldSpecVersion
L1SpaceSnapshotId
PlateStateSnapshotId
BoundaryDynamicsSnapshotId
TectonicTerrainConstraintSnapshotId
publicContractVersion
modelManifestDigest
generationStatus / validationStatus
planetGeometryAndUnitSystem
createdByModelVersion
parentSnapshotId / upgradeBranchId
canonicalDigest
```

创建时间可作为审计元数据，但不参与自然结果身份。只有全部必需上游快照和契约检查通过后，才能原子发布正式构造快照。

### 4.4 公共对象目录

首版公共对象至少包括只读视图：

```text
PlateView
CrustDomainView
BoundaryView
KinematicSegmentView
BoundarySubtypeSegmentView
JunctionView
ConstraintSourceView
```

每个对象公开：

- 稳定对象标识和类型；
- 球面范围或多尺度几何引用；
- 合法连接和父子／来源关系；
- 公共状态、置信和适用范围；
- 模型及数据契约版本；
- 证据索引；
- 可查询但不可修改的字段集合。

显示名称、颜色和界面选择状态不是对象身份，也不进入自然计算。

### 4.5 公共字段目录

每个公共字段都由 `FieldDescriptor` 描述：

```text
fieldId / namespace / stableName
semanticDefinition
valueType / shape
unit / referenceDatum / normalization
validRange / clampPolicy
valueStatusDomain
confidenceSchema
spatialSupport：点／边／单元／区域／线性对象
availableLevels / nativeResolution / errorEstimate
aggregationRule / interpolationRule
missingValuePolicy
sourceSnapshot / sourceFields / dependencyIds
modelState：已计算／受约束生成／候选／泛化表达／不生成
contractVersion / deprecationState
```

缺少单位、归一化方式、空间支持、缺失语义或聚合规则的字段不得进入 A 层公共契约。

### 4.6 首版公共字段组

首版至少公开以下命名空间：

```text
space.*
  球面位置、稳定单元、真实面积／距离和层级关系

plate.*
  plateId、主／微类型、球面分区、运动代理摘要

crust.*
  大陆性、厚度、浮力、过渡、稳定核心和相对成熟状态

boundary.*
  boundaryId、邻接、三重点、运动分量、分段和子类型资格

tectonicConstraint.*
  基底倾向、抬升／沉降、方向张量、参考贡献、冲突和来源账本

quality.*
  状态、置信、误差、完成度、限幅和失败代码
```

字段组名称和稳定语义属于公共契约；具体内存数组、压缩块和缓存键不属于公共契约。

### 4.7 不进入公共自然契约的内容

以下内容默认留在 B／C 层：

- 候选生成的全部随机尝试序列；
- 被拒绝候选的临时几何；
- 松弛求解器逐次迭代数组；
- 修复前的临时非法拓扑；
- 线程、任务队列和区块调度信息；
- 内存偏移、对象指针和容器布局；
- 显示用颜色、选中状态和相机参数；
- 可从权威对象重建的覆盖索引、三角网和等值线。

其中必要摘要可以通过证据索引查询，但不能成为下游自然模块的未声明输入。

### 4.8 只读的含义

只读不仅是接口没有“保存”按钮，还包括：

- 公共对象和字段以内容寻址或不可变句柄读取；
- 不提供修改 L1–L5 权威值的 setter；
- 下游不能获得可写内部缓冲区；
- 任何修改意图必须创建新的 WorldSpec、模型分支或派生快照；
- 下游生成结果保存自己的 snapshotId，并引用 tectonicSnapshotId；
- 删除缓存不改变构造快照身份和查询结果。

开发诊断工具可以读取失败快照，但不能以调试权限原地修复后继续冒充原快照。

### 4.9 状态和不确定性原样传播

公共契约必须保留：

```text
generationStatus / validationStatus
ZERO / UNKNOWN / NOT_APPLICABLE / FAILED / CLAMPED
候选／受约束生成／已计算／泛化表达／不生成
置信度分项
空间误差和原生分辨率
```

L6 不能为了简化接口把未知变成零、把候选改称已计算事实、把低置信字段转成普通数值，或只公开合成值而隐藏冲突和来源状态。

### 4.10 避免字段复制和语义漂移

公共字段优先引用权威上游数据或通过声明式派生视图计算。如果确需物化：

- 保存来源快照和字段标识；
- 保存派生公式／转换版本；
- 校验值摘要与引用闭合；
- 上游变化后旧物化值标为过期，不能静默复用；
- 同一语义只存在一个稳定 public fieldId。

不能分别为地形、材料和查询模块复制三个名称不同但含义相同的“大陆性”数组。

### 4.11 安全的缓存降级

C 层缓存可以：

- 按空间层级或区域逐出；
- 在不同平台使用不同内部布局；
- 从公共对象和字段重建；
- 带独立 cacheVersion；
- 失败时回退到较慢的权威查询。

缓存缺失只能影响性能，不能改变数值、对象身份、状态或解释结果。若某数据无法从 A 层和版本化模型重建，它就不是缓存，必须重新评估是否属于权威状态。

### 4.12 D01 建议规则

```text
TectonicSnapshot 是引用 L1–L5 权威快照的统一只读外观，不复制成可变世界
数据分为公共权威契约、诊断证据和可重建缓存三层
只有 A 层字段能成为下游正式自然计算依赖
公共对象保存稳定身份、球面范围、连接、状态、版本和证据索引
每个公共字段必须声明语义、单位、空间支持、分辨率、聚合、缺失和来源
公共字段按 space／plate／crust／boundary／tectonicConstraint／quality 命名空间组织
内部尝试、迭代数组、调度、显示状态和可重建索引不进入公共自然契约
只读要求内容寻址、无可写缓冲、下游创建派生快照且不得回写
未知、候选、低置信、限幅和失败状态必须原样传播
同一语义只有一个稳定 public fieldId，物化派生值保存公式和上游引用
缓存删除只影响性能，不能改变结果和解释
```

## 五、L6-D02：球面位置、对象、区域与多尺度查询

L6 查询必须使用权威球面空间语义，而不是屏幕像素、当前投影或视图缩放。一次查询绑定唯一 `tectonicSnapshotId`，并明确目标、字段、精度要求和允许的降级方式。

### 5.1 统一查询请求

建议使用：

```text
TectonicQueryRequest
├─ tectonicSnapshotId
├─ requestedFieldIds
├─ spatialTarget
│  ├─ 球面点／稳定 cellId
│  ├─ 球面区域
│  ├─ objectId
│  ├─ 球面路径／走廊
│  └─ 全局摘要
├─ resolutionPolicy
├─ errorTolerance
├─ aggregationPolicy
├─ stateAndConfidenceFilter
├─ resultBudget / pagination
└─ consumerViewId
```

缺少快照标识的查询不得自动读取“当前最新世界”，否则同一计算过程可能混用多个版本。

### 5.2 球面点查询

点查询使用三维单位向量或等价规范球面坐标：

```text
queryPoint = normalized 3D vector
```

经纬度可以作为输入便利格式，但进入查询前转换为权威向量。结果至少返回：

- 实际采样球面位置；
- 所属稳定空间单元和层级；
- 字段值、状态、置信与误差；
- 采用的插值或归属规则；
- 相关板块、边界和贡献来源引用。

落在边界上的点应返回稳定唯一的单元归属，同时允许对象查询返回两侧板块和共享 boundaryId。

### 5.3 区域查询

区域使用球面多边形、球冠、稳定单元集合或版本化球面包围体表示。禁止以未声明投影中的普通矩形作为权威区域，因为它可能跨日期变更线、极区或立方球面接缝。

区域查询可以返回：

```text
面积加权统计
门槛覆盖率
对象交集与包含关系
字段极值及位置
方向张量摘要
未知／失败／低置信覆盖率
主要来源贡献
```

面积统计必须使用 L1 真实球面面积，不按像素数量计数。

### 5.4 对象查询

对象查询以稳定 objectId 为入口，支持：

- 对象基础属性和球面范围；
- 父子、邻接、来源和谱系；
- 与对象关联的公共字段；
- 多尺度几何；
- 证据索引和验证状态；
- 与指定区域或其他对象的空间关系。

对象名称、颜色和列表位置不能替代 objectId。跨模型版本查询旧 objectId 时，通过谱系返回延续、拆分、合并、消失或未知，不猜测一对一对应。

### 5.5 路径与走廊查询

为地形剖面和区域分析提供球面路径／走廊查询：

- 路径由大圆弧、球面折线或对象几何引用定义；
- 采样间距使用真实距离和误差要求；
- 返回沿程弧长、字段值、对象交叉和状态变化；
- 走廊宽度使用球面距离；
- 穿越接缝和极区时保持连续。

路径查询不能依赖当前二维地图上画线后的像素长度。

### 5.6 多尺度和误差策略

建议三种明确策略：

```text
EXACT_AVAILABLE_LEVEL
  指定已经存在的权威层级；缺失则失败，不隐式换层

AT_MOST_ERROR
  返回满足误差上限的最低成本层级；不能满足时明确降级／失败

BEST_AVAILABLE
  在预算内返回最佳现有结果，并报告实际层级、误差和覆盖
```

查询可以构建可重建缓存，但不能修改自然快照或因访问顺序生成不同细节。需要新增权威细化补丁时，应由运行计划产生新的空间／自然快照，而不是查询接口静默完成。

### 5.7 字段插值和聚合服从描述符

不同字段使用不同规则：

- 连续标量按 FieldDescriptor 规定进行面积、球面或核插值；
- plateId、类别和状态等离散值不做数值插值；
- 方向张量在共同切平面中平行移动后组合；
- 线性边界使用最近合法弧段和弧长参数查询；
- 资格场区域统计同时保留均值、峰值与覆盖率；
- UNKNOWN、FAILED 等状态单独统计，不参与普通数值平均。

调用方不能临时指定与字段语义冲突的插值规则。

### 5.8 多来源和最近对象查询

“最近边界”查询必须返回：

- 使用的球面距离；
- 最近对象及距离；
- 容差内的并列对象；
- 最近点、boundaryId、segmentId 和弧长位置；
- 方向歧义和置信。

需要构造影响时，应查询贡献账本或资格场，不能把几何最近边界自动当成唯一成因。

### 5.9 稳定排序与分页

区域对象结果按稳定规则排序，例如：

```text
主排序：对象类型和规范空间键
次排序：稳定 objectId
```

分页游标绑定快照、查询规范摘要和排序版本。插入缓存、改变线程或加载顺序不能导致对象重复、遗漏或换页漂移。

### 5.10 查询结果包

```text
TectonicQueryResult
├─ snapshotId / queryDigest
├─ actualSpatialSupport / actualLevel
├─ values / objects / statistics
├─ valueStatus / confidence / errorEstimate
├─ coverage / unknownCoverage
├─ interpolationAndAggregationUsed
├─ sourceAndEvidenceRefs
├─ warnings / degradationReasons
└─ stablePageCursor
```

查询结果必须自描述，不能要求调用方猜测单位、层级或缺失语义。

### 5.11 D02 建议规则

```text
每次查询绑定唯一 tectonicSnapshotId，不隐式读取最新状态
点、区域、对象、路径和全局摘要共享同一球面查询协议
权威目标使用球面向量、多边形和稳定单元，不使用投影像素
区域统计按真实球面面积，并保存未知／失败覆盖率
多尺度策略明确区分精确层级、误差上限和最佳可用
查询只创建缓存，不静默生成或修改权威自然细节
插值、聚合和缺失处理服从 FieldDescriptor
最近对象查询保留并列、弧长、方向和置信，不等同唯一成因
分页绑定快照和查询摘要，排序与执行顺序无关
结果返回实际层级、误差、覆盖、状态、单位和证据引用
```

## 六、L6-D03：下游消费者视图与读取边界

公共契约不表示每个模块都应读取全部字段。L6 为下游提供按职责裁剪的只读视图，减少错误依赖，并让模块接口可独立测试。

### 6.1 视图是字段授权清单，不是数据副本

`ConsumerView` 保存：

```text
consumerViewId / version
requiredFieldIds
optionalFieldIds
allowedObjectTypes
allowedQueryKinds
minimumStatus / confidenceRequirements
supportedSpatialLevels
missingAndDegradationPolicy
forbiddenSemanticUses
```

视图引用同一公共字段，不为每个消费者复制数组。能力声明不匹配时，在启动计算前失败或协商降级，不能运行到中途才发现缺字段。

### 6.2 地形输入视图

`TerrainInputView` 可以读取：

- 球面空间、真实距离、面积和层级关系；
- 构造基底倾向与参考贡献；
- 抬升、沉降、冲突和限幅状态；
- 方向张量、结构一致性和可解析尺度；
- 来源板块、边界、分段和贡献账本引用；
- 字段状态、置信和误差。

它不能把参考贡献直接声明为最终高程，也不能读取内部修复数组来绕过公共资格。

### 6.3 材料输入视图

`MaterialInputView` 可以读取：

- 大陆性、厚度、浮力和过渡壳状态；
- 稳定核心、结构继承和相对成熟度；
- 边界子类型、形变资格和方向结构；
- 更新／热成熟代理及其无年代语义；
- 构造场状态、置信和来源。

它不能把大陆性直接翻译为单一岩石，不能把稳定核心直接命名为具体克拉通岩性，也不能回写壳体属性。

### 6.4 气候和水文的读取边界

气候与水文通常应读取后续生成的最终地形、海陆和材料状态，而不是用构造参考高程替代实际地表。L6 可向它们提供：

- 行星几何和稳定空间标识；
- 最终地形结果所引用的 tectonicSnapshotId；
- 用于解释和失效传播的构造来源索引；
- 明确标记为上游参考的字段。

在正式自然计算中：

- 气候不能从“汇聚资格”直接生成降水；
- 水文不能从“裂谷资格”直接生成河道或湖泊；
- 构造参考贡献不能绕过地形模块成为水流高程容器。

若未来某气候或地下水模型确需直接读取构造字段，应新增显式消费者契约和验证，而不是扩大默认权限。

### 6.5 查询与显示视图

`ExplorationQueryView` 可以读取广泛的公共对象、场、状态和证据索引，用于地图探索和“为什么”查询，但：

- 显示样式不参与自然结果；
- 高程夸张不回写参考贡献；
- 可见性过滤不改变区域统计；
- 泛化几何不得替代权威对象几何参与计算；
- 用户选择状态不进入快照身份。

### 6.6 验证与诊断视图

`ValidationDiagnosticView` 可以读取 A 层公共状态及 B 层证据，包括失败、修复摘要和固定测试报告。它只能报告、比较和定位问题，不得修改快照或成为普通世界生成的隐藏输入。

### 6.7 能力协商

消费者在运行前声明：

```text
支持的 publicContractVersion
需要的视图版本
必需／可选字段
支持的单位和状态语义
最低空间层级与误差
是否允许 CONDITIONAL 输入
```

L6 返回：兼容、可降级兼容或不兼容。降级必须列出缺失字段、实际精度和影响范围，不能静默删字段。

### 6.8 禁止语义升级

消费者不得：

- 把候选字段显示或保存为已证实对象；
- 把无量纲资格当作概率或米值；
- 把相对成熟度当作绝对年代；
- 把 UNKNOWN 当作零；
- 把参考高程贡献当作最终高程；
- 用显示泛化结果替代计算字段；
- 因输出不理想回写构造快照。

这些限制写入视图的 `forbiddenSemanticUses`，并进入消费者契约测试。

### 6.9 D03 建议规则

```text
消费者视图是同一公共字段上的只读授权和语义契约，不复制数据
每个视图声明必需／可选字段、对象、查询、状态、精度和降级策略
地形读取基底、响应、方向、状态和来源，但参考贡献不是最终高程
材料读取壳体和结构条件，但不能从大陆性直接指定具体岩性
气候与水文默认读取后续最终地形，不绕过地形模块消费构造高程
探索视图可广泛读取，但显示、夸张、过滤和选择不影响自然状态
诊断视图可以读取证据但只能报告，不能修复或参与生成
消费者运行前执行能力协商，降级明确列出影响
候选、资格、成熟度、未知和参考贡献禁止被语义升级
```

## 七、L6-D04：依赖图、失效范围、派生快照与禁止回写

L6 必须明确每个公共对象和字段依赖哪些上游状态。上游发生改变时，旧快照保持不可变，依赖图计算哪些结果过期、哪些仍可复用，以及下游派生快照需要重算到什么范围。

### 7.1 字段与对象级依赖图

建议使用有向无环依赖图：

```text
DependencyNode
├─ nodeId
├─ nodeKind：snapshot／objectType／field／derivedView
├─ inputNodeIds
├─ dependencyMode：必需／可选／条件
├─ spatialDependency：全局／区域／对象邻域／沿线
├─ invalidationRule
├─ compatibleVersionRange
└─ evidenceRef
```

依赖边来自正式公共契约，不从运行时“碰巧读取过哪些字段”推断。隐藏读取属于契约违规。

### 7.2 变化集

新上游快照与旧快照比较后产生：

```text
ChangeSet
├─ changedSnapshotIds
├─ changedFieldIds
├─ changedObjectIds / lineage
├─ changedSpatialRegions
├─ semanticOrUnitChanges
├─ confidenceOrStatusChanges
└─ modelVersionChanges
```

数值相同但语义、单位、状态或置信模式改变，也属于可能影响下游的变化，不能只比较浮点数组。

### 7.3 失效状态

下游派生结果相对某个新上游快照可以是：

```text
FRESH         依赖与当前上游完全匹配
STALE         依赖已变化，旧结果仍可只读查看但不能冒充当前结果
INCOMPATIBLE  契约或语义不兼容，不能继续读取
MISSING       尚未生成所需派生结果
```

旧结果不会被删除或原地改写。界面可以显示旧结果，但必须标出其父构造快照和失效状态。

### 7.4 空间失效范围

依赖规则可以把变化限制到：

- 指定球面区域；
- 某 plateId 及其邻接边界；
- 某 boundaryId／segmentId 的影响范围；
- 某字段全部空间；
- 整个世界。

例如显示颜色变化不产生自然失效；某条边界核参数变化可能只使对应贡献和下游区域过期；WorldSpec 的行星半径变化通常使真实距离相关结果全局失效。

空间失效范围必须保守覆盖真实依赖。宁可扩大重算范围，也不能遗漏受影响区域而产生混合版本结果。

### 7.5 派生快照关系

下游结果保存：

```text
derivedSnapshotId
parentTectonicSnapshotId
consumerModelVersion
consumerContractVersion
inputFieldDigest
spatialCoverage
completionAndValidationStatus
```

同一构造快照可以拥有多个地形或材料派生分支。不同消费者结果不能写回 `TectonicSnapshot`，也不能共享可写字段。

### 7.6 禁止回写

禁止：

- 地形模块为获得更好山脉修改构造抬升资格；
- 材料模块把生成的岩性写回 crust.continentality；
- 气候或水文根据结果修改板块边界；
- 显示层为平滑接缝改变权威几何；
- 验证模块为通过测试修正字段值。

如果未来加入真实双向反馈，应由编排器显式创建新的世界迭代：

```text
旧构造快照 + 下游反馈候选
→ 受版本化耦合模型验证
→ 新上游规格／新构造快照
```

这不是下游原地回写。

### 7.7 对象谱系与局部复用

上游模型升级后，通过对象谱系判断：

- 延续对象可否复用下游局部结果；
- 拆分对象的旧结果如何标记为多个候选映射；
- 合并对象的来源如何保留；
- 消失对象关联的下游结果如何失效；
- 新对象需要生成哪些下游内容。

谱系只是复用依据之一。字段语义、空间位置或模型版本不兼容时，即使 objectId 有延续关系也不能盲目复用。

### 7.8 依赖查询

L6 应支持：

- 某字段变化会使哪些消费者结果过期？
- 某个地形单元依赖哪些构造字段和对象？
- 为什么该派生快照是 STALE？
- 哪些区域需要重算？
- 某次升级能否复用对象或缓存？
- 哪条隐藏依赖导致契约测试失败？

### 7.9 D04 建议规则

```text
依赖图以正式字段／对象节点和声明式依赖边构成，不从偶然读取推断
变化集同时比较数值、对象、空间、语义、单位、状态和模型版本
FRESH、STALE、INCOMPATIBLE 和 MISSING 分开
旧快照保持只读，失效只改变它相对新上游的使用状态
空间失效范围按区域、对象、边界影响域或全局保守计算
每个下游派生快照保存父构造快照、输入摘要和消费者版本
下游、显示和验证禁止原地回写构造权威状态
未来双向反馈只能通过显式耦合模型生成新世界快照
对象谱系支持局部复用，但不能绕过语义和版本兼容检查
```

## 八、L6-D05：版本兼容、序列化与非破坏升级

L6 需要把“文件能否读”“字段能否理解”“结果是否相同”分开判断。仅使用一个版本号无法安全表达这些差异。

### 8.1 分离的版本维度

至少保存：

```text
storageFormatVersion
publicContractVersion
unitAndDatumSchemaVersion
objectSchemaVersion
modelManifestDigest
resultSemanticsVersion
consumerViewVersions
evidenceSchemaVersion
cacheVersion
```

缓存版本变化通常不影响结果；模型清单或结果语义变化通常需要新快照；公共契约新增可选字段不一定破坏旧消费者。

### 8.2 兼容性结论

建议分别报告：

| 结论 | 含义 |
| --- | --- |
| `STORAGE_READABLE` | 当前实现能够解析存储容器 |
| `CONTRACT_COMPATIBLE` | 所需字段和语义可被消费者理解 |
| `QUERY_COMPATIBLE` | 请求的查询类型、层级和状态可执行 |
| `RESULT_EQUIVALENT` | 按声明范围，结果语义与数值满足等价标准 |
| `REPRODUCIBLE_BY_ORIGINAL_MODEL` | 可使用原模型版本重新生成 |
| `INCOMPATIBLE` | 至少一个必要维度不满足 |

文件可读不表示结果等价，查询可运行也不表示新旧模型产生相同世界。

### 8.3 快照包和清单

概念上的存储包包括：

```text
manifest
├─ 快照头、版本、依赖和规范摘要
├─ 必需／可选数据块目录
├─ 内容哈希、长度、压缩和校验信息
├─ 空间覆盖与层级目录
├─ 对象及字段索引
└─ 证据与缓存目录

content-addressed chunks
├─ 权威对象／字段块
├─ 多尺度补丁
├─ 诊断证据块
└─ 可选缓存块
```

具体文件容器、数据库或压缩算法留待工程选型。压缩方式和块布局不参与自然结果身份。

### 8.4 规范序列化

为跨平台摘要和回归，必须规定：

- 数字单位、字节序和特殊浮点值策略；
- 字段及对象稳定排序；
- Unicode 和字符串规范化；
- 可选字段缺失与显式空值的区别；
- 张量、向量和球面坐标的规范表达；
- 量化摘要与权威精度的关系；
- 哈希覆盖哪些内容。

内部高性能布局可以不同，但规范摘要输入必须一致。

### 8.5 懒加载和局部读取

存储包支持按字段、对象、空间块和层级加载：

- 清单和契约描述先加载；
- 消费者只加载视图需要的必需块；
- 区域查询按球面覆盖读取数据块；
- 缺失可选缓存回退到权威查询；
- 缺失必需权威块立即失败；
- 懒加载顺序不改变查询结果。

### 8.6 升级分类

升级分为：

1. **存储迁移**：仅改变容器或压缩，权威语义和规范摘要不变。
2. **契约适配**：通过无损重命名、单位换算或默认可选字段提供兼容视图。
3. **结果语义升级**：模型、门槛或字段含义改变，必须创建新快照分支。
4. **无法升级**：缺少原始信息，保留旧快照只读或要求重新生成。

只有可证明语义等价的适配可以透明执行。不能用默认值伪造旧快照从未计算过的字段。

### 8.7 未知字段和前后兼容

- 旧消费者可以忽略明确标记为可选的新字段；
- 遇到未知必需字段必须拒绝；
- 新消费者读取旧快照时，通过能力协商判断缺失字段；
- 枚举新增值不能被旧消费者自动映射到最接近旧值；
- deprecated 字段保留替代关系和移除版本，不静默改义。

### 8.8 非破坏升级和谱系

升级结果保存：

```text
newSnapshotId
sourceSnapshotId
upgradeKind
adapterOrModelVersion
objectAndFieldLineage
compatibilityReport
validationReport
```

旧快照仍可按原模型读取。升级失败不破坏原包，也不能把部分迁移结果覆盖成正式快照。

### 8.9 完整性与恢复

- 数据块有内容哈希和长度校验；
- 清单原子提交；
- 可重建缓存损坏时删除重建；
- 权威块损坏时快照失败，不能用缓存代替；
- 局部下载／复制缺块时明确报告覆盖不足；
- 恢复操作保存审计记录，不改变自然身份。

### 8.10 D05 建议规则

```text
存储、公共契约、单位、对象、模型结果、消费者、证据和缓存分别版本化
文件可读、契约兼容、查询兼容、结果等价和原模型可重现分别报告
快照包使用清单、内容寻址数据块、空间目录和完整性校验
规范序列化规定单位、排序、字符串、浮点、向量和哈希范围
支持字段／对象／区域／层级懒加载，加载顺序不改变结果
存储迁移、契约适配和结果语义升级使用不同流程
只有语义等价适配可透明执行，结果变化必须创建新分支
未知必需字段拒绝，未知可选字段可跳过但不得改义
旧快照永久只读保留，升级保存来源、谱系和兼容报告
权威块损坏阻断快照，缓存不能替代权威状态
```

## 九、L6-D06：结构化证据、解释查询与诊断包

L6 需要回答“这里为什么是这种构造状态”“为什么没有出现某种资格”“升级后什么改变了”。权威解释应是可验证的结构化证据图，自然语言只是根据证据图生成的显示结果。

### 9.1 证据图

建议：

```text
EvidenceGraph
├─ EvidenceNode
│  ├─ nodeId
│  ├─ nodeKind：value／object／rule／threshold／test／failure／decision
│  ├─ sourceSnapshotId
│  ├─ structuredPayload
│  ├─ status / confidence / error
│  └─ modelVersion
└─ EvidenceEdge
   ├─ inputTo
   ├─ derivedFrom
   ├─ constrainedBy
   ├─ rejectedBecause
   ├─ validatedBy
   └─ supersededBy
```

一项公共值至少能沿图追溯到上游字段、对象、规则、门槛和验证结果。

### 9.2 典型解释链

例如某位置的抬升资格：

```text
tectonicConstraint.upliftQualification
← L5 汇聚响应贡献与空间核
← L4 convergenceSegment / collisionQualification
← L4 法向相对速度与壳体双侧取样
← L3 plateId、boundaryId、壳体与欧拉运动
← L2 WorldSpec、模型清单和命名随机来源
← L1 球面位置与距离
```

解释链不能跳过不确定环节。若极性未知，不能生成“因为某板块正在俯冲到另一板块下方”的确定陈述。

### 9.3 解释查询类型

首版支持：

```text
WHY_VALUE
  为什么该位置／对象具有当前值？

WHY_STATUS
  为什么结果是 UNKNOWN、CLAMPED、CONDITIONAL 或 FAILED？

WHY_NOT
  为什么没有形成某项资格或对象候选？

SOURCE_BREAKDOWN
  哪些来源贡献了多少，是否冲突？

DEPENDENCY_IMPACT
  某字段变化会使什么失效？

COMPARE_SNAPSHOTS
  两个快照在字段、对象、模型和证据上为何不同？

VALIDATION_TRACE
  哪些测试通过、失败、未运行或不适用？
```

`WHY_NOT` 只能基于已声明的必要条件、门槛和拒绝原因回答，不能声称证明所有可能成因都不存在。

### 9.4 结构化原因优先

每个解释结论至少包含：

- 稳定 reasonCode；
- 相关 fieldId／objectId；
- 实际值、门槛、单位和状态；
- 空间位置／范围和分辨率；
- 置信与误差；
- 来源快照和模型版本；
- 支持、反对或缺失证据；
- 禁止解释和模型边界。

中文或其他语言的说明由这些结构化字段生成。文字模板变化不改变证据身份和自然结果。

### 9.5 三个证据详细度

| 级别 | 内容 | 用途 |
| --- | --- | --- |
| 摘要 | 主因、状态、主要来源、置信和模型边界 | 地图点击与普通探索 |
| 标准 | 分项贡献、关键门槛、依赖路径、相关验证 | 设计分析和问题定位 |
| 完整 | 候选尝试摘要、修复、数值统计、测试明细和失败复现 | 开发与科学审计 |

详细度只改变加载内容，不改变结论。摘要不能通过省略不确定性使结论显得更确定。

### 9.6 最低必须保留的证据

正式快照至少永久保留：

- 上游快照和模型清单；
- 公共字段来源及派生版本；
- 对象身份、拓扑和谱系；
- 组合、限幅、状态与置信原因；
- 适用固定测试和验证结论；
- 阻断失败的稳定代码和最小复现输入；
- 规范摘要和契约兼容报告。

逐次求解器数组、全部随机拒绝几何和性能跟踪可按保留策略裁剪，但保留足以解释最终接受／拒绝决定的摘要。

### 9.7 分块和按需加载

证据按快照、空间区域、对象、字段和测试分块：

- 普通探索只加载摘要；
- 点击对象加载相关标准证据；
- 诊断工具按需加载完整块；
- 缺失可选完整块应标记“详细证据未保留”，不能假装不存在失败；
- 必需证据块缺失使快照验证失败。

### 9.8 访问边界

- 普通消费者可以查询公共值的摘要来源，但不能读取内部临时数组；
- 探索视图可以读取对象级标准证据；
- 验证诊断视图可以读取完整证据包；
- 自然模型不能把 B 层证据作为隐藏输入；
- 导出时明确选择包含摘要、标准或完整证据，且记录导出级别。

这些边界用于控制语义耦合和数据体积，不改变本地用户对自己世界的读取权。

### 9.9 快照比较

比较两个快照时，先比较：

```text
WorldSpec 和模型清单
公共契约和单位
对象谱系
字段变化集
空间影响范围
状态、置信和验证变化
```

再生成“变化原因”。不能只比较渲染图片或浮点差值。对象拆分／合并通过谱系展示，模型语义改变时明确标为不可直接数值比较。

### 9.10 解释的确定性

相同快照、查询规范和证据级别应得到相同结构化解释图。自然语言措辞可以随界面语言或模板版本改变，但 reasonCode、来源、数值和结论状态保持一致。

### 9.11 D06 建议规则

```text
结构化证据图是权威解释，自然语言是可替换显示
公共值可追溯到来源字段、对象、规则、门槛、模型和验证
支持 WHY_VALUE、WHY_STATUS、WHY_NOT、来源、依赖、比较和验证查询
WHY_NOT 只依据已声明必要条件，不能证明所有未建模成因不存在
解释包含稳定原因码、数值、单位、空间、置信、版本和模型边界
摘要、标准和完整三级只影响加载量，不改变结论及不确定性
正式快照保留来源、谱系、组合、验证、失败复现和规范摘要等最低证据
大体积调试数据可裁剪，但最终决定摘要必须保留
证据按区域、对象、字段和测试分块按需加载
消费者、探索和诊断视图具有不同证据访问范围，B 层不成为隐藏自然输入
快照比较先对齐规格、版本、谱系和语义，再比较数值
```

## 十、L6-D07：统一构造快照、消费者测试与发布门槛

L6 最终发布 `TectonicSnapshot`。它是构造子引擎对整体自然引擎的唯一正式入口，绑定 L1–L5 权威快照、公共契约、消费者视图、依赖图、证据索引和兼容报告。

### 10.1 最终快照结构

```text
TectonicSnapshot
├─ TectonicSnapshotHeader
├─ PublicObjectCatalog
├─ PublicFieldCatalog
├─ ConsumerViewCatalog
├─ SpatialQueryContract
├─ DependencyGraph / ChangeAndLineageIndex
├─ EvidenceIndex
├─ CompatibilityReport
├─ ValidationAndPublicationReport
└─ RebuildableCacheManifest
```

L6 不复制 L1–L5 的全部权威数组；它通过不可变引用、公共描述符和必要物化视图组成统一快照。

### 10.2 发布状态

```text
generationStatus = COMPLETE / PARTIAL / FAILED
validationStatus = NOT_RUN / PASSED / CONDITIONAL / FAILED
publicationStatus = DRAFT / DIAGNOSTIC_ONLY / RELEASED / SUPERSEDED
```

- `RELEASED` 必须是 `COMPLETE + PASSED`。
- `DIAGNOSTIC_ONLY` 可以保存失败或条件输入，但消费者默认拒绝。
- `SUPERSEDED` 表示已有推荐的新分支，旧快照仍保持可读和身份不变。
- `DRAFT` 不能被普通下游发现为正式输入。

### 10.3 公共契约结构检查

发布前检查：

- 所有必需对象和字段存在；
- objectId、fieldId、snapshotId 引用闭合；
- 字段描述符完整且命名唯一；
- 单位、基准、状态、置信、聚合和缺失语义合法；
- 消费者视图只引用存在的公共字段；
- 依赖图无未声明循环和隐藏输入；
- 必需证据和兼容报告存在；
- 缓存未被误标为权威数据。

### 10.4 消费者契约测试

每个消费者视图运行独立测试：

**TerrainInputView**

- 能读取所需空间、基底、响应、方向、状态和来源；
- 无法写入权威缓冲；
- 不把参考贡献自动称为最终高程；
- 缺失必需字段时在运行前失败。

**MaterialInputView**

- 能读取壳体、结构和构造条件；
- 不提供“大陆性直接等于某岩性”的快捷字段；
- 相对成熟代理保留无年代语义。

**ExplorationQueryView**

- 点、区域、对象、路径和解释查询一致；
- 显示设置不影响统计和证据；
- 可见泛化与权威几何明确区分。

**ValidationDiagnosticView**

- 能读取完整验证和失败证据；
- 无法修改状态或向生成器注入测试答案。

### 10.5 K01–K04 的 L6 封装测试

L6 不重新判断构造科学结果，而是对已经通过的 K01–K04 快照检查：

- 公共对象和字段能够完整表达预期关系；
- 点、区域、对象和解释查询给出一致结果；
- 消费者视图能读取各自需要的字段；
- UNKNOWN、极性、冲突、限幅和置信没有在封装中丢失；
- 序列化、懒加载和缓存重建不改变结果；
- TestOracle 不进入普通消费者视图。

### 10.6 T01–T06 的上游就绪检查

L6 只检查未来 T01–T06 所需构造上游是否可用，例如稳定空间标识、构造基底、方向约束、材料前提来源和证据索引。它不在此层验证降水、河流、湖泊、溶洞或侵蚀结果。

就绪报告分为：

```text
AVAILABLE
AVAILABLE_WITH_LIMITS
MISSING
INCOMPATIBLE
```

### 10.7 一致性与关系测试

- 同一字段经不同合法视图和查询路径得到相同值与状态；
- 全量加载、懒加载、缓存重建和序列化往返结果一致；
- 整体旋转后空间查询和方向字段等价变换；
- 地图投影、显示夸张、语言和证据文字模板不改变公共摘要；
- 创建下游快照不改变父构造快照；
- 上游变化后失效范围和消费者状态正确更新；
- 旧契约适配与新结果分支遵守兼容报告。

### 10.8 失败代码

```text
L6_MISSING_UPSTREAM_SNAPSHOT
L6_UNRELEASED_UPSTREAM
L6_PUBLIC_FIELD_DESCRIPTOR_INVALID
L6_OBJECT_REFERENCE_BROKEN
L6_DUPLICATE_PUBLIC_SEMANTIC

L6_CANONICAL_DIGEST_MISMATCH
L6_NONDETERMINISTIC_QUERY

```

失败记录保存快照、字段／对象、消费者、查询摘要、兼容维度、实际值、门槛和最小复现输入。

### 10.9 验证顺序

```text
1. L1–L5 上游状态、身份和模型清单检查
2. 公共对象／字段契约与引用闭合
3. 三层数据、只读和缓存透明性
4. 空间、多尺度、分页和查询一致性
5. 消费者视图与禁止语义使用测试
6. 依赖图、变化集、失效和派生父链
7. 序列化、懒加载、升级和完整性
8. 证据图、解释和快照比较
9. K01–K04 封装与 T01–T06 就绪检查
10. 确定性、跨平台摘要和原子发布
```

### 10.10 正式发布门槛

```text
L1–L5 输入均为 COMPLETE + PASSED 且契约匹配
L6 generationStatus = COMPLETE
L6 validationStatus = PASSED
所有适用 P0，以及 L6-O01 至 O80 中的适用硬约束通过
所有消费者必需字段和视图测试通过
依赖图、谱系、证据和兼容报告完整
序列化往返、懒加载、缓存重建和规范摘要一致
K01–K04 封装测试通过
不存在隐藏依赖、语义升级、UNKNOWN 填零或回写路径
publicationStatus 原子切换为 RELEASED
```

### 10.11 D07 建议规则

```text
TectonicSnapshot 是整体自然引擎读取构造结果的唯一正式入口
发布状态与生成／验证状态分开，只有 COMPLETE + PASSED 才能 RELEASED
公共对象、字段、视图、依赖、证据和兼容信息必须引用闭合
每个消费者运行独立契约和禁止语义使用测试
L6 对 K01–K04 验证封装保真，不重新计算科学 Oracle
对 T01–T06 只检查构造上游就绪，不提前验证自然过程结果
全量／懒加载／缓存／序列化／视图查询必须一致
失败使用稳定代码并保存消费者、查询和最小复现输入
隐藏依赖、回写路径、UNKNOWN 填零和语义升级均阻断发布
发布通过原子状态切换，旧快照保持只读并可被新分支取代
```
