# 引擎重设计蓝图

> **文档状态**
>
> - 文档类型：总体架构
> - 决策状态：部分确认
> - 实现状态：未实现
> - 版本：0.1
> - 说明：总体方向与不可变快照原则已确认；下游子引擎仍按阶段讨论。

本文重新定义类地行星地形引擎的架构。目标不是继续向早期网页原型累加随机规则，而是建立一套可重复、可追溯、可局部重算、可被固定测试世界验证的自然状态生成系统。

关联：[自然系统耦合与模型边界](自然系统耦合与模型边界.md) · [第一版验收标准](../验收体系/第一版验收标准（讨论稿）.md) · [测试世界矩阵与验收顺序](../验收体系/测试世界矩阵与验收顺序（讨论稿）.md)。

## 一、重新设计的原因

早期最小原型能从种子生成海陆、高程、板块候选与下坡河流候选，并以二维图和球体显示。它适合验证“世界能否被直观看见”，但不适合作为正式引擎基础，原因是：

- 高程、板块、河流和显示结果直接耦合，无法保存某条河、湖泊或特殊地貌的完整依据。
- 河流只沿地势下降追踪，未连接降水、融雪、蒸发、地下水、分流、湖泊与沉积物账本。
- 各种地貌没有统一的对象状态和降级机制，难以区分已计算结果、条件候选与展示性表达。
- 缺少依赖图与失效范围；改变材料、海平面或气候后，无法可靠地判断哪些结果必须重算。
- 固定测试世界只能作为外部说明，不能成为引擎内建的可执行验收对象。

因此，重新设计的核心不是替换一种噪声函数，而是把“随机地形图”转为“由自然状态图驱动的可解释世界”。

## 二、设计目标与非目标

### 目标

1. **确定性**：同一世界种子、背景预设、偏好、模型版本与测试配置，生成相同的世界状态。
2. **因果顺序**：先生成容器和边界，再计算环境条件与水量，最后生成地貌对象和显示标签。
3. **守恒与前提**：水、雪、地下储量、沉积物等可追踪量保留账本；对象必须具有明确的地形、材料、连通或过程前提。
4. **可解释性**：任一对象能说明来源、输入、满足条件、缺少条件、使用的模型状态和适用边界。
5. **跨尺度一致**：全球、区域、地貌级共享稳定标识与边界；局部细化不改变未被授权修改的全球骨架。
6. **渐进实现**：每个模块能以明确状态接入，未实现的过程不会伪装成已计算事实。
7. **可验收性**：T01–T06 是正式的引擎输入包与验收契约，而不仅是文档案例。

### 非目标

- 首版不求解完整板块动力学、全球大气环流、三维海洋、完整地下水、百万年地貌演化或洞穴内部几何。
- 首版不追求对现实某个地区的精确复刻、绝对年代或参数标定。
- 展示层不拥有自然规则；地图颜色、三维网格和命名不能反向修改世界状态。

## 三、总体架构

```text
世界请求（种子 + 固定类地预设 + 高级偏好）
                │
                ▼
       世界规格与可重现性记录
                │
                ▼
        ┌──── 自然状态引擎 ────┐
        │  1. 行星与构造骨架  │
        │  2. 地形与材料容器  │
        │  3. 气候条件场      │
        │  4. 水文状态与账本  │
        │  5. 地貌对象与分类  │
        │  6. 证据与验收      │
        └────────┬───────────┘
                 │ 不可变世界快照
        ┌────────┴───────────┐
        ▼                    ▼
  查询／解释接口        地图与局部三维适配器
        │                    │
        └──── 桌面应用与导出层 ────┘
```

引擎核心不依赖桌面界面、渲染框架或文件格式。桌面应用只负责创建世界、保存快照、切换季节、查看图层、查询对象与呈现局部三维。

## 四、核心原则：不可变世界快照与依赖图

每次生成或重算产出一个不可变的 `世界快照`。快照由以下身份共同确定：

```text
世界标识 = 世界种子
        + 类地背景预设版本
        + 高级偏好
        + 启用模块集合
        + 模型版本集合
        + 测试世界配置（若有）
```

快照内部记录模块依赖图。例如：

```text
构造骨架 → 高程／海陆 → 流域边界 ─┐
材料区   ───────────────────────────┼→ 地貌对象与分类 → 显示层
高程／海陆 → 气候条件场 → 水文账本 ─┘
```

修改输入时，依赖图决定失效范围：

- 修改地图配色、标签密度或三维网格精度：只重绘显示层。
- 修改季节状态：重算季节性雪、水量、湖岸、湿地与覆盖状态，不改稳定构造、主地形和材料边界。
- 修改气候背景或海平面：重算气候、水文及其派生分类；海平面变化还会影响海陆、海岸和流域出口。
- 修改材料区：重算渗透、地下水、侵蚀／沉积资格和材料相关地貌，不重新随机生成板块。
- 修改构造或高程骨架：使所有下游状态失效并重新建立快照。

## 五、统一空间与对象模型

### 5.1 空间层

首版采用分层球面单元体系，而不是一张永远固定分辨率的噪声贴图：

| 层级 | 作用 | 必须稳定保存的内容 |
| --- | --- | --- |
| 全球层 | 海陆、构造区、主气候带、主流域与海洋边界 | 球面单元标识、板块、海平面、主流域编号 |
| 区域层 | 山脉、盆地、河谷、湖泊、材料区与区域气候 | 父级映射、分水岭、出口、材料边界、对象候选区 |
| 地貌层 | 河曲、瀑布、峡谷、湿地、崖壁、泉眼等可观察对象 | 对象几何、连接、状态、条件和证据索引 |
| 局部三维预留层 | 只在需要查看时细化地表网格 | 固定区域标识、采样规则、相对高程与材料属性 |

具体单元可选用等面积球面网格、四叉球面网格或其他实现，但必须满足邻接关系稳定、跨尺度映射明确、极区无特殊破损和局部细化可追溯。算法选择不应先于这些约束。

### 5.2 对象层

世界由连续场和离散对象共同构成：

- **连续场**：高程、坡度、温度、降水、蒸发需求、雪水、地表水量、地下储量、沉积潜势等。
- **区域对象**：板块、构造带、流域、湖盆、材料区、气候区、湿地候选区、海岸段。
- **线性对象**：河流、分流、暗河候选、山脊、断崖边缘、海岸线。
- **点／局部对象**：泉水、瀑布、洞口、天坑、峰顶、山巅、岛屿候选。

每个对象统一保存：

```text
对象标识 · 类型 · 空间范围 · 稳定父级
连接关系 · 当前状态 · 生成证据 · 依赖版本
代表季节状态 · 分类名称 · 降级原因（若有）
```

对象状态统一使用：`已计算`、`受约束生成`、`候选`、`泛化表达`、`不生成`。显示层必须原样保留该状态。

## 六、模块边界与数据契约

### 6.1 行星与构造骨架模块

**输入**：世界种子、类地预设、板块偏好。

**输出**：球面网格、板块区域、边界类型候选、初始大陆／洋盆倾向、稳定随机流。

**边界**：首版输出的是构造约束和地形初始条件，不声称求解真实地幔对流或板块历史。

### 6.2 地形与材料容器模块

**输入**：构造骨架、海平面、材料偏好与稳定随机流。

**输出**：高程、坡度、曲率、盆地、分水岭、海岸、材料区、表层覆盖与候选地形连接。

**职责**：提供水和沉积物的容器、势能路径与岩性前提；不能依据后续景观名称反向修改高程。

### 6.3 气候条件模块

**输入**：纬度、海陆、地形、代表季节、固定类地背景。

**输出**：温度、降水、水汽可用量、蒸发需求、雨雪分配、融雪候选等连续场。

**边界**：首版可采用受约束的水汽输送与地形抬升近似；降水必须受水汽来源限制，不能作为独立噪声层。

### 6.4 水文状态模块

**输入**：地形容器、气候条件、材料的入渗／储水属性、上游与海洋边界、代表季节。

**输出**：地表径流、积雪、融雪、土壤／地下储量、河网、分流比例、湖泊水位、湿地水文周期、出海水量账本。

**硬规则**：所有节点必须平衡输入、输出、损失和储量变化；分流、汇合、湖泊、湿地、地下水和入海口不得重复使用同一份水。

### 6.5 地貌过程与分类模块

**输入**：地形、材料、气候、水文、对象连接与模型启用状态。

**输出**：河谷、瀑布、河曲、峡谷、湖泊、湿地、三角洲、岩溶、崖壁、残丘等对象，以及它们的状态、条件和证据。

**职责**：判断某类对象是否有资格出现，并在条件不完整时降级。它不直接制造水量、高程或岩性。

### 6.6 证据、验证与查询模块

**输入**：所有模块的快照、账本、依赖图和测试配置。

**输出**：对象解释、固定测试世界验收结果、方向性变体比较、失败定位和可重现性记录。

**职责**：将 T01–T06 转为首类输入包，并输出通过、条件通过、不通过或未验证结论。

## 七、生成与重算流程

```text
1. 固化世界规格与随机流
2. 建立全球球面网格和构造骨架
3. 生成海陆、高程、分水岭、材料与表层容器
4. 对每个代表季节计算气候条件场
5. 对每个代表季节执行水文收支与水系连接
6. 从连续场提取地貌对象并判定其状态
7. 建立对象证据、依赖图与验收结果
8. 冻结世界快照，交由地图和三维适配器显示
```

步骤 4–6 可以在规定的迭代边界内重复：例如气候输入改变雪水与水文，水文结果改变湿地范围；但首版不允许显示层或景观命名触发反向重塑地形。每个迭代必须保存停止理由、容差和未收敛状态。

## 八、随机性设计

不使用一个全局随机数序列贯穿全部模块。世界规格生成稳定的命名随机流：

```text
world/plates
world/elevation
world/materials
season/S1/climate
season/S1/hydrology
region/{稳定区域标识}/geomorphology
```

这样可以保证：

- 局部按需细化不会因访问顺序改变其他区域。
- 添加新的显示图层不会改变旧世界的板块、高程或河网。
- 变体测试能只改变声明的输入，不会意外消费其他模块的随机数。
- 对象证据可精确指出自己的随机来源与模型版本。

## 九、桌面应用与引擎的边界

桌面应用应通过引擎公开接口工作：

| 用户动作 | 引擎动作 | 显示层动作 |
| --- | --- | --- |
| 输入种子并生成 | 创建世界规格与基础快照 | 展示生成进度、全球图和球体 |
| 切换代表季节 | 请求对应季节状态或其缓存 | 更新雪、水、湖岸、湿地和覆盖图层 |
| 调整高级偏好 | 生成新的世界规格或分支快照 | 对比差异，保留原世界不变 |
| 点击对象 | 查询对象、账本、连接和证据 | 显示“为什么在这里”与模型边界 |
| 放大局部区域 | 请求稳定区域的细化快照 | 生成局部三维网格与观察界面 |
| 运行 T01–T06 | 载入固定测试配置并执行验收 | 展示规则、证据和失败位置 |

桌面应用不得直接编辑快照内部数组或为了视觉效果写入河流、湖泊、山脉和景观标签。

## 十一、建议实施切片

新设计不应一次完成全部模块。建议按可演示、可验收的垂直切片推进：

1. **切片 A：世界快照与地形容器**：世界规格、稳定随机流、球面空间层、高程、海陆、材料、分水岭、基础证据与二维／球面显示。
2. **切片 B：T01 水文闭环**：气候最低字段、雨雪、雪水、融雪、地表径流、湖泊账本与对象查询。
3. **切片 C：T02 与 T03**：雨影、蒸发需求、内流盆地、多路径河网、湿地与分流守恒。
4. **切片 D：T04**：简化沉积账本、海洋边界、河口和三角洲降级规则。
5. **切片 E：T05 与 T06**：地下连接、岩溶资格、材料差异、特殊地貌候选与局部三维细化。

每个切片先让对应固定测试世界得到可审查结论，再扩大到随机世界；不以视觉丰富度替代契约通过。

## 十二、现有原型的处置

早期网页原型已删除。它曾用于验证全球图、球面观察和种子可重复性，相关经验仅作为历史输入，不承担正式引擎职责。

在切片 A 完成前，不应继续把气候、水文、地下水或特殊地貌规则直接写入该页面。新的引擎核心应先以独立数据模型和测试接口实现，再由该页面或未来桌面应用接入。

## 十三、需要共同确认的架构决定

以下事项影响具体实现，但不影响本蓝图的总体方向：

1. 首版球面空间单元采用何种具体网格与局部细化方案。
2. 引擎核心的具体语言、运行时、数据序列化格式和桌面框架。
3. “固定类地背景”中的定量参数范围及哪些高级偏好可开放。
4. 气候、水文、地下水、沉积物与侵蚀近似模型的具体公式、时间步长和收敛容差。
5. 何时将局部三维从显示预留提升为正式验收范围。

本蓝图先冻结职责、数据流、模型边界和验收路径；具体算法与代码必须在对应切片开始前另行设计和确认。
