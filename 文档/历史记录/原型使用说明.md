# 类地行星地形引擎

## 当前主线：随机地形与全球水文

现已新增独立 `worldgen`，从种子生成球面板块、海陆、高程与山带。

```sh
python3 -m worldgen --seed 20260923
```

打开随机地形查看器（原型文件已清理），或查看生成的地形图（原型文件已清理）。支持图层切换、缩放和位置数据查看。详细用法与科学边界见[第一版随机地形记录](随机地形原型记录.md)。这是地质启发式原型，尚非完整板块演化和物理仿真。

## 基于现有世界增加水文

```sh
python3 -m worldgen.hydrology --world artifacts/world/world.json --out artifacts/world
```

球体新增水文图层、河网与参考湖面，详见[全球水文 v0.1](全球水文参考态记录.md)。当前为有效径流 300 mm/年、湖盆预先满蓄的稳态情景，尚未模拟实际降水和从干地蓄水的时间过程。

## 有限水量与时间演化

```sh
python3 -m worldgen.evolution --world artifacts/world/world.json --out artifacts/world
```

当前示例从干地开始，先供水 60 步，再停止供水并继续蒸发 60 步。查看器支持时间滑条与回放，显示湖泊蓄水、退水及分离。详细参数、收支和近似见[有限水量演化记录](有限水量与湖泊演化记录.md)。演化图层暂不显示动态河段流量，上一版满蓄河网保留为参考数据。

## 已有局部水文原型

当前实现：Python 标准库原型，包含土壤桶、河段储水、湖泊门槛出口、有限地下水交换、交换账本、命令行、检查点与离线报告。

这是公式与水量闭环的第一轮工程验证，不是完整行星生成器；未进行真实流域标定或独立观测验证。最终引擎语言与桌面框架仍未选定。

## 快速运行

需要 Python 3.11 或更新版本；直接运行无需安装第三方依赖。在本目录执行：

```sh
python3 -m hydro run --scenario examples/b14.json --steps 1 --out artifacts/b14
python3 -m hydro run --scenario examples/coupled.json --steps 288 --out artifacts/coupled
python3 -m hydro benchmark --out artifacts/benchmarks --allow-partial
python3 -m unittest discover -s tests -v
```

Windows 将 `python3` 替换为 `py -3` 或本机的 `python`。这些是跨平台命令写法，不代表已在 Windows 上运行通过。

- B14 一步闭环示例（原型文件已清理）：土壤、地下补给、河段和闭口湖；预期最终储水 110 m³。
- 耦合示例（原型文件已清理）：一天的恒定降水、土壤补给、河道、湖泊出口与地下水交换，每步 300 秒。参数为合成演示值。
- B14 运行报告（原型文件已清理）。
- 一天耦合运行报告（原型文件已清理）。
- B01–B18 基准报告（原型文件已清理）。

`--steps` 是新执行步数。未指定时为 1；示例雨量均为持续速率，运行多步会持续降雨，不是自动停止的单次暴雨。

## 结果与当前证据

本机已执行的结果见 [实现验证记录](独立水文原型验证记录.md)。基准命令包含 18 组实验：17 组可在本机完成；B17 包含 Windows/macOS 一致性，缺双平台证据时必须为 BLOCKED。

`benchmark` 默认在有 BLOCKED 且无 FAIL 时退出 2；`--allow-partial` 仅允许这种部分验证以退出 0 结束，报告仍保留 BLOCKED。任何 FAIL 都退出 1。此选项不能绕过计算失败。

每次运行输出：

| 文件 | 内容 |
| --- | --- |
| report.html | 可离线打开的水量表、储量、水位和每步平均出流图 |
| states.csv | 含初始状态的逐步储量、水位及累计残差 |
| ledger.csv | 每笔内部／外部交换，体积均为 m³ |
| summary.json | 累计收支、步数和权威数据摘要 |
| scenario.json | 展开默认值并排序后的生效配置 |
| checkpoint.json | 状态、账本、历史、配置及校验值 |

曲线连接的是计算样点，不表示已求解样点之间的完整水动力；流量图为步平均流量。HTML 不加载外部脚本或网络资源。

## 从高度网格生成排水

```sh
python3 -m hydro terrain --input examples/terrain.json --steps 24 --out artifacts/terrain
```

输入是规则局部网格的高程矩阵、格子宽高、明确指定的边界出口、雨量速率和时间步。自动计算四邻接排水、平坦区流向、汇流面积、流域归属、无出口洼地，并转换为已有水文模型的配置。

查看地形与排水地图（原型文件已清理）及水量报告（原型文件已清理）。示例有 35 个格子、两个流域终点；一天雨量为 168 m³，其中约 91.2 m³ 留在洼地，76.8 m³ 经出口流出。

输入字段：

| 字段 | 含义 |
| --- | --- |
| elevation_m | 矩形二维高程矩阵，行列从 0 开始，不接受空洞或 NaN |
| cell_width_m / cell_height_m | 局部平面格子尺寸，影响面积及坡降计算 |
| outlets | 明确允许离域的边界格子坐标，例如 `[[4,6]]`；其他边界为无流边界 |
| dt_s / rain_m_s | 时间步和均匀降雨速率 |
| routing_tau_s | 0 为瞬时汇流；正值为每个非洼地单元的概念储水时间 |
| channel_area_m2 | 仅用于展示候选河道的汇流面积阈值，不影响水量计算 |

本轮是“不透水地表”受控实验：土壤容量和入渗为零，降雨全部成为径流或直接进入洼地。未把新的地形来源与土壤参数标定混在一起。洼地底部只接收一次降雨，其余格子作为独立陆地单元接收雨量。

模型边界：局部平面、四邻接、显式无流边界；不自动把区域边缘判为海洋。不透水地表、瞬时路由和候选河道都属于受控实验假设。零雨量下的流向图仍是潜在排水路径，不表示永久有水。

洼地识别当前只提取没有更低出口的等高底部区域。水位达到第一个更高邻格后，需要扩展淹没面积、容量曲线或合并水体；本版超范围返回 `CAPACITY_OUT_OF_DOMAIN` 并保留此前完整检查点，不模拟后续溢流。该门槛不是完整盆地的最终溢流鞍点。

`terrain.json` 保存适配器版本、原始高程、邻接、流向、汇水面积、流域终点及有效容量范围；`scenario.json` 可继续交给普通 `run` 命令。恢复运行时原地形地图不会自动重绘；可从地形元数据查询位置关系。

详细实现与证据见[地形接入验证记录](局部地形排水验证记录.md)。

## 湖面扩展、合并与溢流

```sh
python3 -m hydro flood --input examples/fill-spill-merge.json --steps 12 --out artifacts/fill-spill-merge
python3 -m hydro flood --resume artifacts/fill-spill-merge/flood-checkpoint.json --steps 1 --out artifacts/flood-resumed
```

独立 `flood` 命令沿用高度网格输入，支持湖面扩大、邻盆填充、合并和从最终鞍点溢流。`terrain` 命令仍保留上一阶段的有限容量实验行为。

查看湖面回放（原型文件已清理）与[实现验证记录](湖盆淹没合并与溢流验证记录.md)。示例 12 步输入 14.4 m³、储水 9 m³、外流 5.4 m³。报告包含时间步滑条、逐格水深、活动湖盆、事件、CSV 和独立检查点。

本模块限于 1024 格、初始干燥、只增加水量的不透水准静态实验，要求 `routing_tau_s=0`；未与土壤、蒸发和地下水联算，也不计算洪水传播速度。同高分支用稳定 ID 排序。新增 16 项测试，连同原有回归共 44 项通过；报告的浏览器交互验收尚未完成。

## 检查点与失败恢复（已有水文配置）

```sh
python3 -m hydro run --resume artifacts/coupled/checkpoint.json --steps 12 --out artifacts/resumed
```

恢复时不能同时指定新场景，配置、时间步和模型版本沿用存档。模型失败整步回滚；CLI 将最后完整状态写入输出目录的 `failed-run-checkpoint.json` 并返回错误码。

H4 越界在独立组件中返回首次触边时刻与局部状态；完整调度器停止并回滚本步，不自动推进事件之后的时间。

检查点使用同目录临时文件与替换提交。当前通过从初始条件确定性重放核对完整检查点，能发现被重新计算校验值但内部不一致的数据；此方式会随模拟长度增加成本，不是生产级快速恢复方案。

## 配置入口

顶层字段：`schema_version=1`、`name`、`dt_s`、`nodes`、可选 `land` 和 `exchanges`。未知字段直接报错，避免参数拼写错误被静默忽略。所有 ID 是不含冒号的非空字符串。

### 节点

| kind | 必需属性 | 可选／说明 |
| --- | --- | --- |
| aquifer | id、capacity_m3 | initial_m3，head；有限地下储水桶 |
| reach | id、tau_s、to | initial_m3、area_m2、base_m、rain_m_s、evap_m_s、inflow_m3_s、head |
| lake（闭口） | id | initial_m3、area_m2、base_m、rain_m_s、evap_m_s、inflow_m3_s、head、curve；无出口参数 |
| lake（有出口） | id、to、tau_s、spill_m3 | 与闭口湖同；spill_m3 是出口高程对应库容，不是出口高程本身 |
| junction | id、to | inflow_m3_s；无储水时延，初始储量必须为 0 |
| outlet | id | 外部出流记账终点，没有内部储水 |

水体面积默认 1 m²、底高默认 0 m，实际示例应明确填写。初始体积、雨量、蒸发及外部入流默认 0。`to` 是单一节点 ID；不支持分汊、潮汐或路由循环。

`curve` 为严格递增的 `[[volume_m3, elevation_m], ...]`，起始体积必须为 0，不允许范围外外推。首版即使配置曲线，受雨／蒸发面积仍由固定 `area_m2` 提供。具有曲线的水体暂不能参与线性 H4 交换。

### 陆地单元

必需：`id`、`area_m2`、`capacity_m3`、`drainage_threshold_m3`、`groundwater`、`to`。可选：`initial_m3`、`infiltration_m_s`、`drainage_m_s`、`rain_m_s`、`evap_m_s`，默认均为 0。

每块土壤在首版拥有独占的地下桶，禁止多土壤抢占同一个有限容量桶。陆地径流进入 `to`，与直接落在水体上的雨量不同。输入者应确保面积没有重复覆盖，当前人工场景没有几何重叠检测。

### 地下交换

`exchanges` 条目为 `{"a":"ground","b":"lake","conductance_m2_s":0.0001}`。

两端节点须有 `head={"base_m":0,"b_m2":1000,"min_m3":0,"max_m3":10000}`。只有 min_m3 可省略，默认 0。`b_m2` 为水位变化与储量的比例，不是直接给定水位。

地表水的 head 必须与固定面积几何相符。地下 head 上界不得超过桶容量。交换边不能共享节点；饱和连接、储量和水头关系超有效范围会停止，不能当作河床脱水或复杂含水层的求解。

## 代码结构

| 路径 | 内容 |
| --- | --- |
| hydro/models.py | 无界面的纯计算组件、容量曲线与地形排水排序 |
| hydro/engine.py | 配置、路由图、算子顺序、账本、事务与检查点 |
| hydro/benchmarks.py | B01–B18 独立参考值和收敛实验 |
| hydro/report.py | CSV、JSON 与离线 HTML/SVG 诊断 |
| hydro/cli.py | 运行、基准和平台结果比较 |
| tests/test_hydrology.py | 守恒、解析性质、失败回滚、恢复和 CLI 测试 |

人工地形排水函数可独立调用，`terrain` 命令可从规则网格生成 `to` 河网和有限范围洼地。独立的 `hydro/flood.py` 实现小型网格的准静态淹没、合并与溢流，`hydro/flood_report.py` 输出回放报告；两套检查点不可混用。

## 跨平台验证方法

在 Windows 与 macOS 的同一代码版本分别执行 benchmark，保留各自的 `benchmarks.json`，然后执行：

```sh
python3 -m hydro compare-platforms windows-benchmarks.json macos-benchmarks.json --out platform-comparison.json
```

比较完整基准结果的标准化摘要及引擎版本。只有实际获得两端报告后才能给出该平台组合的通过证据；不把复制或改写平台名称的报告视为有效实验。

当前使用系统 `math.exp/expm1/log1p` 与 binary64，尚未解决任意平台数学库末位差异。若摘要不一致，需实现或选择确定性数值路径，不能改用宽松容差宣称严格复现。

## 当前限制

- 只有概念水量模型，无动量、能量、冰雪、侵蚀或现实参数标定。
- H2 的步内均匀入流会产生时间离散误差，B15 专门检查收敛。
- 整步复制、保留全部账本与恢复时重放适合小场景，不适合直接扩大到整颗行星。
- 不支持任意地下网络、多土壤共享桶、分汊、回水或河床脱水继续求解。
- 本机通过不等于 Windows 已验证，也不等于现实地理模型已验证。

模型依据和下一轮验证要求见[水文模型设计](../专题研究/水文模型与基准实验设计.md)与[科学模型与验证规范](../总体架构/科学模型与验证规范.md)。
