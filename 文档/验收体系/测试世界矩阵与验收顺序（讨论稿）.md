# 测试世界矩阵与验收顺序

> **文档状态**

> - 决策状态：部分确认
> - 实现状态：未执行验收

本文将六类固定专门测试世界组织成可执行的验收矩阵。其作用是明确每个场景验证哪条自然过程链、依赖哪些较基础的能力、应保存哪些证据，以及发现失败时优先回查哪个模块。

关联：[第一版验收标准](第一版验收标准（讨论稿）.md) · [自然系统耦合与模型边界](../总体架构/自然系统耦合与模型边界.md) · [沟通进度与决策清单](../项目管理/沟通进度与决策清单.md)。

## 一、使用原则

- 固定测试世界验证受控条件下的过程一致性；随机世界验证多个已通过过程在同一颗行星中的组合表现。两者不能相互替代。
- 测试顺序按依赖关系组织，不代表实际世界在物理时间中的形成顺序。
- 每个场景只验证其主链条，同时保留足以发现跨模块错误的最小上下文；不要求在一个测试世界中复现全部景观。
- 任一对象的视觉外观不能替代其账本、连接关系、材料依据和模型状态。
- 通过固定测试世界只说明实现满足项目已选择的近似模型与约束，不能直接宣称得到现实世界的验证。

## 三、能力层与建议验收顺序

### 第 0 层：共同底座

先验证所有测试世界共享的基础能力：

1. 固定种子、模型版本、边界条件和测试配置可完整保存并重复读取。
2. 高程、海陆、材料区、流域边界、海平面和季节状态具有稳定标识。
3. 水量与储量账本能区分输入、输出、损失和状态变化；对象连接以有向关系表达。
4. 每个分类对象均能返回生成状态：已计算、受约束生成、候选、泛化表达或不生成。

第 0 层未通过时，不应以任何局部景观图像作为验收结论。

### 第 1 层：气候与地表水骨架

建议先执行 T01，再执行 T02。

- T01 检验湿润、高山与融雪条件下，水如何从气候输入进入河湖。
- T02 在同一骨架上检验水汽受限、雨影、蒸发需求与外来河／内流盆地的边界。

这两项共同回答“水从哪里来、为什么在这里多或少、积雪如何进入水系”。

### 第 2 层：多路径河网与近海出口

建议执行 T03，再执行 T04。

- T03 检验陆地低坡河段中的汇合、分流、再汇合、湿地与河道沉积条件。
- T04 在已能追踪多路径水量的基础上，引入沉积物账本和海洋边界，决定能否称为三角洲。

T04 不应绕过 T03 单独验收，因为三角洲分流同样依赖水量分配与湿地／滞水的收支一致性。

### 第 3 层：材料控制的地表与地下过程

建议在第 1 层的补给能力和第 0 层的材料能力通过后，执行 T05 与 T06；二者可并行讨论或实施验证。

- T05 关注可溶岩和地下水的连通，验证地表水转入地下又重新出露的路径。
- T06 关注材料与结构差异对地表形态的选择，验证特殊地貌不会脱离成因条件。

T05 的可溶岩条件可为 T06 的岩溶石林分类提供依据；T06 的非岩溶岩柱规则则帮助防止二者混用。

## 四、跨场景复用与隔离规则

| 共享能力 | 使用场景 | 复用规则 |
| --- | --- | --- |
| 气温、降水、水汽来源、蒸发需求、雨雪分配 | T01、T02，并为 T03–T05 提供边界 | 共享字段定义和单位；各场景仍独立固定边界，不复制前一场景的结果图 |
| 地表水账本与连接图 | T01–T05 | 同一守恒规则适用；场景可选择不同输入、储水与出口，不共享未声明状态 |
| 材料与表层属性 | T02–T06 | 统一属性词典；不同场景只启用与目标过程相关的属性 |
| 海洋水位与海岸边界 | T01、T04 | T01 的海洋是水汽来源背景；T04 的海洋还必须作为河口水位与沉积再分配边界 |
| 地下连接表达 | T05，并支持未来局部三维 | 只复用连接和高程／范围记录，不假设已实现完整三维水动力 |
| 形态量与分类状态 | T03、T06 及全部对象查询 | 形态量是分类证据，不能被景观名称反向篡改 |

隔离规则：修改某场景的控制变体，只能改变该变体声明的输入。若无依赖关系的字段、对象身份或其他场景基准结果随之改变，应判为测试环境或依赖追踪错误。

## 五、统一证据包

每次运行任一固定测试世界，应输出同一结构的证据包；具体字段可随模型演进增加，但不得省略核心内容。

| 部分 | 最低内容 | 用途 |
| --- | --- | --- |
| 身份与可重现性 | 测试世界编号、种子、模型版本、固定配置、启用模块、变体编号 | 重跑、比较与防止配置混淆 |
| 空间与边界 | 高程、材料区、边界输入／输出、对象稳定标识 | 判断对象是否处于正确容器与位置 |
| 状态账本 | 水、雪、地下储量或沉积物的输入、输出、损失、储量变化 | 检查守恒和重复计量 |
| 连接关系 | 河网、地下路径、湖泊出口、海洋边界等有向图 | 检查来源、去向、分流和汇合 |
| 分类依据 | 对象状态、满足条件、所缺条件、降级原因 | 解释为什么生成、候选或拒绝 |
| 季节与变体对比 | 基准与各状态／变体的差异、允许不变项与实际不变项 | 检查连续性与方向性 |
| 验收结论 | 通过、条件通过、不通过或未验证；对应规则编号和证据位置 | 形成可审查结论 |

## 六、失败定位路线

| 首先看到的异常 | 首先回查 | 其次回查 |
| --- | --- | --- |
| 降水位置或雨影不合理 | 气候输入、水汽路径、地形抬升条件 | 温度、蒸发需求与季节边界 |
| 河流无源、逆流或分流后翻倍 | 高程／流向、上游输入、水量账本 | 储水、损失和分流规则 |
| 湖泊、湿地或天坑水位无解释 | 容量、出口、入渗与蒸发账本 | 地下连通或季节输入 |
| 三角洲、江洲或河滩无条件出现 | 沉积物来源、保留边界、低坡材料 | 水位状态与分类门槛 |
| 泉水、暗河或溶洞无依据 | 可溶岩、裂隙、地下储量与水头 | 地表补给与出露去向 |
| 峡谷、岱崮或石林像随机装饰 | 高差、材料差异、结构控制和侵蚀路径 | 分类状态与降级规则 |
| 季节切换后地貌拓扑改变 | 稳定骨架标识与季节状态分离 | 缓存、依赖失效与随机数作用域 |

## 七、整体通过门槛

六个测试世界的整体结论不能简单取“通过数量”。建议按以下顺序判断：

1. 第 0 层共同底座全部通过。
2. T01–T04 中与水量和边界有关的阻断规则全部通过；否则不接受河湖、湿地或三角洲相关的整体结论。
3. T05、T06 中与材料前提和分类降级有关的阻断规则全部通过；否则不接受岩溶与特殊地貌相关的整体结论。
4. 允许某些高阶过程为“未验证”或“条件通过”，但必须将对应对象降级表达，且在查询中说明缺失模型。
5. 在六类固定世界通过其适用门槛后，才进入随机世界的组合检验与地图探索验收。

## 八、仍待共同决定的事项

- 每个测试世界的具体尺度、数值范围、网格／连续场表示与容差。
- 账本的时间步长、季节状态数量和内部积分方式。
- 气候、融雪、地下水、沉积物与侵蚀的首版具体公式及参数标定范围。
- “条件通过”是否可进入首版发布，以及哪些对象必须达到“已计算”状态。
- 随机世界组合测试的数量、覆盖指标与人工审阅流程。

本文只定义验收组织方式，不新增任何算法、参数或实现承诺。
