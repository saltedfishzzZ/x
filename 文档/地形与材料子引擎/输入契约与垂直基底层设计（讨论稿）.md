> **文档状态**

本文讨论地形与材料子引擎的 M1“输入契约与垂直基底层”。M1 不生成材料、地形起伏、坡面或盆地；它把世界规格、球面空间、正式构造快照、模型清单、垂直基准和运行范围组织为不可变输入束，并在任何自然生成开始前完成准入判断。

关联：[地形与材料子引擎前置条件清单](地形与材料子引擎前置条件清单（讨论稿）.md) · [全球规格层设计](../构造子引擎/全球规格层设计（讨论稿）.md) · [球面空间底座设计](../构造子引擎/球面空间底座设计（讨论稿）.md) · [构造输出契约层设计](../构造子引擎/构造输出契约层设计（讨论稿）.md) · [构造验收与解释层设计](../构造子引擎/构造验收与解释层设计（讨论稿）.md)。

## 一、M1 的职责与边界

### M1 负责

- 绑定同一世界身份下的世界规格、球面空间和构造发布资产。
- 判断上游发布状态、验收结论、能力、字段与版本是否满足本次运行。
- 建立版本化垂直基准、单位和允许精度语义。
- 区分改变自然世界的规格、只改变计算范围的运行计划和只影响显示的界面状态。
- 锁定地形与材料模型、参数配置及稳定命名随机流。
- 生成不可变 `TerrainMaterialInputBundle` 与准入报告。
- 为全球生成、局部细化和固定测试世界提供统一输入入口。

### M1 不负责

- 修改或修复上游构造快照。
- 根据期望地貌反向改变板块、构造约束或世界规格。
- 生成材料族、岩性解释、高程贡献或地形对象。
- 求解海平面、湖泊、河流、侵蚀或沉积。
- 读取显示夸张、地图投影、相机和配色来改变自然结果。
- 让测试 Oracle 进入正式生成路径。

## 四、M1-D01：上游准入与正式生成资格

### 4.1 准入单位

M1 不分别接受若干松散文件，而是检查一个候选输入集合。集合内所有资产必须通过稳定标识和内容摘要互相绑定，避免把不同种子、不同世界或不同模型运行的结果拼接在一起。

候选集合至少证明：

1. `WorldSpec` 已冻结且通过自身规格校验。
2. `SphereSpaceSnapshot` 与世界半径、网格方案及空间版本一致。
3. `TectonicSnapshot` 引用同一 `WorldSpec` 和空间底座。
4. 构造发布状态为 `RELEASED`。
5. 标准配置下构造验收结论为 `PASS`。
6. 地形消费者要求的 L5/L6 字段、对象、尺度、单位和证据均已声明可用。
7. 构造快照与验收包的规范摘要匹配。
8. 地形材料模型与上游契约版本兼容。
9. 输入不存在未解决的身份冲突、版本冲突或必需证据缺口。

### 4.2 准入结论

建议把输入检查结果分为：

| 结论 | 含义 | 允许用途 |
| --- | --- | --- |
| `ADMITTED` | 标准要求全部满足 | 可进入正式生成 |
| `DIAGNOSTIC_ONLY` | 存在已知限制，但足以执行具名诊断 | 只能生成不可发布诊断结果 |
| `REJECTED` | 身份、契约、状态或必需能力明确不满足 | 禁止生成 |
| `UNRESOLVED` | 缺少证据或无法判定兼容性 | 禁止正式生成，可补齐证据后重试 |

准入结论与具体原因分开保存。一个输入可以同时具有多个原因，例如“构造验收未通过”和“缺少方向字段”。

### 4.3 正式与诊断路径

标准生成只接受 `ADMITTED`。诊断路径允许明确选择 `DIAGNOSTIC_ONLY`，但必须：

- 标记诊断目的和接受的限制；
- 使用独立的运行标识与输出命名空间；
- 在输出中继承全部上游限制；
- 禁止进入 `RELEASED` 地形材料发布；
- 禁止被正式下游消费者自动发现；
- 不得通过补默认值伪造缺失的权威输入。

### 4.4 禁止隐式修复

以下情况不能由 M1 静默修复：

- 世界标识或种子不一致；
- 球面空间版本不兼容；
- 单位、方向基底或字段语义缺失；
- 构造快照与验收包摘要不一致；
- 构造结论为 `FAIL` 或 `NOT_VERIFIED`；
- 地形所需的公共字段只存在于上游诊断缓存；
- 上游未知值被擅自替换为零或平均值。

M1 只能拒绝、标记未决，或在用户明确选择诊断运行时保留限制继续。

### 4.5 测试资产隔离

固定测试世界分成：

```text
FixedTestInput   可进入生成路径的受控世界输入
TestOracle       只供验收器读取的预期、容差和禁止结果
```

更换、删除或修改 `TestOracle` 只能改变验收结果，不得改变同一 `FixedTestInput` 生成的自然快照。

## 六、M1-D02：世界规格、运行计划与显示状态

M1 将外部设置分为四类：

| 类别 | 示例 | 是否改变规范自然结果 |
| --- | --- | --- |
| 世界规格与模型身份 | 种子、类地预设、行星参数、高级因果偏好、模型与参数版本 | 是，形成新的生成身份或分支 |
| 运行计划 | 目标区域、目标 LOD、任务优先级、线程与内存预算 | 只改变计算范围和调度，不改变同一内容的规范结果 |
| 数值执行配置 | 精度等级、近似算法、计算后端、容差配置 | 必须进入复现清单；可能影响能力或兼容等级 |
| 显示状态 | 投影、镜头、颜色、标签、语言、垂直夸张 | 否，不进入自然输入束 |

默认只输入种子时，L2 先用版本化类地预设展开完整 `WorldSpec`。M1 不读取界面中的隐式默认值。高级偏好必须先进入世界规格并获得稳定摘要，不能从桌面应用直接注入某个局部生成步骤。

建议使用：

```text
GenerationIdentity = hash(
    WorldSpec,
    TectonicSnapshot,
    TerrainMaterialModelManifest,
    TerrainMaterialParameterProfile
)
```

`TerrainMaterialRunPlan` 只描述本次请求生成哪些区域和尺度、资源如何安排、失败时是否继续诊断。局部生成和全局生成对同一位置、尺度及版本必须得到相同规范结果。线程数、任务顺序、缓存、镜头和浏览顺序不参与 `GenerationIdentity`。

数值执行配置若只能造成已声明容差内的平台差异，可以作为复现清单和兼容等级；若会改变分类、对象拓扑、材料类别或超出容差的权威值，则必须形成不同生成分支，不能伪装成纯性能选项。

部分生成属于同一世界的覆盖状态：未请求区域标记为未生成，不能填入默认自然值，也不能把“只生成一个区域”当成另一颗世界。

## 八、M1-D03：垂直基准契约

M1 输出不可变 `VerticalDatumDescriptor`，首版至少包含：

```text
datumId
datumKind = REFERENCE_SPHERE
bodyFrameId
centerDefinition
referenceRadiusMeters
upDirectionMode = RADIAL
heightUnit = METER
surfaceSemanticRegistryVersion
errorModelVersion
compatibilityVersion
```

球面方向 `n` 由 L1 权威几何提供，点的全局位置定义为：

```text
P = O + n × (referenceRadiusMeters + h)
```

其中 `O` 是行星中心，`h` 是相对参考球面的径向高程。参考球面零高程是稳定几何基准，不代表平均海平面。固体表面、水面、冰雪表面、植被冠层和显示高度通过不同 `surfaceKind` 表达，不能共用模糊 `height` 字段。

每个高程查询至少返回：

```text
heightMeters
verticalDatumId
surfaceKind
lod
supportScaleMeters
verticalErrorBoundMeters
validity
snapshotId
```

局部三维使用由全球锚点派生的东—北—上坐标系。锚点保存球面方向、高程、基准和快照；局部坐标只是有限范围内的计算表示。洞穴深度、建筑高度或悬挑偏移需要同时引用全球锚点和所属固体表面，不能把局部负值当作全球负高程。

基准兼容分为：

| 结论 | 条件 | 处理 |
| --- | --- | --- |
| `EXACT` | 基准标识与描述摘要相同 | 可直接组合 |
| `EXPLICITLY_CONVERTIBLE` | 参考中心与方向语义一致，存在版本化转换 | 生成带误差的新派生结果 |
| `NOT_COMPARABLE` | 中心、方向、单位语义或表面类型无法对齐 | 拒绝组合 |
| `UNRESOLVED` | 缺少描述或转换证据 | 禁止正式使用 |

基准转换不能静默发生。转换必须记录源基准、目标基准、公式、误差和转换版本。修改行星参考半径仍然改变世界规格和生成身份；转换只用于显式数据迁移或比较。

## 十、M1-D04：缺失、未知、部分生成与能力协商

M1 不使用单一状态混合所有问题。字段与对象分别声明：

```text
availability   # 是否存在或已经生成
applicability  # 在当前位置是否有物理意义
validity       # 契约与依赖是否仍有效
knowledge      # 已知、估计或未知
coverage       # 覆盖的空间与尺度
confidence     # 分类或解释置信度
errorBound     # 数值误差
```

建议状态包括：

| 维度 | 主要状态 |
| --- | --- |
| availability | `PRESENT`、`NOT_GENERATED`、`MISSING` |
| applicability | `APPLICABLE`、`NOT_APPLICABLE`、`UNDETERMINED` |
| validity | `VALID`、`STALE`、`INVALID` |
| knowledge | `KNOWN`、`ESTIMATED`、`UNKNOWN` |

零、空集合和 `false` 都可能是合法自然值，不能作为缺失哨兵。错误、未生成、未知和不适用也不能互相替代。

每个 M1 模型声明结构化 `InputRequirement`：

```text
requirementId
fieldOrCapabilityId
requiredLevel
contractVersionRange
spatialScope
lodRange
maximumError
allowedStates
fallbackPolicy
consumerPurpose
```

M1 将要求与上游能力清单逐项匹配，得到：

| 结论 | 含义 |
| --- | --- |
| `SATISFIED` | 要求直接满足 |
| `SATISFIED_WITH_DECLARED_FALLBACK` | 使用模型预先声明、可追溯的降级方案满足 |
| `UNSATISFIED` | 明确不满足 |
| `UNRESOLVED` | 缺少证据，无法判断 |

必需要求只有在 `SATISFIED`，或标准配置预先允许对应 fallback 时，才可进入正式生成。fallback 必须写入能力声明、来源账本和验收范围；临时补值不构成 fallback。

部分覆盖使用显式球面区域和 LOD 范围表达。局部运行必须检查目标核心区、过渡区及计算边缘区是否都有所需输入；范围外保持 `NOT_GENERATED`。确定性派生字段可以满足要求，但必须绑定派生公式、版本、源字段、误差与证据，并标为 `DERIVED`。

## 十一、M1-D04 初步验收方向

| 编号 | 验收内容 |
| --- | --- |
| M1-I28 状态分轴 | 存在性、适用性、有效性、知识状态、覆盖和置信不共用模糊枚举 |
| M1-I29 合法零值 | 零、空集合和 `false` 不会被识别为缺失 |
| M1-I30 未生成分离 | `NOT_GENERATED` 不被解释为未知自然值或不适用 |
| M1-I31 未知传播 | `UNKNOWN` 不被静默替换为零、平均值或默认类别 |
| M1-I32 要求逐项匹配 | 每项输入要求都有明确匹配结论和证据 |
| M1-I33 fallback 受控 | 只有预先声明的 fallback 可用于标准运行并降低相应能力声明 |
| M1-I34 局部覆盖完整 | 核心、过渡和边缘计算范围均满足声明输入要求 |
| M1-I35 派生可追溯 | 派生输入绑定公式、版本、源字段、误差和证据 |
| M1-I36 过期阻断 | `STALE` 或 `INVALID` 的必需输入不能通过标准准入 |

## 十二、M1-D05：随机流命名、隔离与确定性

M1 只定义和锁定随机流契约，不在本层抽取具体地形随机值。所有地形材料随机性从世界种子经稳定键派生：

```text
streamKey = H(
    worldSeed,
    streamSchemaVersion,
    layerNamespace,
    processNamespace,
    stableOwnerId,
    scaleBand,
    purpose,
    relevantParameterFingerprint
)
```

运行计划、线程、任务顺序、缓存、镜头和存储数组序号不得进入随机键。`relevantParameterFingerprint` 只包含真正影响该流的参数，使修改某个局部材料偏好不会无理由重抽其他大陆的山地随机性。

命名空间示例：

```text
terrain-material/v1/M2/material-family/{ownerId}
terrain-material/v1/M2/material-mixture/{ownerId}/{scaleBand}
terrain-material/v1/M3/base-elevation/{sourceId}
terrain-material/v1/M4/ridge-detail/{ridgeId}/{scaleBand}
terrain-material/v1/M4/local-relief/{regionId}/{scaleBand}
```

随机流绑定稳定球面对象、区域或贡献标识，不绑定临时格元数组位置。空间相关场仍由明确的相关模型生成；流隔离不等于逐格元独立白噪声。

禁止共享可变全局随机数发生器。每个采样还需使用稳定 `samplePurpose` 和 `sampleIndex`，确保增加一种新属性不会移动旧属性的随机序列。随机核心、整数到分布的映射和流模式都进入 `TerrainRandomStreamManifest`；改变流语义时提升模式版本并形成可追踪差异。

固定测试输入使用固定世界种子和流清单。测试 Oracle 不提供随机值，也不能影响抽样。诊断重试必须复用同一随机键；通过不断换随机数获得成功属于新的输入，不能冒充同一次重试。

## 十四、M1-D06：统一运行契约

所有运行模式共用 `TerrainMaterialInputBundle` 与 `TerrainMaterialRunPlan`，通过 `runProfile` 声明目的：

| 运行配置 | 用途 | 关键附加条件 |
| --- | --- | --- |
| `STANDARD_GLOBAL` | 生成标准全球基础地形与材料 | 正式上游 `RELEASED + PASS`，覆盖要求完整 |
| `REGIONAL_REFINEMENT` | 在父快照上增加授权尺度细节 | 父快照兼容、区域与边缘完整、尺度带获授权 |
| `FIXED_TEST` | 运行 TM01—TM09 等固定资产 | 使用版本化测试输入；Oracle 独立；产物进入测试命名空间 |
| `DIAGNOSTIC` | 定位失败、比较模型或受限实验 | 显式接受限制；禁止正式发布和自动下游发现 |

运行计划至少声明：

```text
runId
runProfile
inputBundleId
targetRegion
targetLodRange
targetScaleBands
requiredCapabilities
parentSnapshotId
boundaryAndHaloPolicy
numericExecutionProfile
evidenceLevel
failurePolicy
outputNamespace
```

全球与局部运行使用相同自然模型、随机流和字段语义。局部运行读取不可变父快照，只生成获授权的更细尺度贡献和对象谱系；对重叠位置和尺度，独立局部运行与完整全球运行必须给出相同规范结果。

固定测试允许使用结构有效的合成上游夹具，其生命周期可以是 `TEST_FIXTURE`，无需伪装成生产 `RELEASED`。测试准入仍检查身份、契约、单位、空间、能力和摘要，只替换生产发布门槛；测试产物不得进入标准世界发布。`FixedTestInput` 可进入生成器，`TestOracle` 仍仅由验收器读取。

诊断配置可以读取 `DIAGNOSTIC_ONLY` 或特意破坏的输入，但必须隔离输出、继承限制并阻止发布。断点续算、缓存和任务迁移只能恢复同一输入束与运行计划；自然参数、流版本、父快照或尺度语义变化时创建新运行。

## 十六、M1-D07：发布、自验收与失败契约

M1 的发布单位不是单一配置文件，而是原子绑定的 `TerrainMaterialInputRelease`：

```text
TerrainMaterialInputRelease
├─ TerrainMaterialInputBundle
├─ InputAdmissionReport
├─ VerticalDatumDescriptor
├─ TerrainRandomStreamManifest
├─ InputDependencyManifest
├─ TerrainMaterialRunPlan
├─ M1ValidationPackage
└─ InputReleaseManifest
```

`InputReleaseManifest` 保存所有资产的规范摘要、生成身份、运行配置、能力范围、验收结论和生命周期状态。任一引用缺失、摘要不匹配或版本不可兼容时，整份发布不可用。

M1 验收结论沿用 `PASS`、`CONDITIONAL_PASS`、`FAIL`、`NOT_VERIFIED`；生命周期使用 `DRAFT`、`DIAGNOSTIC_ONLY`、`RELEASED`、`SUPERSEDED` 和 `REVOKED`。标准 M2 只接受 `runProfile = STANDARD_GLOBAL/REGIONAL_REFINEMENT`、准入为 `ADMITTED`、验收为 `PASS` 且生命周期为 `RELEASED` 的输入发布。

`M1ValidationPackage` 需要覆盖 M1-I01 至 M1-I56，并保存要求、断言、观测、证据、失败、能力限制和复现信息。M1 还需要独立自验收，使用人工构造的错世界、错摘要、坏基准、缺字段、Oracle 泄漏、随机流漂移和命名空间混淆等夹具验证准入器本身；M1 不能为自己的错误生成通过证明。

失败记录至少包含：

```text
failureCode
requirementId
assetId
fieldOrCapabilityId
spatialAndScaleScope
expectedContract
observedState
dependencyPath
impactScope
reproductionPackageId
```

最小复现包包含触发失败所需的最小输入束、模型与契约版本、随机流清单、运行计划、准入规则及断言，不包含无关缓存和界面状态。发布必须原子完成，旧发布通过 `SUPERSEDED` 谱系保留，发现严重契约错误时可 `REVOKED`，但不覆盖历史证据。

## 十八、确认结论

M1-D01 已确认：标准地形生成只接受身份一致、契约兼容、构造发布状态为 `RELEASED`、标准验收为 `PASS` 且必需能力完整的输入束。受限输入只可进入显式诊断路径，并禁止正式发布；M1 不修复上游、不补造权威值，测试 Oracle 与生成路径物理隔离。

M1-D02 已确认：世界规格、构造快照、地形材料模型和自然参数共同定义生成身份；运行计划只控制范围、尺度请求和调度；数值执行配置进入复现与兼容性判断；显示状态完全隔离。局部与全局运行对重叠内容一致，未生成区域保持显式未生成。

M1-D03 已确认：首版使用绑定 L1 球面方向、行星中心和版本化参考半径的球面垂直基准，权威高程以米表示并携带表面类型、LOD、支持尺度、误差、有效性和快照。局部三维从全球锚点派生；基准转换显式、有版本并传播误差，无法比较的基准拒绝组合；参考球面零点与海平面分离。

M1-D04 已确认：存在性、适用性、有效性、知识状态、覆盖、置信和误差分开表达；输入模型通过结构化要求与上游能力逐项协商。未知、缺失、未生成、不适用和合法零值互不替代；只有预先声明且可追溯的 fallback 或派生规则可用于正式运行，部分覆盖显式声明球面范围和尺度。

M1-D05 已确认：所有随机性从世界种子通过版本化命名键派生，按层、过程、稳定对象、尺度带、用途和真正相关的参数隔离；运行与显示状态不进入随机键。禁止共享可变全局随机源，采样用途和索引保持稳定；随机核心、分布映射及模式版本进入流清单，跨补丁边界共享稳定条件，重试不得偷偷换流。

M1-D06 已确认：标准全球、区域细化、固定测试和诊断运行共用输入契约，仅通过版本化运行配置改变授权范围和发布规则。区域细化引用不可变父快照并与全球运行重叠内容一致；测试夹具与 Oracle 分离并隔离发布；诊断输出继承限制且不可被正式发现；恢复和迁移不改变规范结果。

M1-D07 已确认：M1 以输入束、准入报告、垂直基准、随机流清单、依赖清单、运行计划、验收包和发布清单为原子发布资产。标准 M2 只读取 `ADMITTED + PASS + RELEASED` 的正式输入发布；结论可追溯，失败可最小复现，替代与撤销保留历史；M1 使用独立故障夹具自验收，不能为自身错误生成通过证明。

至此 M1-D01 至 M1-D07 全部确认。下一阶段进入 [M2 材料背景层设计](材料背景层设计（讨论稿）.md)。
