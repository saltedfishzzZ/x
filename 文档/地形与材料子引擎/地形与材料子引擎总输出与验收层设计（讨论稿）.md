> **文档状态**
>
> - 文档类型：分层设计
> - 决策状态：已确认
> - 实现状态：未实现

本文讨论地形与材料子引擎的 M7“总输出与验收层”。M7 不生成新的材料、地形、拓扑或固体容器，而是把 M1—M6 已发布且相互兼容的不可变资产组合为一个可供下游稳定消费的 `PrimaryTerrainMaterialRelease`，统一提供能力协商、消费者视图、证据追踪、失效范围、复现入口和总发布结论。

## 一、M7 的职责与边界

### M7 负责

- 校验 M1—M6 发布的世界身份、版本、摘要和依赖链闭合。
- 建立地形与材料子引擎的总发布清单和原子入口。
- 聚合能力声明，但保留能力的原始所有层和证据来源。
- 为气候、水体、水文、地貌语义、桌面探索和局部三维提供受限消费者视图。
- 汇总跨层来源图、要求追踪、验收证据和解释入口。
- 计算跨层失效范围和兼容性状态，不替下层修复资产。
- 组合固定测试世界、跨层不变量和跨平台验收结论。
- 提供失败定位、最小复现和发布生命周期。

### M7 不负责

- 重算或修改 M1—M6 的权威自然状态。
- 复制一份脱离来源层的“最终高程”“最终材料”或“最终拓扑”。
- 为使总验收通过而填补缺失字段、重排门槛或平滑接缝。
- 将 `CONDITIONAL_PASS`、`UNVERIFIED` 或实验资产伪装为标准能力。
- 生成气候、水量、水位、海陆、河网、植被或成熟地貌语义。
- 根据显示需求改变科学字段或对象身份。
- 把旧层与新层的兼容片段拼接成没有真实依赖链的混合快照。

## 二、正式输入与拟议输出

### 2.1 正式输入

```text
M1InputContractRelease
M2MaterialBackgroundRelease
M3BaseElevationRelease
M4MultiScaleReliefRelease
M5SurfaceGeometryTopologyRelease
M6SolidContainerInterfaceRelease
TerrainMaterialReleaseProfile
TerrainMaterialAcceptancePolicy
```

所有层必须已经完成各自发布，且 M2—M6 的直接依赖标识逐层闭合到同一 M1 世界身份。M7 不接受运行中的草稿、只存在于缓存的结果或未绑定验收包的孤立资产。

### 2.2 拟议输出

```text
PrimaryTerrainMaterialRelease
├─ aggregateReleaseManifest
├─ immutableLayerReleaseRefs
├─ dependencyClosure
├─ capabilityMatrix
├─ consumerViewRegistry
├─ crossLayerEvidenceGraph
├─ acceptanceAndConformanceBundle
├─ invalidationAndCompatibilityMap
├─ explanationAndReproductionIndex
└─ aggregateReleaseState
```

`PrimaryTerrainMaterialRelease` 是引用闭合的总发布入口，不是把所有层数据复制到一个大文件。

## 四、M7-D01：状态所有权与汇总边界

### 4.1 M7 是发布编排层

M7 的工作顺序是：

```text
读取 M1—M6 已发布资产
  → 验证同一世界身份和精确依赖链
  → 验证发布档案要求的能力与证据
  → 建立受限消费者视图和跨层索引
  → 原子发布总清单
```

M7 不能调用下层内部发生器来补算缺失数据，也不能改变任何下层发布。若发现冲突，结果是拒绝、降级或要求产生新的下层快照，而不是在 M7 中修补。

### 4.2 自然状态所有权保持唯一

M1—M6 的权威所有权保持不变：

| 层 | 权威状态 | M7 的权限 |
| --- | --- | --- |
| M1 | 世界规格、球面与垂直基准、输入准入、随机流和运行清单 | 引用、校验、暴露允许的规格摘要 |
| M2 | 材料族、连续物性、层序、结构和材料不确定性 | 引用、组合消费者材料视图 |
| M3 | 长波基础高程、构造响应、材料放置和 M4 授权 | 引用、追踪高程来源和预算 |
| M4 | 多尺度原生起伏、完整固体表面和发生器账本 | 引用、提供权威表面入口 |
| M5 | 微分几何、关键对象、脊谷坡崖、盆地与谱系 | 引用、组合几何拓扑视图 |
| M6 | 容器曲线、门槛、潜在连接、屏障和水体求解输入 | 引用、组合固体容器视图 |
| M7 | 总清单、能力矩阵、证据索引、消费者注册和发布结论 | 自身权威状态 |

同一事实只能有一个权威所有者。M7 可以建立索引和摘要，但摘要必须反向引用来源层；若摘要与来源不一致，以来源层发布为准并使 M7 候选失败。

### 4.3 总发布不是新自然快照

`PrimaryTerrainMaterialRelease` 是一组不可变层发布的组合清单。它不创建另一套可独立修改的自然字段：

- “最终高程”仍指向 M4 `primarySolidElevationField`；
- “最终材料”按查询语义指向 M2 背景或 M3/M4 表面材料视图；
- “最终盆地”指向 M5 几何对象；
- “最终容器曲线”指向 M6；
- M7 只规定某个总发布使用的是哪一份精确对象与修订。

这样避免同一世界出现两份都自称权威、但更新节奏不同的高程或材料数据。

### 4.4 世界身份与依赖闭合

标准总发布至少验证：

```text
M1 worldIdentity
  = M2 sourceWorldIdentity
  = M3 sourceWorldIdentity
  = M4 sourceWorldIdentity
  = M5 sourceWorldIdentity
  = M6 sourceWorldIdentity
```

并验证逐层精确依赖：

```text
M2 → 指定 M1
M3 → 指定 M1 + M2 + L5 构造发布
M4 → 指定 M3 + 材料约束
M5 → 指定 M4
M6 → 指定 M5 + 重力／垂直基准
M7 → 指定上述完整闭包
```

仅世界种子相同并不足以证明兼容。模型版本、参数档案、随机流命名、数值策略、垂直基准、对象规范和验收策略也必须满足声明的兼容关系。

### 4.5 禁止拼接混合快照

以下组合即使局部字段看似可用，也不能形成标准发布：

- 新 M4 固体表面配旧 M5 拓扑；
- 新 M5 盆地配旧 M6 容器曲线；
- 不同垂直基准下的 M3 高程与 M6 等势接口；
- 不同材料背景修订下的表面出露和物性；
- 同种子但模型或随机流版本不同且未证明兼容的资产；
- 已撤销层发布与当前有效层发布的混合；
- 来自不同平台但数值策略或规范摘要不兼容的片段。

M7 不通过“选择看起来最新的每一层”组装世界。总发布必须来自一条真实存在且闭合的依赖链。

### 4.6 发布档案与可选能力

不同使用场景可以要求不同发布档案，例如：

```text
CORE_GLOBAL_TERRAIN
GLOBAL_TERRAIN_AND_MATERIAL
TOPOLOGY_AND_CONTAINER_READY
LOCAL_3D_CAPABLE
```

档案只规定哪些能力为必需、可选或禁止，不改变自然状态：

- 必需能力缺失则该档案失败；
- 可选能力缺失可以发布，但必须明确为 `NOT_AVAILABLE`；
- 实验能力不能冒充标准能力；
- `LOCAL_3D_CAPABLE` 可以要求局部三维接口，基础全球档案则允许其缺失；
- 同一层发布可以参与多个兼容档案，但每个 M7 总发布绑定一个明确档案版本。

具体能力矩阵和协商规则在 M7-D03 冻结。

### 4.7 层状态与总状态

M7 不重新定义层内验收结果。总状态由档案要求和所有依赖共同决定：

```text
PASS
CONDITIONAL_PASS
FAIL
UNVERIFIED
```

- 标准档案的所有必需层必须为兼容的 `PASS + RELEASED`；
- 任一必需层 `FAIL`、`UNVERIFIED`、已撤销或摘要不一致，总发布失败；
- 下层 `CONDITIONAL_PASS` 不能被 M7 提升为 `PASS`；
- 可选能力的明确缺失不必导致核心档案失败；
- 一个层的高分或视觉质量不能抵消另一层的阻断失败；
- 总状态必须保留造成结论的层、能力和断言引用。

### 4.8 M7 派生索引的边界

M7 可以拥有便于消费的派生索引：

- 跨层对象和字段查询目录；
- 能力到消费者视图的映射；
- 位置到来源证据的反向索引；
- 对象到失效依赖的索引；
- 固定测试与要求覆盖索引；
- 最小复现包目录。

这些索引必须可由层发布和 M7 规则重建。索引删除不损失自然事实；索引错误会阻断或撤销 M7 发布，但不能改变下层资产。

### 4.9 与下游系统的边界

M7 可以向下游暴露经过档案验证的输入，但不接收下游结论作为自己的自然状态：

- 气候系统读取固体表面、尺度、材料和几何接口；
- 水体边界求解器读取 M6 受限视图；
- 水文系统读取地形、材料、潜在路径和容器接口；
- 地貌语义层综合 M2—M6 证据与后续气候、水文状态；
- 桌面应用读取预览、查询、解释和能力状态；
- 局部三维系统读取全球锚点、材料和空间接口。

气候、水体、水文或语义结果形成独立快照。若过程改变固体地形，必须从新的演化固体快照重新经过相应 M 层，不回写当前 M7 总发布。

### 4.10 与桌面应用的边界

桌面应用可以：

- 选择种子和高级因果偏好；
- 发起生成、细化、查询和解释请求；
- 显示生成阶段、能力、误差和失败范围；
- 渲染二维地图、三维球体和局部三维场景；
- 保存或选择某个已发布世界版本。

界面状态、相机、配色、高程夸张、标签布局和渲染抽稀不进入 M7 世界身份。桌面应用不得通过修改显示层结果覆盖权威字段，也不能把未发布草稿当作正式世界。

### 4.11 不允许的快捷方式

M7-D01 不允许：

- 复制并维护第二份可编辑的最终高程或材料；
- 用相同种子代替精确依赖和版本闭合；
- 自动选取各层“最新版本”拼接总发布；
- 在 M7 中补算、平滑或默认填充下层缺失数据；
- 将 `CONDITIONAL_PASS` 或实验能力提升为标准 `PASS`；
- 用总体验收平均分抵消必需层失败；
- 将显示缓存、渲染网格或 UI 状态写入世界身份；
- 将下游水体、气候或水文结果回写当前地形材料发布；
- 让派生索引成为无法追溯到来源层的新权威事实；
- 发布引用不闭合或摘要不一致的混合快照。

### 4.12 M7-D01 验收方向

| 编号 | 验收内容 |
| --- | --- |
| M7-G01 上游准入 | 标准总发布只接受档案要求内兼容的 `PASS + RELEASED` M1—M6 资产 |
| M7-G02 所有权唯一 | 自然字段和对象仍由原层拥有，M7 只拥有清单、索引、契约和结论 |
| M7-G03 不重算自然状态 | M7 不补算、填充、平滑或修改材料、高程、拓扑和容器 |
| M7-G04 世界身份一致 | 所有层绑定同一世界身份，种子相同不能替代完整身份校验 |
| M7-G05 依赖闭合 | M1—M6 的直接与传递依赖、版本、参数和摘要形成真实闭包 |
| M7-G06 禁止混合快照 | 新旧表面、拓扑、容器、材料和基准不得跨不兼容依赖链拼接 |
| M7-G07 总入口非副本 | 总发布通过不可变引用组合资产，不维护第二套可编辑权威数据 |
| M7-G08 档案语义 | 必需、可选、实验和禁止能力由版本化发布档案明确区分 |
| M7-G09 状态不升级 | M7 不将下层 `CONDITIONAL_PASS`、`UNVERIFIED` 或撤销状态提升 |
| M7-G10 阻断不可抵消 | 任一必需层或能力失败不能被视觉质量、平均分或其他层抵消 |
| M7-G11 索引可重建 | M7 派生目录与反向索引可由层发布重建且不成为新自然事实 |
| M7-G12 下游隔离 | 气候、水体、水文和语义结果形成独立快照，不回写当前总发布 |
| M7-G13 显示隔离 | 相机、配色、夸张、抽稀、标签和 UI 状态不进入世界身份 |
| M7-G14 确定性 | 相同层发布、档案和 M7 规则生成相同总清单与状态摘要 |

## 五、M7-D01 确认结论

M7-D01 已确认：将 M7 定义为总发布编排层；它只拥有 M1—M6 的不可变引用、依赖闭包、能力矩阵、消费者注册、证据索引和总发布结论，不重新计算或复制自然状态。标准总发布必须来自同一世界身份和真实闭合依赖链，不能按“每层最新版本”拼接，也不能提升下层条件通过状态。发布档案区分必需、可选和实验能力；下游气候、水体、水文、语义和桌面显示状态均保持独立。

## 六、M7-D02：总快照、资产依赖图与原子组合

### 6.1 四类身份不能混用

M7 至少区分：

```text
worldIdentity          # 自然世界身份：种子、世界规格和因果偏好等
layerReleaseId         # 某一层不可变正式发布的身份
aggregateReleaseId     # 一组精确层发布与档案组成的 M7 总发布身份
artifactDigest         # 某个序列化文件、对象块或索引内容的摘要
```

- 同一 `worldIdentity` 可以因模型升级、参数标定或精度变化拥有多个层发布；
- 同一组层发布在不同发布档案下可以产生不同总发布；
- 相同语义资产可以有不同存储分块，但其规范摘要应保持一致；
- 文件摘要相同不自动表示两个对象拥有相同自然身份；
- 路径、文件名、机器名和缓存位置不参与任何自然或发布身份。

### 6.2 总发布清单

建议总清单至少包含：

```text
AggregateTerrainMaterialManifest
├─ aggregateReleaseId
├─ worldIdentity
├─ releaseProfileId
├─ directLayerReleaseRefs
├─ transitiveDependencyClosure
├─ assetAndDigestTable
├─ coverageAndScaleManifest
├─ capabilityMatrixRef
├─ consumerViewRegistryRef
├─ evidenceAndAcceptanceRefs
├─ compatibilityAndLimitationSummary
├─ aggregateState
└─ createdByModelAndPolicyVersions
```

清单是总发布的权威入口。标准查询先固定 `aggregateReleaseId`，再解析到具体层资产，不能在查询过程中重新选择所谓最新层版本。

### 6.3 直接依赖与传递依赖

M7 直接引用 M1—M6 正式发布，同时保存完整传递闭包。闭包至少追踪：

- 世界规格、球面空间、垂直与重力基准；
- 构造子引擎相关正式发布；
- 模型与参数档案；
- 随机流命名和数值策略；
- 材料、高程、表面、几何拓扑与容器层发布；
- 固定测试、验收策略、Oracle 和证据版本；
- 身份规范、序列化规范和消费者契约版本。

总依赖图必须为有向无环图。若两个资产互相依赖，应在架构层拆分共同上游或建立显式时间步，而不能在清单中保存循环引用。

### 6.4 依赖闭包验证

M7 构建候选总发布时逐项验证：

1. 所有直接引用均存在且处于允许生命周期状态；
2. 每个层发布声明的直接依赖与清单选中的上游一致；
3. 传递闭包中的摘要和版本没有分叉或冲突；
4. 世界身份、垂直基准、尺度、对象规范和随机流兼容；
5. 必需验收包、能力和证据可达；
6. 没有悬空引用、循环、重复身份冲突或已撤销资产；
7. 覆盖与发布档案要求一致。

闭包验证失败时，M7 只报告冲突路径和最小失败集合，不自动替换其中某一层。

### 6.5 资产类别

总发布中的资产按语义分为：

```text
AUTHORITATIVE_LAYER_ASSET  # M1—M6 权威字段、对象和账本
AGGREGATE_MANIFEST_ASSET   # M7 清单、能力、契约和结论
REBUILDABLE_INDEX_ASSET    # 空间索引、反向索引、查询目录
EVIDENCE_ASSET             # 验收、解释、来源和复现证据
PRESENTATION_ASSET         # 预览、缩略图、显示抽稀和样式
```

只有前两类参与权威查询。可重建索引损坏可通过重建恢复，但重建结果必须通过摘要和契约检查；证据资产缺失可能阻断发布或审计；展示资产不进入科学结果和世界身份。

### 6.6 引用组合而非数据复制

M7 使用不可变引用组合资产：

- 不把所有层字段复制进单一巨型文件；
- 不为统一格式而重采样权威高程或材料；
- 不把对象图展开成失去身份的显示栅格；
- 不把层内误差压缩成一个总分；
- 不改变层资产的分块、精度和语义；
- 可以建立版本化读取适配器，但适配器只转换接口表示，不能改变自然含义。

若消费者要求不同格式，应通过可追溯导出资产或视图处理，并保留来源总发布身份。

### 6.7 区域补丁与覆盖清单

连续缩放世界可以包含全球骨架和按需局部补丁。总清单必须明确：

```text
globalBaseCoverage
availableScaleIntervals
authoritativePatchSet
patchCoreAndHalo
patchLineageAndParentRefs
coverageGaps
unresolvedOrProvisionalRegions
```

- 全球发布档案必须满足规定的全球骨架覆盖；
- 可选局部补丁只增强声明区域和尺度，不替换不相干全球资产；
- halo 是计算支持，不能伪装成正式核心覆盖；
- 重叠补丁必须来自兼容谱系并通过各层拼接验收；
- 缺失细节应显示为能力不足，不得由显示插值冒充正式资产；
- 新增补丁形成新的 M7 总发布修订，旧发布保持可重现。

### 6.8 内容摘要与规范摘要

建议同时保存：

```text
byteDigest          # 序列化字节完整性
canonicalDigest     # 规范化语义表示摘要
scientificSummary   # 单位、范围、计数、状态和关键不变量摘要
```

`byteDigest` 用于发现文件损坏；`canonicalDigest` 用于跨合法分块或序列化比较；`scientificSummary` 用于快速验收与诊断。三者用途不同，不能只用文件哈希证明科学兼容性。

规范化过程必须版本化，并明确浮点量化、对象排序、图规范化、未知状态和误差区间的处理方式。允许的跨平台数值差异不能改变拓扑、身份、能力或通过结论。

### 6.9 原子组合与提交

总发布采用候选—验证—提交过程：

```text
STAGING
  → RESOLVE_DEPENDENCIES
  → VALIDATE_CLOSURE_AND_PROFILE
  → BUILD_REBUILDABLE_INDEXES
  → VERIFY_DIGESTS_AND_EVIDENCE
  → ATOMIC_COMMIT
```

在 `ATOMIC_COMMIT` 之前，候选不可被标准消费者读取。提交点只发布一个指向完整总清单的不可变根引用。崩溃恢复后只能看到完整旧根或完整新根，不能看到半套层引用。

### 6.10 并发构建与确定性

M1—M6 的独立资产验证、索引构建和摘要计算可以并行，但：

- 层引用集合在候选开始时冻结；
- 并发任务不能自动跟随上游“最新版本”；
- 归并使用规范顺序和确定性图表示；
- 失败或取消的任务不能留下可见正式根；
- 重试、线程数和任务调度不改变总清单内容；
- 多进程同时提交时使用明确的候选身份和原子比较，不覆盖其他已发布根。

### 6.11 缺失、孤立与损坏资产

M7 必须分开处理：

```text
MISSING_REQUIRED_ASSET
MISSING_OPTIONAL_ASSET
ORPHANED_ASSET
DIGEST_MISMATCH
DEPENDENCY_CONFLICT
REVOKED_DEPENDENCY
UNREADABLE_ASSET
```

- 必需资产缺失或损坏阻断标准发布；
- 可选资产缺失按档案声明能力降级；
- 孤立资产不自动加入总发布，可由清理策略处理；
- 摘要不符时不得尝试“最接近”匹配；
- 已撤销依赖使相关总发布不可用于新消费，但历史证据仍保留；
- 缓存缺失只触发可重建索引重建，不应改变自然资产。

### 6.12 快照固定与查询一致性

一次查询、导出或下游运行必须固定单个 `aggregateReleaseId`：

- 查询过程中即使有新总发布产生，也继续读取原固定版本；
- 多字段查询使用同一闭包，不能一个字段读旧 M4、另一个读新 M5；
- 长任务记录固定总发布和实际读取资产摘要；
- 用户主动切换版本时形成新的查询会话；
- “当前最新版”只用于会话开始时选择，不能作为层资产内部引用。

```text
AggregateSnapshotCompositionView
├─ identityTuple
├─ aggregateManifest
├─ directAndTransitiveDependencyGraph
├─ assetClassificationAndDigests
├─ coverageScaleAndPatchManifest
├─ authoritativeAndRebuildableRefs

├─ atomicCommitRecord

```

### 6.14 不允许的快捷方式

M7-D02 不允许：

- 用种子或文件时间戳代替层发布身份；
- 自动选择各层最新资产构建总发布；
- 在缺少真实依赖边时根据名称或路径猜测兼容性；
- 复制和重采样层权威数据以制造表面统一格式；
- 把 halo、缓存或显示插值计入正式覆盖；
- 只用字节哈希证明科学语义兼容；
- 在消费者可见位置逐个替换层引用；
- 让并发完成顺序改变清单或对象排序；
- 将孤立、损坏或摘要不符的资产自动纳入发布；
- 在一次查询中隐式切换总发布版本。

## 九、M7-D03：消费者视图、能力矩阵与协商规则

### 9.1 最小授权消费者视图

M7 按消费者职责提供最小只读视图，避免下游依赖无关层的内部实现：

| 消费者视图 | 主要用途 | 允许读取 | 明确禁止 |
| --- | --- | --- | --- |
| `ClimateTerrainInputView` | 地形强迫、下垫面基础和尺度化粗糙度 | M4 表面、M5 坡度／粗糙度、M2/M3 材料摘要、误差 | 河网、海洋、水量和未发布地貌语义 |
| `WaterBoundaryInputView` | 静态水体覆盖与岸界求解 | M6 容器曲线、门槛、连通、屏障、势位基准 | 预选海洋、目标海陆比例和实际水量 |
| `HydrologyTerrainInputView` | 地表／地下水过程 | M2 物性证据、M4 表面、M5 几何、M6 容器和潜在路径 | 预制流量、唯一河网和默认隔水结论 |
| `LandformSemanticEvidenceView` | 地貌类别识别 | M2—M6 中性候选、位置、材料、尺度、来源和误差 | 把候选直接提升为成熟地貌 |
| `ExplorationQueryView` | 二维地图、三维球体、查询与解释 | 已发布字段、对象、状态、简化表示和来源入口 | 通过显示编辑改写权威状态 |
| `Local3DAnchorView` | 局部三维生成和连接 | 全球锚点、材料、表面、门户、坐标变换与能力状态 | 从缺失能力猜测洞穴内部 |
| `ValidationDiagnosticView` | 验收、调试和失败定位 | 暂定对象、冲突、误差、断言和复现入口 | 绕过标准发布供产品消费 |

视图可以组合多个来源层，但每个字段和对象仍保留原权威层引用。消费者看不到无关的内部随机流、临时候选、缓存键和未授权诊断状态。

### 9.2 能力是带条件的承诺

能力不能只用布尔值表示。建议能力记录为：

```text
CapabilityDescriptor
├─ capabilityId
├─ ownerLayer
├─ semanticVersion
├─ status
├─ supportedSpatialCoverage
├─ supportedPhysicalScaleInterval
├─ supportedLODAndSamplingRange
├─ unitsDatumAndCoordinateSystem
├─ errorAndConfidenceBounds
├─ requiredDependencyCapabilities
├─ allowedConsumerViews
├─ limitations
├─ fallbackOptions
└─ evidenceRefs
```

同一个字段在某个尺度、区域和误差目标下可用，不代表它在所有场景都具备完整能力。能力矩阵必须能表达全球粗尺度可用、局部细尺度缺失，或几何容量可用但地下材料接口部分可用等情况。

### 9.3 能力状态

统一状态建议为：

```text
AVAILABLE
AVAILABLE_WITH_BOUNDS
PARTIAL
PROVISIONAL
NOT_AVAILABLE
FAILED
INCOMPATIBLE
```

- `AVAILABLE`：满足请求和档案的正式能力；
- `AVAILABLE_WITH_BOUNDS`：正式可用，但结果为区间或候选集；
- `PARTIAL`：仅覆盖请求的一部分空间、尺度或子能力；
- `PROVISIONAL`：依赖边界或关系尚未闭合，不能作为标准事实；
- `NOT_AVAILABLE`：当前发布明确未提供；
- `FAILED`：本应提供但生成或验收失败；
- `INCOMPATIBLE`：能力存在，但契约、版本、单位或语义不兼容。

合法零值、空对象集合和 `NOT_AVAILABLE` 必须分开。`PARTIAL` 也不能被消费者当作完整全球覆盖。

### 9.4 能力请求

消费者在运行前提交声明式请求：

```text
CapabilityRequest
├─ consumerTypeAndContractVersion
├─ requiredCapabilities
├─ optionalCapabilities
├─ regionAndCoverageRequirement
├─ physicalScaleAndResolutionRequirement
├─ maximumAcceptedError
├─ allowedKnowledgeStates
├─ allowedFallbackClasses
├─ determinismRequirement
└─ performancePreference
```

`performancePreference` 只能在满足科学契约的候选之间选择，不能用更快为理由静默放宽误差、尺度或状态要求。消费者必须明确哪些能力缺失会阻断运行，哪些只关闭可选功能。

### 9.5 协商响应

M7 返回：

```text
CapabilityNegotiationResult
├─ aggregateReleaseId
├─ acceptedContractVersion
├─ grantedCapabilities
├─ boundedOrPartialCapabilities
├─ unavailableOrIncompatibleCapabilities
├─ selectedFallbacks
├─ effectiveCoverageScaleAndError
├─ sourceLayerAndAssetRefs
├─ limitationsAndWarnings
└─ negotiationDecision
```

决策至少包括：

```text
ACCEPTED
ACCEPTED_WITH_DECLARED_FALLBACK
PARTIALLY_ACCEPTED
REJECTED
```

协商结果绑定总发布和消费者契约版本。它不创建新自然数据，也不能改变总发布能力状态。

### 9.6 合法降级规则

fallback 必须预先登记并由消费者请求允许。合法示例：

- 请求细尺度坡度但该区域只有较粗尺度正式坡度，消费者明确允许使用粗尺度并接收实际尺度；
- 局部三维缺失时，全球探索视图退回单值表面并关闭洞穴入口功能；
- 高精度容器体积暂不可用时，诊断工具接受带上下界曲线；
- 材料细类缺失时，某个气候模型只读取已验证的连续热力属性摘要。

非法示例：

- 用显示网格或法线贴图替代权威高程与坡度；
- 用默认材料填充未知区域；
- 用单流向路径替代 M6 多路连接；
- 用零值替代缺失水力物性；
- 用低 LOD 插值声称获得更细物理尺度；
- 用旧版消费者私自解释新版字段。

fallback 结果必须携带原请求、实际能力、差异和来源。

### 9.7 版本兼容与适配器

消费者契约和能力描述使用语义版本。兼容规则至少区分：

- 表示变化但语义等价；
- 新增可选字段；
- 单位或基准变化；
- 状态集合变化；
- 对象身份或拓扑语义变化；
- 删除或重命名能力。

只读适配器可以执行无损表示转换、字段重命名和显式单位转换，但必须：

- 版本化并进入依赖闭包；
- 保留来源、误差和状态；
- 不猜测缺失值；
- 不改变对象身份和拓扑；
- 不将不兼容语义伪装为兼容。

单位、基准、状态或拓扑含义无法无损转换时，协商返回 `INCOMPATIBLE`。

### 9.8 查询结果统一包络

所有消费者查询使用统一外层语义：

```text
TerrainMaterialQueryResult<T>
├─ aggregateReleaseId
├─ consumerContractVersion
├─ capabilityId
├─ requestedRegionScaleAndLOD
├─ actualRegionScaleAndLOD
├─ valueOrObjectRefs<T>
├─ unitsDatumAndCoordinates
├─ capabilityAndKnowledgeState
├─ errorConfidenceAndAlternatives
├─ sourceLayerAssetAndEvidenceRefs
├─ fallbackRecord
└─ limitations
```

不同领域可拥有专用内部类型，但不能删除快照、尺度、单位、状态、误差和来源信息。

### 9.9 跨字段和批量查询一致性

一个消费者任务通常同时读取高程、材料、坡度和容器。M7 必须保证：

- 全部查询绑定同一个 `aggregateReleaseId`；
- 相关字段使用兼容区域、尺度、基准和对象修订；
- 批量结果要么整体满足契约，要么明确列出局部失败；
- 不能在重试时自动切换到新发布；
- 相关不确定性情景保持联合一致；
- 派生视图不得把不同尺度字段对齐后冒充同尺度事实。

### 9.10 覆盖和流式加载

连续缩放桌面应用可按需加载，但能力协商必须先区分“发布中不存在”和“存在但尚未加载”：

```text
PRESENT_AND_LOADED
PRESENT_NOT_LOADED
NOT_IN_RELEASE
LOAD_FAILED
```

- 未加载资产可以在固定总发布内异步获取；
- `NOT_IN_RELEASE` 不能通过网络或缓存偶然找到的孤立文件补齐；
- 加载失败不改变能力事实，但当前查询返回运行失败；
- 预取、缓存和流式顺序不改变查询值；
- 界面可显示加载进度，但不能把占位地形当正式结果。

### 9.11 诊断权限与产品路径隔离

诊断视图可访问暂定对象、失败断言和多候选内部证据，但：

- 标准消费者无权通过诊断视图绕过发布门槛；
- 导出工具必须标明实验或诊断资产；
- 桌面应用默认显示正式结果，并清楚标示缺失和不确定；
- 调试开关不能改变权威数据，只改变可见信息；
- 验收工具对 Oracle 的访问与正式生成路径物理隔离。

### 9.12 消费者不得回写

## 十二、M7-D04：跨层来源图、解释、要求追踪与证据体系

### 12.1 四类信息必须分开

M7 区分：

```text
PROVENANCE      # 数据或对象实际由哪些输入、模型和上游资产生成
EXPLANATION     # 面向人或工具的可读因果说明
REQUIREMENT     # 系统必须满足的规则、边界和能力
EVIDENCE        # 某个要求或结论通过何种观测、测试和断言得到支持
```

来源记录是可审计事实；解释是基于来源记录生成的视图；要求是版本化规范；证据是对要求的支持或反证。解释文本不能成为新的生成输入，测试通过也不能改写自然字段。

### 12.2 跨层证据图节点

建议跨层图至少包含：

```text

RandomStreamNode
FieldOrObjectNode
ContributionAndBudgetNode
TransformationNode
CapabilityNode
RequirementNode
AssertionNode
FixtureAndOracleNode
ObservationNode
FailureNode
ReleaseDecisionNode
ExplanationNode
```

节点使用不可变身份和内容摘要。大体量字段可以由区域、尺度和对象摘要节点代表，但必须能追溯到具体权威资产和查询范围。

### 12.3 关系类型

建议关系至少包括：

```text
GENERATED_FROM
TRANSFORMED_BY
CONSTRAINED_BY
AUTHORIZED_BY
CONTRIBUTES_TO
DERIVED_FROM
AGGREGATES
REFINES
DEPENDS_ON

TESTED_BY
OBSERVED_BY

CONTRADICTS
FAILS
EXPLAINS
SUPERSEDES
REVOKES
```

因果来源子图必须遵守运行时单向依赖；验收、解释和历史关系可以指回被检验对象，但不能被误读为生成依赖。每条边声明关系语义、作用域、尺度、版本和证据强度。

### 12.4 因果来源与相关性分离

来源图只记录实际参与生成或约束的因素。例如：

- M4 山岭发生器实际引用的 L5 构造资格可以是 `GENERATED_FROM` 或 `CONSTRAINED_BY`；
- 附近存在某种岩性但未进入计算，只能是空间相关证据，不能写成生成原因；
- M5 识别出的山脊引用完整表面和分析尺度，不把 M4 控制线冒充几何原因；
- M6 容器引用 M5 盆地与重力基准，不把下游湖泊状态写成来源；
- 地貌语义未来可引用多类证据，但不会改变原始来源链。

无法确定唯一归因时保留多个候选及贡献范围，不编写确定性故事。

### 12.5 要求标识与追踪

每条规范要求使用稳定标识并至少记录：

```text
requirementId
ownerLayerOrCrossLayerScope
normativeStatement
rationale
applicableReleaseProfiles
verificationMethods
blockingSeverity
versionAndSupersession
```

要求可追踪到：

- 设计决定和模型边界；
- 实现组件或算法能力；
- 一个或多个验收断言；
- 固定夹具、属性测试或变形测试；
- 观测结果和通过／失败结论；
- 受影响发布档案和消费者。

没有验证方法或证据的必需要求状态为 `UNVERIFIED`，不能因文档中已经描述而视为通过。

### 12.6 证据类型与证明范围

| 证据类型 | 适合证明 | 不能单独证明 |
| --- | --- | --- |
| 结构不变量 | 引用、单位、有限值、图无环、预算和摘要闭合 | 自然形态是否合理 |
| 解析基准 | 已知曲面、容量、导数和简单拓扑的数值正确性 | 复杂世界统计分布 |
| 变形关系 | 旋转、重映射、细化和参数变化下的关系正确性 | 绝对现实标定 |
| 属性测试 | 大量合法输入始终满足通用规则 | 特定世界是否逼真 |
| 统计校准 | 多种子总体分布落在版本化包络 | 单个局部对象因果正确 |
| 固定测试世界 | 端到端组合行为和已知困难场景 | 所有可能世界 |
| 消费者契约 | 下游读取边界、状态和兼容性正确 | 上游物理模型本身正确 |
| 视觉检查 | 接缝、条纹、碎片、平顶等明显伪影 | 数值守恒、因果和物理真实性 |

正式结论按要求组合多类证据。视觉相似不能单独使科学要求通过，解析测试通过也不能替代统计和组合测试。

### 12.7 Test Oracle 隔离

`TestInput`、正式生成逻辑和 `TestOracle` 必须物理隔离：

- Oracle 不能向发生器提供目标值、形状、阈值或期望对象数；
- 正式代码不能读取测试世界预期答案；
- 调参数据集、开发测试集和发布验收集分别版本化；
- 固定夹具的预期关系可以公开，但用于盲测的具体样本不进入生成路径；
- Oracle 版本、适用模型和容差进入证据图；
- Oracle 自身通过故障注入和交叉实现进行自检。

发现 Oracle 泄漏时，相关验收证据失效，不能只重跑同一测试恢复可信度。

### 12.8 证据独立性和复用

同一底层观测可能支持多个要求，但不能被计作多个独立证据来夸大可信度。M7 记录：

```text
evidenceFamilyId
sharedDataAndImplementationRefs
independenceClass
calibrationUsage
validationUsage
knownCorrelations
```

- 同一算法生成结果并验证自身，属于低独立性证据；
- 独立解析实现或不同方法的交叉核验具有更高独立性；
- 用于调参的数据不能同时作为未声明的发布盲测；
- 多个平台运行同一实现可证明平台一致性，不等于独立物理验证；
- 证据复用必须保留共同来源和相关性。

### 12.9 解释查询类型

M7 至少支持以下解释入口：

```text
WHY_VALUE_OR_OBJECT_EXISTS
WHY_CLASSIFICATION_IS_UNCERTAIN
WHY_CAPABILITY_IS_UNAVAILABLE
WHY_RESULT_CHANGED
WHY_RELEASE_FAILED
WHAT_WOULD_BE_INVALIDATED
```

典型回答结构为：

```text
结论或状态
→ 直接权威来源
→ 关键上游贡献与约束
→ 尺度、误差和适用范围
→ 支持与反证证据
→ 未知和限制
→ 固定快照及复现入口
```

解释必须绑定位置、区域、对象、尺度和总发布。不能用全球概述回答局部对象，也不能把粗尺度原因无条件推广到细尺度形态。

### 12.10 “为什么变化”解释

比较两个总发布时，M7 先比较依赖和对象谱系，再生成变化解释：

- 哪个直接或传递依赖发生变化；
- 哪些层资产重新生成；
- 对象是保持、变形、分裂、合并、重分类还是退役；
- 数值变化是否超出误差与跨平台容差；
- 能力变化来自覆盖、模型、契约还是验收状态；
- 哪些下游结果需要失效。

缓存重建、文件移动或显示样式变化不应被解释为自然世界变化。

### 12.11 失败证据与反证

证据图不仅保存通过证据，还保存：

- 失败断言和最小反例；
- 与结论冲突的观测；
- 无法归因的异常；
- 已知模型适用范围外案例；
- 被撤销或被新证据推翻的结论；
- 验证器自身失败和 Oracle 问题。

阻断反证不能被隐藏或用更多无关通过项稀释。若一个要求存在未解决的高严重度矛盾证据，其状态不得为 `PASS`。

### 12.12 证据时效与撤销

证据绑定精确输入、模型、参数、数值策略和契约版本：

- 依赖变化后，旧证据可以保留历史价值，但不能自动验证新发布；
- 若变化被已证明的兼容性规则覆盖，可显式继承证据并记录依据；
- Oracle、容差或要求变化使相关结论重新进入待验证；
- 发现验证器缺陷时可撤销一组证据并沿依赖图传播；
- 历史证据不删除，使用 `SUPERSEDED` 或 `REVOKED` 表达状态。

### 12.13 运行日志与证据资产

运行日志用于诊断，不自动成为可信证据。正式证据资产必须结构化、版本化并具备：

```text
evidenceId
evidenceType
scopeAndClaim
sourceInputsAndTools
methodAndVersion
observedResult
uncertainty
independenceAndCorrelation
artifactDigests
status
```

日志文本、截图或人工备注可以作为辅助附件，但不能替代机器可核验的断言结果和来源闭包。任何外部或人工证据也必须明确来源和适用范围。

### 12.14 最小复现索引

每个失败和关键发布结论链接到可独立运行的复现包，至少包括：

- 精确总发布与相关层引用；
- 最小空间、尺度和对象裁剪；
- 模型、参数、随机流和数值策略；
- 要求、断言、夹具和 Oracle 版本；
- 预期关系与观测摘要；
- 必需能力和执行入口；
- 不依赖原工作目录、缓存或界面的数据。

复现包索引由 M7 拥有，包内自然数据仍引用或裁剪自权威层资产。

### 12.15 建议输出

```text
CrossLayerEvidenceAndExplanationView
├─ provenanceGraph
├─ requirementTraceabilityGraph
├─ assertionAndEvidenceGraph
├─ evidenceIndependenceMap
├─ contradictionsAndFailures
├─ explanationQueryIndex

├─ evidenceValidityAndRevocation
└─ minimalReproductionIndex
```

### 12.16 不允许的快捷方式

M7-D04 不允许：

- 将可读解释文本作为自然状态或下一次生成输入；
- 把空间相关性写成未经证实的生成因果；
- 只记录通过证据而丢弃冲突、失败和未知；
- 让视觉检查单独证明物理、守恒或拓扑正确；
- 使用同一调参样本冒充独立发布验收；
- 让正式生成逻辑读取 Oracle 或预期答案；
- 把同源测试重复计作多个独立证据；
- 在依赖或要求变化后自动沿用旧证据；
- 用非结构化日志替代要求、断言和观测关系；
- 生成不绑定快照、位置、尺度和误差的解释。

```text
SCIENTIFIC_MODEL_CHANGE
PARAMETER_OR_CALIBRATION_CHANGE
AUTHORITATIVE_INPUT_CHANGE
NUMERICAL_STRATEGY_CHANGE
CONTRACT_OR_SCHEMA_CHANGE
ACCEPTANCE_POLICY_CHANGE
PRESENTATION_ONLY_CHANGE
CACHE_OR_STORAGE_ONLY_CHANGE
```

变化类别由内容和语义决定，不按文件名或提交说明猜测。同一个修改可以同时影响多个类别。

### 15.2 世界变化与非世界变化

通常会产生新自然或发布结果的变化包括：

- 世界规格、种子、因果偏好和命名随机流改变；
- 材料、高程、起伏、拓扑或容器模型及参数改变；
- 数值策略的差异超出已证明的等价范围；
- 垂直基准、重力势、尺度定义和对象身份规范改变；
- 上游权威输入或正式补丁改变。

通常不改变自然世界的变化包括：

- 文件移动、压缩方式和缓存位置改变；
- 可证明等价的序列化重排；
- 显示配色、相机、标签和高程夸张改变；
- 查询索引重建；
- 日志格式和非规范诊断文本改变。

非世界变化仍可能产生新的软件构建或字节摘要，但不应产生新的自然对象身份。是否等价必须有版本化规则和证据，不能靠人工直觉临时判定。

### 15.3 四类失效对象

M7 分开计算：

```text
AUTHORITATIVE_INVALIDATION   # 哪些 M1—M6 权威资产需重新生成
AGGREGATE_INVALIDATION       # 哪些 M7 总清单、能力和契约需重建
EVIDENCE_INVALIDATION        # 哪些验收、解释和证据不再适用
DOWNSTREAM_INVALIDATION      # 哪些气候、水体、水文、语义或导出结果过期
```

缓存失效单独处理，不得与权威失效混为一谈。清除缓存不使世界过期；权威资产变化也不能只通过清缓存来假装完成更新。

### 15.4 依赖图驱动传播

失效从变化节点沿 D02 和 D04 的真实依赖边传播：

```text
changed source
  → directly derived layer assets
  → dependent objects, curves and indexes
  → M7 aggregate manifests and capabilities
  → affected evidence and consumer results
```

传播必须保留空间、物理尺度、对象、能力和消费者范围。没有依赖边的资产默认不失效；但“没有记录依赖”不能被当作独立证明，缺失来源边本身会阻断最小失效优化。

### 15.5 最小但保守的失效范围

失效范围遵循：

- 能证明无影响时保留资产；
- 无法证明局部性时扩大到最近的可验证依赖边界；
- 不因节省计算而缩小未知影响；
- 不因实现方便而默认全世界重算；
- 范围可以是区域、尺度带、对象子图、曲线区间、能力或整层；
- 最终范围附带传播路径和保守性理由。

“最小”意味着不让无关资产过期；“保守”意味着所有可能受影响的权威结果都包含在内。两者都需证据支持。

### 15.6 典型传播示例

| 变化 | 至少失效 | 可以保留的典型内容 |
| --- | --- | --- |
| M1 球面或垂直基准改变 | 相关 M2—M7 及下游全部几何结果 | 与该世界无关的测试工具缓存 |
| M2 某局部材料物性修订 | 相关材料视图、读取该物性的 M3/M4 派生、后续 M5/M6 与下游区域 | 无依赖的远区和纯几何资产，前提是有证据 |
| M4 局部表面补丁改变 | 受影响 M5 对象、M6 曲线／门槛／路径、M7 能力与下游结果 | 未依赖该补丁的其他区域 |
| M5 显著性阈值改变 | 相关关键对象、谱系、M6 来源接口及下游语义证据 | M4 权威固体表面与发生器账本 |
| M6 积分容差收紧 | 相关曲线、容量证据、消费者能力和水体结果 | M5 几何及无关路径拓扑 |
| 验收容差或 Oracle 改变 | 相关证据、通过结论和 M7 发布状态 | 自然资产本身，除非新结论要求重生成 |
| 显示配色改变 | 展示缓存 | M1—M7 科学资产与下游自然状态 |

实际范围以记录的依赖为准，表格不能替代运行时追踪。

### 15.7 拓扑变化扩大失效

局部数值变化可能触发非局部拓扑影响。例如：

- M4 局部高程变化改变 M5 控制鞍部；
- 鞍部顺序变化改变 M6 父容器及全局连通索引；
- 新局部三维通道连接两个原本独立的容器；
- 对象分裂或合并改变跨尺度谱系；
- 能力覆盖变化影响某个消费者的整个批量任务。

因此先计算局部数值影响，再检查关键拓扑和身份不变量。若不变量变化，沿相关对象图向外传播；不能仅按地理包围盒裁剪失效范围。

### 15.8 缓存键与防污染

缓存键至少包含：

```text
aggregateReleaseId
sourceLayerAndAssetIds
consumerContractVersion
capabilityId
regionScaleLODAndLevel
uncertaintyScenarioId
algorithmAndAdapterVersion
canonicalQueryParameters
```

缓存不得只按种子、坐标和 LOD 命名。读取缓存时校验规范摘要和依赖；不匹配即视为未命中，而不是尝试局部修补。失败、暂定和欠定结果也可以缓存，但状态必须进入键和值，不能与正式结果混淆。

### 15.9 权威资产与缓存生命周期

- 权威层发布和 M7 清单不可变，按发布生命周期保存；
- 缓存可随时删除和重建；
- 展示资源可以独立刷新；
- 最小复现包和阻断证据按审计策略保留；
- 被替代发布仍可用于历史复现；
- 被撤销发布不供新任务选择，但相关证据不能删除；
- 垃圾回收只能删除没有任何发布、证据或复现引用的可回收资产。

### 15.10 兼容性的多个维度

兼容性至少分为：

```text
STORAGE_COMPATIBLE       # 可读取或可无损迁移序列化数据
CONTRACT_COMPATIBLE      # 消费者接口字段和状态兼容
SEMANTIC_COMPATIBLE      # 物理含义、单位、尺度和对象语义兼容
NUMERICALLY_EQUIVALENT   # 在声明容差内结果等价
EVIDENCE_COMPATIBLE      # 旧证据仍适用于新资产或规则
```

存储可读不等于科学语义兼容；数值接近也不保证对象身份和拓扑兼容。每个兼容性结论引用规则、适用范围、容差和证据。

### 15.11 迁移与适配

迁移分为：

1. **无损存储迁移**：改变编码或分块，规范语义不变；
2. **无损契约适配**：字段重命名、明确单位转换或新增可选字段；
3. **语义迁移**：尺度、状态、对象或物理定义改变，需要新层发布和重新验收。

前两类生成新字节资产和迁移证据，可在兼容规则允许时保持自然身份。第三类不能通过适配器隐藏，必须产生新发布、谱系和失效传播。

迁移工具版本和输入输出摘要进入依赖图，禁止原地覆盖旧资产。

### 15.12 下游失效通知

M7 为下游生成结构化失效报告：

```text
InvalidationReport
├─ oldAndNewAggregateReleaseIds
├─ changedInputsAndRules
├─ affectedCapabilities
├─ affectedRegionsScalesAndObjects
├─ topologyAndIdentityChanges
├─ evidenceAndAcceptanceChanges
├─ downstreamSnapshotRefs
├─ reusableAssets
└─ requiredActions
```

报告只说明哪些结果可复用、需重算或不再兼容，不主动修改下游快照。下游必须显式选择新总发布并生成新结果。

### 15.13 比较与回归基线

新旧发布比较至少区分：

- 预期模型变化；
- 数值容差内变化；
- 对象身份和拓扑变化；
- 能力与覆盖变化；
- 未预期回归；
- 仅存储或展示变化。

回归基线绑定模型和档案版本。升级模型后不能要求所有像素与旧版一致，但必须保持仍适用的不变量、变形关系和兼容性承诺。

### 15.14 不允许的快捷方式

M7-D05 不允许：

- 按文件修改时间或目录判断世界是否变化；
- 所有变化一律全世界重算，或所有局部修改一律只局部失效；
- 缺少依赖记录时假定不受影响；
- 门槛、连通或身份变化后保留旧下游结果；
- 只按种子、坐标和 LOD 构造缓存键；
- 用缓存命中覆盖摘要或依赖不一致；
- 将存储兼容误报为语义或证据兼容；
- 通过适配器隐藏尺度、状态或拓扑语义变化；
- 原地迁移或覆盖旧权威资产；
- 垃圾回收仍被发布、证据或复现包引用的资产。

## 十七、M7-D05 确认结论

M7-D05 已确认：对所有变化先分类，再分别计算权威资产、M7 清单、证据和下游结果的失效范围；缓存与展示变化不冒充自然世界变化。失效沿真实依赖图传播，既要求最小化，也在影响未知时保守扩大；门槛、连通和身份变化可产生非局部影响。缓存键包含完整发布、契约、尺度和情景，权威与缓存生命周期分离。存储、契约、语义、数值和证据兼容分别判定；语义迁移必须产生新发布，下游通过结构化报告显式更新。

## 十八、M7-D06：固定测试世界、跨层不变量与跨平台验收

### 18.1 三层验收结构

M7 总验收由三类互补测试组成：

1. **层内固定夹具**：复用 M1—M6 各自的解析、关系和故障夹具，用于定位具体层错误。
2. **端到端固定世界**：使用完整正式路径生成可复现世界，验证跨层组合、不变量、解释和消费者契约。
3. **预注册统计世界组**：使用冻结种子集和参数分层验证总体分布、极端情况及伪模式，不用单个世界代替总体校准。

层内全部通过不能替代端到端世界；端到端世界视觉合理也不能掩盖层内守恒或契约失败；统计通过不能证明某个固定因果场景正确。

### 18.2 端到端固定世界

建议建立以下 M7 专用地形与材料固定世界：

| 编号 | 固定世界 | 主要跨层验收内容 |
| --- | --- | --- |
| TM01 | 大陆碰撞山系 | 汇聚资格、材料响应、长波抬升、多尺度山系、峰脊谷与容器边界 |
| TM02 | 俯冲边缘与邻接海盆 | 极性、非对称地形、材料分带、固体低地、崖坡和海洋求解输入守界 |
| TM03 | 大陆裂谷与封闭低盆 | 成对轴肩、负高程、断块、闭合盆地、低地非海洋和多门槛 |
| TM04 | 扩张轴与转换段 | 轴向形态、转换连接、跨尺度频谱、材料过渡和潜在路径连续 |
| TM05 | 走滑阶区与三重点 | 低垂向纯走滑、混合响应、分支关系、冲突状态和无星形伪峰 |
| TM06 | 稳定核心与材料过渡 | 低幅起伏、连续物性、无标签台阶、无噪声海和长期背景形态 |

| TM08 | 多级嵌套盆地 | 关键区域、盆地谱系、排他／包含容量、门槛层级和无重复计量 |
| TM09 | 岩溶资格与局部三维锚点 | 材料资格、表面—地下边界、洞口／空腔能力降级和禁止臆造暗河 |
| TM10 | 跨立方球面长结构 | 球面方向、面缝、对象身份、容器曲线、路径和旋转等价性 |
| TM11 | 全球骨架与局部连续细化 | P0—P4 尺度、补丁核心／halo、聚合守恒、最小失效和连续缩放 |
| TM12 | 缺失、冲突与降级世界 | 未知状态、能力协商、fallback、反证、失败定位和发布阻断 |

每个世界拥有固定世界规格、种子、构造输入、材料档案、发布档案和版本化预期关系。预期以不变量、区间、排序、拓扑和变形关系为主，不要求像素级参考图。

### 18.3 与已有专题测试世界的关系

已有 T01—T06 测试世界主要面向湿润山地、内陆盆地、冲积平原、三角洲、岩溶和差异侵蚀等水文／地貌组合场景。当前 M7：

- 可以复用其固体地形和材料前置部分作为辅助场景；
- 不把尚未实现的气候、水文、侵蚀结果列为 M7 必须输出；
- 不因下游河流、湿地或三角洲未生成而判 M7 失败；
- 为这些下游测试提供稳定的地形材料输入契约；
- 后续完整自然系统验收再把 M7 发布与气候、水体、水文结果组合。

这样避免当前子引擎为通过未来测试而提前生成过程地貌。

### 18.4 跨层不变量

端到端测试至少检查：

1. **身份与依赖**：M1—M7 世界身份、版本、摘要和引用闭合。
2. **单位与基准**：球面坐标、垂直基准、重力势、距离、面积和体积一致。
3. **材料—几何一致**：材料柱、放置、最终表面出露和多交点状态匹配。
4. **尺度与预算**：M3/M4 预算闭合，真实波长与 LOD 分离，局部细化聚合守恒。
5. **表面—拓扑一致**：M5 对象可由 M4 表面重建，且不修改表面。
6. **拓扑—容器一致**：M6 曲线、门槛和路径引用正确 M5 对象并保持容量守恒。
7. **语义边界**：低地、谷线、容器和门槛不自动变成海洋、河流、湖泊或出口。
8. **不确定性闭合**：相关误差和拓扑候选跨层一致，不丢失未知状态。
9. **能力与消费者**：协商结果与实际覆盖、尺度、状态和证据一致。
10. **解释与复现**：关键结果和失败可追溯并可从最小包重现。

### 18.5 变形关系套件

对同一个固定世界实施不改变自然语义的变换：

- 任意球面旋转；
- 等价立方球面面编号和朝向重映射；
- 合法存储分块与对象排序变化；
- 补丁切分、加载顺序与重叠范围变化；
- 并行度、任务顺序和缓存冷热变化；
- 在同一物理尺度提高 LOD；
- 无损序列化与契约适配；
- 显示投影、配色和高程夸张变化。

结果必须满足对应等价关系，而不是要求所有底层字节完全相同。旋转后的空间对象应通过反变换一一对应，显示变化不得影响科学摘要。

### 18.6 确定性等级

不同结果使用不同确定性要求：

```text
EXACT_SEMANTIC
EXACT_DISCRETE
TOLERANT_NUMERIC
STATISTICAL_ENVELOPE
PRESENTATION_ONLY
```

- 发布状态、能力状态、对象身份、拓扑关系、失败代码和依赖图应满足 `EXACT_DISCRETE`；
- 字段、面积、体积和误差区间可在声明数值策略下满足 `TOLERANT_NUMERIC`；
- 多种子分布使用 `STATISTICAL_ENVELOPE`；
- 预览图像属于 `PRESENTATION_ONLY`，不参与科学相等；
- 物理含义、单位、尺度和状态集合必须满足 `EXACT_SEMANTIC`。

若数值差异跨越分类门槛并改变对象、拓扑或验收结论，则不再是允许浮点差异。

### 18.7 Windows 与 macOS 跨平台验收

Windows 与 macOS 使用相同：

- 世界规格、种子和命名随机流；
- 模型、参数、尺度、阈值和验收档案；
- 规范化与对象排序规则；
- 固定世界、断言和 Oracle 版本。

跨平台要求：

- 离散状态、对象身份、图关系、能力和发布结论一致；
- 数值字段、曲线和统计在预注册容差内；
- 规范摘要在量化规则下保持一致；
- 字节摘要可因合法容器格式不同而不同；
- 平台差异必须记录在构建资产而非自然身份中；
- 不允许针对平台使用不同科学阈值来强行通过。

### 18.8 统计世界组

统计验收使用预注册分层种子集：

- 覆盖构造格局、材料背景、尺度预算和不确定性状态；
- 分开校准集、开发集和发布盲测集；
- 验证高程、坡度、曲率、频谱、方向、对象密度、盆地容量和连通复杂度；
- 检测条纹、网格印迹、重复模板、面周期、补丁方块和平顶裁剪；
- 对极端尾部设置单独审查，不只检查均值；
- 种子集和统计指标变更触发证据重新验收。

统计包络应来自科学参考、解析限制和版本化设计目标，不按本次实现输出自我拟合。

### 18.9 单因素与消融测试

固定世界附带单因素变体，用于验证因果隔离：

- 只改变构造汇聚强度；
- 只改变某一连续材料物性；
- 只启用或关闭某尺度带；
- 只改变重力／垂直近似；
- 只增加局部细化补丁；
- 只改变 M7 发布档案或消费者请求。

预期只有真实依赖路径上的结果变化。消融某类证据后，能力或置信应相应降级，而不是由无关默认值保持原结论。

### 18.10 故障注入与验证器自检

跨层故障注入至少包括：

- 混合不同世界或不同版本的层快照；
- 单位、垂直基准或重力势错配；
- M3/M4 预算重复、低频泄漏和材料反馈循环；
- M5 跨断点求导、随机拆平和对象身份依赖格元；
- M6 容量非单调、门槛循环、填洼路径和低盆自动入海；
- 缺失能力被默认值或显示数据补齐；
- 证据图丢失反证或 Oracle 泄漏；
- 缓存键缺失版本导致旧结果污染；
- 跨平台数值差异改变拓扑或发布状态；
- 原子提交中断和摘要错配。

验证器必须能稳定拒绝这些错误。故障夹具与正常固定世界隔离，避免测试只会确认正确样本。

### 18.11 验收矩阵与阻断等级

每个发布档案维护：

```text
Requirement × EvidenceType × FixtureOrWorld × Platform × Capability
```

断言严重度至少为：

```text
BLOCKING
REQUIRED_NON_BLOCKING
ADVISORY
EXPERIMENTAL
```

- `BLOCKING` 失败直接阻断档案发布；
- `REQUIRED_NON_BLOCKING` 必须修复或获得版本化例外，不能静默忽略；
- `ADVISORY` 记录趋势和风险，不改变当前结论；
- `EXPERIMENTAL` 只评价具名实验能力；
- 严重度不能在测试完成后为通过而临时降低。

### 18.12 不稳定测试处理

同一输入和环境结果不稳定时：

- 标记 `FLAKY_OR_NONDETERMINISTIC`；
- 保存所有相互矛盾的运行证据；
- 不通过无限重试选取一次成功结果；
- 定位随机流、并发、未初始化状态、数值策略或外部依赖；
- 阻断受影响的确定性要求和发布档案；
- 修复后使用原失败输入及独立回归样本重新验收。

### 18.13 性能和资源证据

桌面应用需要性能验收，但性能不能替代科学正确性：

- 记录全球生成、局部细化、查询、内存、存储和启动预算；
- Windows/macOS 分别测量并保存硬件与构建信息；
- 性能回退只能选择 D03 已授权且语义明确的 fallback；
- 不通过降低未声明精度、跳过证据或使用展示网格达到性能目标；
- 性能失败可以阻断具名产品档案，但不改变科学字段的正确性结论。

### 18.14 建议输出

```text
CrossLayerAcceptanceMatrix
├─ layerFixtureResults
├─ fixedWorldResults
├─ statisticalWorldSetResults
├─ crossLayerInvariantResults
├─ metamorphicRelationResults
├─ crossPlatformComparison
├─ faultInjectionAndValidatorSelfTests
├─ requirementCoverageMatrix
├─ performanceAndResourceEvidence
└─ blockingDecisionInputs
```

### 18.15 不允许的快捷方式

M7-D06 不允许：

- 用单个好看的世界代替层内、端到端和统计验收；
- 要求逐像素图像相同作为唯一正确标准；
- 用层内全部通过代替跨层不变量测试；
- 让尚未实现的水文地貌成为 M7 地形材料发布前提；
- 使用调参种子作为未声明的发布盲测；
- 只检查均值而忽略极端尾部和伪模式；
- 把允许浮点误差扩展到对象、拓扑和发布状态差异；
- 为不同平台设置不同科学阈值；
- 通过重复运行挑选一次成功来掩盖不稳定测试；
- 以性能为由跳过科学验收或使用未授权近似。

M7-D06 已确认：以层内固定夹具、TM01—TM12 端到端固定世界和预注册统计世界组共同验收。端到端检查身份、单位、材料—几何、尺度预算、表面—拓扑、拓扑—容器、语义边界、不确定性和消费者契约；已有水文专题世界只复用其前置地形，不要求 M7 提前生成河流等状态。球面旋转、面重映射、补丁、并发和 LOD 作为变形关系；Windows/macOS 的离散结论必须一致，数值差异受统一容差约束。不稳定测试不以重试择优，性能验收不得牺牲科学契约。

## 二十一、M7-D07：总发布门槛、失败复现与生命周期

### 21.1 总发布候选流程

```text
DRAFT
  → STAGING
  → VALIDATING_DEPENDENCIES
  → VALIDATING_CAPABILITIES
  → VALIDATING_ACCEPTANCE
  → READY_TO_COMMIT
  → RELEASED
```

任一验证阶段都可进入 `REJECTED`。只有 `READY_TO_COMMIT` 可以执行 D02 的原子根提交。验证阶段读取的是冻结层引用和发布档案；验证过程中产生新层发布时，不自动替换候选依赖。

### 21.2 总发布状态

建议区分：

```text
PASS
CONDITIONAL_PASS
FAIL
UNVERIFIED
```

以及生命周期：

```text
DRAFT → VALIDATING → RELEASED
                    ↘ REJECTED
RELEASED → SUPERSEDED
RELEASED → REVOKED
```

验收状态与生命周期分别表达。例如一个候选可以是 `PASS + READY_TO_COMMIT`，完成原子提交后成为 `PASS + RELEASED`。`REVOKED` 不删除历史资产，只阻止新的标准消费。

### 21.3 标准发布必须满足

一个发布档案的标准总发布至少要求：

- 所有必需 M1—M6 层为兼容的 `PASS + RELEASED`；
- D02 世界身份、依赖闭包、覆盖、摘要和原子资产完整；
- D03 必需能力和消费者契约全部满足；
- D04 必需要求有有效、未撤销且范围匹配的证据；
- D05 没有未处理的权威、证据或下游兼容冲突；
- D06 层内夹具、固定世界、统计组、跨平台和验证器自检满足档案门槛；
- 所有 `BLOCKING` 断言通过；
- 已知高严重度反证已解决；
- 最小复现和失败定位入口可用；
- 总发布清单、能力矩阵、证据包和决定摘要一致。

“已生成文件”或“视觉可浏览”不构成标准发布资格。

### 21.4 绝对阻断条件

以下任一情况阻断标准发布：

- 混合世界身份、依赖不闭合、摘要错配或引用循环；
- 必需层失败、未验证、被撤销或仅条件通过；
- 非有限权威值、单位／基准错配或必需覆盖空洞；
- M3/M4 预算不闭合、来源重复或未授权尺度功率；
- M5 修改表面、跨断点错误求导或拓扑／身份冲突；
- M6 容量负值／回退、重复计量、门槛循环或水状态越权；
- 缺失能力被默认值、显示数据、旧版本或未授权 fallback 补齐；
- Oracle 泄漏、阻断反证被隐藏或证据与资产版本不匹配；
- Windows/macOS 离散结果、拓扑、能力或发布结论不一致；
- 验证器故障注入自检失败；
- 原子提交、崩溃恢复或历史复现无法保证。

其他测试通过、平均分、视觉质量和性能达标均不能抵消这些失败。

### 21.5 条件发布

`CONDITIONAL_PASS` 只允许用于具名实验档案，并必须声明：

```text
missingOrBoundedCapabilities
allowedConsumers
forbiddenConsumers
spatialScaleAndScenarioLimits
knownFailuresAndRisks
requiredFallbacks
expirationOrReviewCondition
```

- 标准气候、水体和水文消费者默认拒绝条件发布；
- 实验消费者必须在 D03 请求中明确允许；
- 条件发布不能被标记为标准世界；
- 条件状态不能通过隐藏失败或降低严重度获得；
- 条件发布升级为标准发布时创建新总发布并重新验收。

### 21.6 版本化例外

对于非科学阻断、已知工具限制或档案允许的非必需项，可以使用版本化例外：

```text
ExceptionRecord
├─ exceptionId
├─ affectedRequirementOrCapability
├─ justificationAndEvidence
├─ allowedReleaseProfiles
├─ scopeAndExpiration
├─ riskAndMitigation
└─ approvingPolicyVersion
```

例外不能覆盖：世界身份混合、权威数据损坏、单位基准错误、守恒失败、拓扑矛盾、Oracle 泄漏或任何档案的 `BLOCKING` 科学要求。例外到期或范围变化会使发布重新进入验证。

### 21.7 发布决定包

每次候选生成结构化决定包：

```text
AggregateReleaseDecisionBundle
├─ candidateAggregateReleaseId
├─ releaseProfileAndPolicy
├─ frozenLayerAndDependencyRefs
├─ capabilityDecisionSummary
├─ requirementCoverageSummary
├─ blockingAndNonBlockingFindings
├─ contradictionsAndExceptions
├─ crossPlatformAndPerformanceSummary
├─ reproductionAndAuditRefs
├─ finalDecision
└─ decisionDigest
```

决定必须能由所引用的结构化证据重新计算。人工说明可以附加，但不能替代机器可验证的阻断断言。

### 21.8 失败分类

建议稳定失败类别：

```text
IDENTITY_OR_DEPENDENCY_FAILURE
ASSET_OR_DIGEST_FAILURE
LAYER_RELEASE_FAILURE
CAPABILITY_OR_CONTRACT_FAILURE
PROVENANCE_OR_EVIDENCE_FAILURE
INVALIDATION_OR_COMPATIBILITY_FAILURE
CROSS_LAYER_INVARIANT_FAILURE
FIXED_WORLD_OR_STATISTICAL_FAILURE
CROSS_PLATFORM_OR_DETERMINISM_FAILURE
PERFORMANCE_PROFILE_FAILURE
VALIDATOR_OR_ORACLE_FAILURE
ATOMIC_RELEASE_FAILURE
```

一个失败可以有主类别和多个关联类别。根因未确定时使用明确未知状态，不根据最接近的错误消息猜测归因。

### 21.9 失败记录

每个失败至少记录：

```text
failureIdAndCode
severityAndBlockingState
requirementAndAssertionIds
aggregateAndLayerReleaseIds
regionScaleObjectAndCapabilityScope
expectedInvariantOrRelation
observedStructuredSummary
metricTopologyAndKnowledgeState
dependencyPathAndSuspectedRootSet
evidenceAndContradictionRefs
minimalReproductionPackageRef
```

失败位置不能只用屏幕截图或日志行表示。空间、尺度、对象和依赖路径应能被工具直接查询。

### 21.10 最小复现包

复现包必须自包含或通过内容摘要引用可获取的不可变资产，至少包括：

- 世界身份、总发布候选和发布档案；
- 最小必需层资产或裁剪；
- 模型、参数、随机流、数值策略和平台信息；
- 消费者契约、查询请求和 fallback 决定；
- 要求、断言、夹具、Oracle 和容差；
- 预期关系、实际结构化结果和错误状态；
- 运行入口与规范摘要。

复现不依赖原工作目录、用户名、绝对路径、临时缓存、线程时序或桌面界面。若失败依赖竞态，包应包含确定的调度或故障注入方式，而不是要求偶然复现。

### 21.11 发布、替代与撤销

- `RELEASED`：允许档案授权的标准消费者读取；
- `SUPERSEDED`：已有更合适的新发布，旧版仍可用于历史复现；
- `REVOKED`：发现严重缺陷，禁止新标准任务使用，保留历史与证据；
- 撤销沿 M7-D05 依赖图通知下游，但不删除其已有快照；
- 新发布不能原地替换旧清单根；
- 同一世界可以并存多个发布档案和模型版本；
- 桌面应用切换版本是显式用户／任务选择，不由后台静默完成。

### 21.12 回滚和恢复

回滚表示将“默认推荐发布指针”切回某个仍有效的旧发布，不改变任何发布内容：

- 回滚目标必须未撤销且与当前消费者契约兼容；
- 指针切换原子完成；
- 已固定旧或新发布的运行继续使用各自版本；
- 回滚原因、决定和影响进入审计图；
- 数据修复通过新发布完成，不能修改回滚目标；
- 崩溃恢复遵守 D02 的完整旧根／新根原则。

### 21.13 长期重现

为长期重现，M7 至少保存或可定位：

- 层发布和传递依赖摘要；
- 模型、参数、随机流和数值策略；
- 数据格式与无损迁移工具；
- 固定测试、Oracle、容差和发布策略；
- 平台与构建信息；
- 消费者契约和适配器；
- 关键证据、决定包和最小复现包。

若某个旧运行环境无法直接执行，应通过验证过的兼容运行时或迁移链复现，并明确这是重建结果而非原字节重放。

### 21.14 审计与可观察性

M7 提供结构化只读审计入口：

- 某总发布为什么通过、拒绝、替代或撤销；
- 哪些层、能力、要求和证据参与决定；
- 哪些例外有效及何时到期；
- 哪些消费者和下游快照引用该发布；
- 一次发布尝试在哪一阶段失败；
- 是否发生过缓存重建、迁移、回滚或验证器撤销。

操作日志辅助审计，但最终结论来自不可变清单、决定包和证据图。

### 21.15 不允许的快捷方式

M7-D07 不允许：

- 因世界可视化正常就跳过必需验收；
- 用平均通过率抵消阻断失败；
- 将条件发布标成标准发布供普通消费者读取；
- 在测试结果出来后降低严重度或新增例外以获得通过；
- 用例外覆盖身份混合、数据损坏、守恒、拓扑或 Oracle 问题；

复核确认：

1. **无权威复制**：M7 只组合不可变引用，不拥有第二份高程、材料、拓扑或容器。

6. **无失效遗漏**：变化分别传播到权威、总清单、证据和下游，拓扑变化允许扩大范围。
7. **无平台双标准**：Windows/macOS 使用同一科学参数、阈值、Oracle 和发布规则。
